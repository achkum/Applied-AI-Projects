Separate THIS_DEVICE_ONLY atomic secure item, process-private capability, serialized fresh resume/bootstrap and explicit uncertainty retirement fit the adopted model. Bootstrap stores one-time capability plus session before active. Resume after an unknown mutation is an explicit recovery action and cannot automatically replay the intent. All pending store writes must remain in the same serialized queue: logout invalidates live authority synchronously, then waits for prior writes to settle/clear before final secure deletion, so a late already-started write cannot resurrect a capability after logout. Generation checks before and after asynchronous persistence, combined with that queue, are required by the proposed serialization/logout-race contract. Local clear failure retains storage-error/no usable process authority while captured server revocation still runs; no false acknowledged logout.
