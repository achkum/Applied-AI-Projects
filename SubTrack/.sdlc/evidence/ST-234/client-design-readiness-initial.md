# ST-234 client/design PRECODE decision — conditional, no source GO
UF-01 steps 5–6, F1.4/F1.5 and DATA_MODEL support a private profile followed by an explicit mode choice. This is local privacy-safe Type 2a contract precision; record new bounds as **Assumed** in ASSUMPTIONS, not a product rewrite or founder gate absent a concrete new scope delta.
ProfileUpdateInput: optional displayName, avatarColourToken, avatarEmoji, language, theme; only avatar fields accept explicit null. ProfileView: displayName nullable while incomplete; both avatar fields nullable; language sv|en, theme system|light|dark, defaultCurrency literal SEK. Neither shape carries owner/contact/provider/verified-name/session/household authority. Reject unknown keys strictly.
Display name: accept an already NFC-normalized, trim-stable, nonblank string of 1–80 Unicode scalar values; reject controls and unpaired surrogates. Do not silently trim/normalize accepted input. OpenAPI maxLength alone and generated Zod `.max(80)` count differently; wrapper must enforce the scalar bound on both input and output, with parity tests including astral, combining and boundary cases, or revise the schema before GO.
Emoji: nullable or a single explicitly supported pictographic scalar, optionally followed by VS16; reject ZWJ sequences, isolated modifiers, controls, unpaired surrogates and other grapheme clusters. This bounded allowlist is implementable without a dependency and intentionally narrower than “one extended grapheme”; client/design must confirm that the offered picker contains only accepted values before GO.
Avatar colour enum is exactly `member.accent.01` through `.08` from ui-tokens. No name/contact hash; a server-owned opaque-ID selection may be proposed separately, otherwise null until selection. Locale defaults to sv for device `sv-*`, else en; explicit sv/en wins. Theme defaults system; currency remains SEK. These defaults are projections, not client assertions.
Trusted verified given/surname may supply an advisory prefill through a private server projection only; no client-asserted verified fields or arbitrary split/full-name inference. The user can edit the prefill, and the accepted display name alone becomes profile data.
Mode choice is exact `{mode:'just-me'}` with no extra keys, admitted only after a persisted completed profile (nonnull valid displayName); an incomplete/null view never implies completion. User chooses after profile: no automatic choice, household/member/consent creation or household endpoint. “My household” remains the separate future flow.
