# ST-237 C28 partial-case isolation security and platform readiness

**Decision: conditional Type 2a source GO for proof-case isolation only; actual feature acceptance remains HOLD.** C27's four natural Firefox variants each reached one partial completion request and observed 409, with no partial read. The source has a zero-argument `DevelopmentEnrollmentPersonVerifier.verify()` which always verifies the fixed `DEVELOPMENT_ENROLLMENT_PERSON` using the epoch simulator HMAC key. The primary enrollment already committed that subject in the same fixture, and the durable enrollment path returns login-required for an existing active external identity. This explains the observed collision at the source level; the closed C27 receipt itself did not identify the 409 reason. Do not reinterpret 409 as a successful partial commit.

Approve a strict `--case profile|partial-terminal` proof selector, with the workflow invoking the existing harness twice in order for each locale/theme matrix job. Each invocation must create a distinct owned PG fixture, epoch/bundle, NSS/TLS trust, server and browser context, verify source and executed build pins, and complete cleanup before the next starts. The workflow must require separate exact-case PASS receipts and a final four-variant result requiring both cases. An absent/unknown case, duplicate or extra argument, failed first invocation, missing receipt, or cleanup failure must fail closed. Keep the two invocations serial on the same matrix job; ensure the job timeout covers both without enlarging browser waits.

The `profile` case must run every existing primary natural-browser step through saved authoritative read, negative authority matrix, same-key fresh-process restart, lost PATCH response single submission, and real reload stop/editor absence. Keep its current mandatory browser status/cookie/wire assertions and all harness refusal, ordinary/qualified catalog, owner-RLS, schema drift, source-pin and custody gates. Its owner persistence query should require exactly one committed natural profile with the existing updated name, completeness, currency, locale and theme; the old total of two belonged to the combined two-enrollment fixture and must not be retained or silently skipped.

The `partial-terminal` case must start with an empty natural browser and a fresh fixture, then run the existing natural identifier, OTP and mandatory simulator action. Keep exact completion 201, one request, selective terminal-cookie delivery, profile read 403 with closed body, login-required stop, editor absence, and retained access/binding but no chain/refresh. Keep `partial-identifier.png` before fill and `partial-terminal-stop.png` after all stop/cookie assertions. The harness must verify exactly one newly committed natural identity/profile and corresponding terminal session/credential family in this fresh fixture, while retaining the same ordinary/qualified catalog, owner-RLS, refusal, source-pin and cleanup checks. It must not satisfy the browser case by inserting an owner, person, session, token, or cookie through test setup.

Use distinct case-labelled closed PASS/FAIL markers and anchored reporter allowlists so a partial-only run cannot impersonate a profile pass. Keep the existing closed status vocabulary and no raw error, credential, identifier, SQL value, body, or URL in receipts. Since screenshot output currently resides under a matrix job's shared TEMP path, prevent a stale image from the first invocation being mistaken for the second case: use case-specific confined screenshot paths or clear/verify expected files before each invocation, and publish the two case artifacts distinctly. Preserve fail-closed abort/route handling, TLS hostname validation, loopback binding, private file modes, owned-container checks, and mandatory cleanup in both cases.

No product, API, SQL, verifier, key, authority, simulator, timeout, retry, expected-status, or runtime change is authorized. This is a proof topology change only. The proposed split is preferable to deleting or recycling the first subject within one fixture: the latter would alter the state being proved and could hide session authority defects. The C28 source needs independent review and a fresh exact-head four-variant natural-browser run through all later gates. Keep the original `2026-10-11T16:53:20.061Z` deadline and historical counters. With the stated remaining author and full-PR budgets, stop and re-estimate if the complete split cannot fit; do not land a partial proof that skips a mandatory gate.
