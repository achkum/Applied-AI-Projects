## Fixed audited business statements

Register exactly two named statements in the private authority constructor, `profileRead` and `profilePatch`; the route supplies only parsed values plus the owner ID received from the authority callback. No caller statement map, SQL text, column name, role/GUC, digest or owner argument. Use `OwnerTx.execute('profileRead', [owner.identityId])` and `OwnerTx.execute('profilePatch', [owner.identityId, hasDisplayName, displayNameOrNull, hasColour, colourOrNull, hasEmoji, emojiOrNull, hasLanguage, languageOrNull, hasTheme, themeOrNull])`. Values have exactly the following PostgreSQL types: `$1 uuid`; `$2,$4,$6,$8,$10 boolean`; `$3 varchar(120)`, `$5 varchar(32)`, `$7 varchar(32)`, `$9 varchar(2)`, `$11 varchar(16)`. Parse canonical values before binding; absent fields use false/null, explicit nullable avatar fields use true/null. For name/language/theme, true/null is invalid. Never accept a client `profileComplete` or currency value.

Proposed exact `profileRead` literal (one parameter), called after the current-authority live-identity lock; its own fresh SELECT is the authoritative persistence proof:

```sql
SELECT p.display_name AS "displayName", p.avatar_color AS "avatarColourToken",
       p.avatar_emoji AS "avatarEmoji", p.language, p.theme,
       p.default_currency AS "defaultCurrency", p.profile_complete AS "profileComplete"
FROM public.identity_profile AS p
WHERE p.identity_id = $1::uuid
```

Proposed exact `profilePatch` literal (eleven parameters), with no dynamic identifier and no currency assignment:

```sql
UPDATE public.identity_profile AS p
SET display_name = CASE WHEN $2::boolean THEN $3::varchar(120) ELSE p.display_name END,
    avatar_color = CASE WHEN $4::boolean THEN $5::varchar(32) ELSE p.avatar_color END,
    avatar_emoji = CASE WHEN $6::boolean THEN $7::varchar(32) ELSE p.avatar_emoji END,
    language = CASE WHEN $8::boolean THEN $9::varchar(2) ELSE p.language END,
    theme = CASE WHEN $10::boolean THEN $11::varchar(16) ELSE p.theme END,
    profile_complete = (CASE WHEN $2::boolean THEN $3::varchar(120) ELSE p.display_name END IS NOT NULL),
    updated_at = pg_catalog.clock_timestamp()
WHERE p.identity_id = $1::uuid
RETURNING p.display_name AS "displayName", p.avatar_color AS "avatarColourToken",
          p.avatar_emoji AS "avatarEmoji", p.language, p.theme,
          p.default_currency AS "defaultCurrency", p.profile_complete AS "profileComplete"
```

Require exactly one returned row and validate the returned `ProfileView`; zero rows are generic conflict/unavailable, never a foreign-owner disclosure. The authority holds the identity row lock through update and commit. PostgreSQL `identity_profile` FORCE RLS plus the runtime owner policy filters both statements, and no statement changes `identity_id`, trusted `identity` fields or currency. A changed name derives completeness from persisted canonical value in that same UPDATE. The initial profile is inserted by ST-236 with null name and false completeness. No pre-read client cache controls UPDATE. On uncertain COMMIT, do not claim saved; the client may make a fresh current-authority POST read only if its session remains valid, and must not automatically replay PATCH.
