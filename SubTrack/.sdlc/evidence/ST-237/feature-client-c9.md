## Source findings

1. **Major — unchanged/invalid profile can still be submitted.** `profile-editor.tsx` renders Save with `disabled={busy}`. `candidate()` and `parseProfilePatch()` reject unchanged or invalid values on submit, which prevents a PATCH and gives feedback, but the frozen `client-readiness.md` requires Save disabled until an allowed change exists **and parses**. The new test explicitly expects the unchanged Save button enabled. Reconcile the disabled state with direct invalid-field feedback so users can see why a changed invalid name cannot be saved. See `apps/web/components/onboarding/profile-editor.tsx` and `apps/web/test/profile-editor.test.tsx`.
2. **Major — computed completeness is not shown.** `ProfileEditor` receives the strictly parsed `ProfileView` but never renders `view.profileComplete`; its visible read-only server value is SEK. The frozen editor criteria require computed completeness to be displayed only from the authoritative reread. Add localized completion/incompletion text tied to the returned view, keeping the saved announcement dependent on known 200 PATCH plus distinct 200 read. See `apps/web/components/onboarding/profile-editor.tsx` and both i18n catalogs.
