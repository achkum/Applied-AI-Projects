## Security findings

- The ingress is one Node `https.Server` bound to `127.0.0.1:3443`. It passes the original Node request/response directly to Nest's Express adapter for the proof POST. The controller requires an encrypted `TLSSocket`, loopback peer, exactly one raw Host and Origin header, and the expected parsed authority. Next handles the actual built registration page on that same listener. There is no HTTP API hop or header rewrite in this scaffold (`private-https-preflight.mjs:27–63`).
- The private CA and leaf are generated in a mode-0700 task directory under `umask 077`; the leaf has DNS SAN `localhost` and no IP SAN. The task CA is imported only into an owned Firefox NSS profile. The browser uses Playwright 1.63.0 without `ignoreHTTPSErrors` or global TLS disabling. The positive loads real Next and posts through browser `fetch`; the wrong-IP case requires Firefox `SSL_ERROR_BAD_CERT_DOMAIN`, and the clean-profile case requires `SEC_ERROR_UNKNOWN_ISSUER`. A fresh positive after each negative prevents a stopped listener from satisfying them (`private-https-preflight.sh:84–116`, `.mjs:80–121`).
- The runner redirects all command, browser and server diagnostics into the private temporary directory. The exported receipt consists of fixed input metadata, fixed PASS markers or a fixed FAIL phase, and a cleanup state; it does not export raw browser errors, certificate/key contents or full internal logs. TERM/KILL targets the recorded process groups, then the owned directory is removed and absence verified before `PROOF PASS` (`private-https-preflight.sh:10–55,118–144`).
- The workflow checks out the PR head, pins Ubuntu 24.04, Node 22, pnpm 12.6.0, and the direct `playwright@1.63.0` web dependency. The lockfile change is only the matching importer entry. Firefox comes from Playwright's matching browser manifest; the actual Firefox and `libnss3-tools` versions are printed in the receipt. The script compares the expected 40-hex head with Git HEAD and verifies committed blob IDs and working-file hashes for both proof programs, the workflow, web package manifest and lockfile (`.github/workflows/subtrack-private-https-profile-proof.yml:21–55`, `private-https-preflight.sh:57–82`).

## Limits and gate

The five-file source pin does not hash every Next page/API dependency or assert a fully clean worktree. In the dedicated CI job, fresh checkout of the expected head plus frozen install supplies the broader source context; a receipt from an arbitrary local dirty checkout would not be exact-head evidence. Treat only the workflow artifact tied to this commit as the required proof. The apt package version is recorded at runtime rather than fixed to a package release; retain that receipt for review.

The author reports syntax and wrong-head checks, but no Linux Firefox/NSS browser execution yet. Require the actual workflow to emit its trusted-host, wrong-host, untrusted-CA and custody PASS markers with `PROOF PASS head=05d6b45f66b09df1d418b361c353c6b90f44f1d7 cleanup=removed`, and have independent QA inspect that exact run before broader ST-237 source GO. Any missing marker, unexpected TLS error, failed cleanup, or different head is a stop.
