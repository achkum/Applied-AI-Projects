# Next executable slice: source inventory (read-only assessment)

2026-10-11. ST-237 is still IN_PROGRESS; this inventory is not source GO, an accepted profile receipt, or a claim of production readiness. It records the smallest next **usable** private flow after ST-237 acceptance: a person with a persisted completed profile explicitly chooses **Just me**, then opens and changes the status of a real owner subscription through the same current browser session. It does not substitute a seeded subscription fixture for an enrollment-produced owner or count the current mock Home/detail screen as an owner read. This note made no source, task, backlog, or Git changes.

Its accepted rule requires a **persisted completed profile before a later explicit choice**. The component has no mode HTTP operation or persistence. `docs/product/USER_FLOWS.md` UF-01 steps 5–6 and `PRODUCT_SPEC.md` F1.4/F1.5 preserve that order and keep My household as a separate path.
- Current ST-237 source has ordinary migration `apps/api/prisma/migrations/0003_enrollment_profile/migration.sql`, Prisma `IdentityProfile`, SQL010 qualified profile RLS, fixed `profileRead/profilePatch` statements, `/v2/me/profile/read` and PATCH `/v2/me/profile`, a mounted editor and private HTTPS launcher. The launcher installs **only** `PRIVATE_PROFILE_STATEMENTS` into `DurableCurrentWebAuthority`; it does not install a mode or subscription statement. Its profile browser/PG matrix is under validation, so none of these is accepted yet.
- `DurableCurrentWebAuthority.withCurrentWebAuthority` already verifies the signed current session, binding/Origin/chain/CSRF, locks a live identity, sets both owner GUCs under `subtrack_runtime`, executes a fixed named statement set, rechecks authority and commits before disclosure. - Existing `/v2/subscriptions/{id}/read` POST `{}` and `/v2/subscriptions/{id}` PATCH `{status}` contracts specify exact current-browser wire behavior, owner/peer projections, lifecycle pairs and invisible foreign/missing IDs. `SubscriptionReadService/Repository`, `SubscriptionLifecycleService/Repository`, browser HTTP adapters and isolated proof compositions exist. ## Boundary and sizing

Existing subscription controllers' Prisma/proof compositions are useful policy and decoder references, but their independent fixture authority cannot simply be mounted beside the ST-237 profile handler. The integrated owner transaction and current-session proof are the central work. The existing mode component is a data shape, not endpoint or storage authorization. ST-237's private tuple, pinned manifest/epoch, direct trusted TLS, sole loopback PG binding, exact cookie roster, disabled refresh/delete/legacy competitors and no real provider remain mandatory. Enabling those competing writers later needs the shared identity/session lock and erasure protocol, with race proof; no extra default/public/production activation follows from this slice. No private data, credentials or provider delivery should enter evidence.

Practical provisional estimate: mode contract/migration/qualified SQL/strict tests 350–550 nongenerated lines; authority statements plus owner subscription/mode HTTP and focused tests 500–800; web mode/detail API/UI, i18n and accessibility tests 400–650; actual PG/HTTPS browser proof and task evidence 600–900. Total **about 1,850–2,900 nongenerated lines plus generated bindings**, likely one L240 task with an explicit reviewed >600-line exception and measured source/PR caps. Scope and clock must be frozen by the Conductor after ST-237 actually passes; the existing ST-237 in-progress tests, task budget and source paths cannot be counted as acceptance or preempted. If the integrated slice will not fit, the split must leave a usable explicit persisted mode and owner-detail path, rather than another isolated helper/editor contract.
