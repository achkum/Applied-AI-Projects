## One executable topology

Use one task-owned Node HTTPS entry bound to `127.0.0.1:3443`, with a leaf certificate containing DNS SAN `localhost`; browser URL and sole permitted `Origin` are exactly `https://localhost:3443`. Initialize an isolated private Nest application against its own Express adapter, then dispatch the original Node `IncomingMessage`/`ServerResponse` for `/v2` and `/v2/*` directly to that adapter and all other requests to the Next request handler. The private controller/module roster is explicit. This keeps `request.socket instanceof TLSSocket` true for `extractV2BrowserEvidence` (`apps/api/src/auth/http/v2-browser-context.ts`) and avoids an HTTP API upstream, proxy TLS assertion, Host/Origin rewrite, or cookie-path translation. Use a private composition and launcher, not `apps/api/src/main.ts` or default `AppModule`; do not bind `0.0.0.0`. Reject a second Host/Origin, non-loopback peer, any cleartext request, forwarded-proto claims, and a second listener. If this direct in-process dispatch cannot preserve raw headers and the real TLS socket through the selected Nest/Express adapter, **freeze fails**; a replacement hop requires an authenticated HTTPS upstream with CA or peer pin *and hostname verification*, proved before source GO.

The browser calls same-origin `/v2/auth/*`, `/v2/me/profile` and `/v2/me/profile/read` with `credentials:'include'`; JavaScript never synthesizes `Origin`, `Cookie`, or `Host`. The current web rewrite in `apps/web/next.config.ts` maps `/api/v2/auth/*` to `http://127.0.0.1:4000/v2/auth/*`, while `apps/web/lib/registration-api.ts` uses `/api/v2/auth/*`. Neither path sends the accepted `Path=/v2` access cookie or `Path=/v2/auth` refresh cookie. The private flow must call external `/v2/*` directly. Retain host-only `Secure; HttpOnly; SameSite=Lax` `st_v2_access` at `/v2`, `st_v2_refresh` at `/v2/auth`, and the one accepted binding cookie. Never set `Domain`, return tokens in JSON, weaken `Secure`, use credentialed reflected CORS, or cache a credential/profile/problem response. The access cookie need not reach Next page requests: keep the profile editor mounted in the live registration component, holding public `sessionId` and current CSRF only in volatile memory. Reload with lost CSRF stops at a localized verified-login-required state; no current recovery/login endpoint is created.

Browser trust is a required implementation proof, not a launch flag. Proposed harness: an ephemeral task-owned Linux browser container/profile with a task-generated local CA; issue a leaf with SAN `localhost`, import only that CA into the **ephemeral Firefox NSS profile**, start the browser with that profile, navigate to `https://localhost:3443`, and assert successful validated hostname/chain. Put key/CA/profile outside Git in private temporary custody, restrict mount/permissions, and destroy them after the run. Run the browser and loopback-bound ingress in one task-owned network namespace (for example, browser container sharing the ingress container namespace); ordinary Docker bridge access to the host loopback listener does **not** satisfy this. Pin the actual browser image, Firefox version and NSS tool/package at source GO after an owned feasibility run; the repository lock currently contains Playwright 1.63.0 transitively but has no direct browser harness or pinned image. Playwright documents persistent Firefox profile launch and version-matched pinned browser images ([BrowserType](https://playwright.dev/docs/api/class-browsertype), [Docker](https://playwright.dev/docs/docker)); Mozilla's NSS documentation describes the website trust bit for an imported CA ([NSS root store](https://firefox-source-docs.mozilla.org/security/nss/runbooks/rootstore.html)). The exact NSS import into a Playwright Firefox profile remains to be *proved* in the owned preflight, including wrong-host and untrusted-CA failures; these docs alone do not establish it. No `ignoreHTTPSErrors`, certificate-error/SPKI bypass flag, `NODE_TLS_REJECT_UNAUTHORIZED=0`, global TLS-off, persistent OS trust/hosts change, or key/log disclosure. If task-owned NSS trust and namespace routing are unavailable in CI, this is a concrete topology blocker; do not substitute a mock/browser TLS bypass.

## Frozen authority and wire sequence

Reuse `DurableDevelopmentEnrollment` signatures and accepted contract exactly: `startOtp(web,{identifier,channel,purpose:'enroll_identifier'},key)` → raw `challengeId,nextBrowserNonce`; `verifyOtp(web,{challengeId,code},key)` → raw restricted `proof,nextBrowserNonce`; `admit(web,{proof},key)` → raw `pending,nextBrowserNonce`; `verifyPerson(web,{pending},key)` awaits the existing zero-argument `DevelopmentEnrollmentPersonVerifier.verify()` → raw `verified,nextBrowserNonce`; `complete(web,{verified},key,privateLocaleHint?)` → known-committed `identityId,sessionId,refreshToken,csrfToken,profile`. The HTTP adapter alone maps raw canonical 43-base64url handles to accepted public `v2.`, `wep.`, `wev.` domains in the proper direction; it never exposes raw handles. Existing verifier uses its server-owned fixed simulator person, HMAC key and trusted result; no client identity, person selector, provider response, contact, name or role field is accepted. Its fixed subject means a second enrollment for the same subject reaches `ENROLLMENT_LOGIN_REQUIRED`; cross-owner profile denial uses separately seeded qualified identities/sessions, never a caller-selected simulator subject.

Follow `docs/product/API_CONTRACT.md` and `packages/contracts/openapi.yaml` exact enrollment bodies/statuses: bootstrap 200, OTP start 202, OTP verify 200, pending 201, simulator verify 200, complete 201. Every mutating enrollment call has exactly one valid `Idempotency-Key`, one browser-created `Origin`, one binding cookie and 43-character `X-Browser-Nonce` where the accepted operation requires it; reject query, duplicate/framed headers, ambiguous cookies, Authorization, CSRF/access/refresh credentials before pre-session work. Return only accepted response fields and generic RFC 9457 problems: 400 malformed, 401 invalid restricted/provider authority, 403 Origin/binding policy, 404 disabled, 409 restart/login-required, 429 bounded throttle/capacity, 500 masked dependency. Wrong-code fifth attempt must retain its committed terminal attempt/burn. No retry/replay after 409, lost/uncertain terminal response, or cookie-write failure; client clears continuation and offers a fresh verified-login path only when separately supported.

After known terminal commit, construct the accepted `V2AccessToken` with epoch-owned matched Ed25519 keys, issue once from **server-returned** `identityId,sessionId`, then write the two cookies and return exactly `WebSessionResponse {transport:'web',sessionId,csrfToken}`. No token/refresh credential in body. The accepted 15-minute access and 24-hour session bounds remain. Profile read and patch use the unchanged `DurableCurrentWebAuthority.withCurrentWebAuthority`: verify token `sub/sid`, exact Origin, canonical binding, same browser chain and current `X-Session-CSRF`, lock live identity first, set `SET LOCAL ROLE subtrack_runtime` and equal server-derived `app.user_id`/`app.current_user_id`, check durable current session/CSRF before and after the callback, fence epoch/manifest, commit, and prove pool role/GUC cleanup. No generic owner/SQL callback or request-supplied statement name is exposed to HTTP.

Contract-first profile operations: **`POST /v2/me/profile/read`** takes exactly JSON `{}` and performs a fresh owner-scoped SELECT under current CSRF; as a pure read it has no idempotency key. **`PATCH /v2/me/profile`** takes one nonempty strict `ProfilePatch` containing only `displayName`, `avatarColourToken`, `avatarEmoji`, `language`, `theme`, then performs owner-scoped UPDATE and returns persisted closed `ProfileView`. No GET is accepted: ordinary browser GET need not have `Origin`, while current durable authority requires Origin and CSRF for every operation. `profileComplete` is computed from persisted canonical display name; `defaultCurrency:'SEK'` is read-only. Strict decoder rejects unknown/duplicate JSON keys, forbidden query, owner/session/contact/verified-name/currency/mode selectors, wrong media and invalid canonical Unicode. `200` closed view on either success; `400` bad envelope/patch, `403` only syntactically rejected Origin/binding/chain/CSRF envelope, generic `401` for any unavailable current authority, session, owner or pre/post-check failure, `409` generic profile state/uncertain write, `500` masked infrastructure. The unchanged current authority collapses its internal failures to one generic error; the adapter must never infer wrong CSRF versus absent owner or reveal that distinction. Never return owner-existence 404. `Cache-Control:no-store` and `Pragma:no-cache` apply to all `/v2` success/problem responses, with no error `Set-Cookie`.

The trusted server composition must supply **only** named static `profileRead` and `profilePatch` SQL literals to `DurableCurrentWebAuthority.businessStatements`. `DurableCurrentWebAuthority.FORBIDDEN_SQL` rejects quoted identifiers and aliases, so SQL uses unquoted snake_case columns and the adapter maps returned fields to strict camelCase `ProfileView`. Freeze these exact quote-free literals with storage/security before source GO; they are corrected from the storage note's quoted camelCase aliases, which the accepted constructor would reject:

```sql
SELECT display_name, avatar_color, avatar_emoji, language, theme, default_currency, profile_complete
FROM public.identity_profile
WHERE identity_id = $1::uuid
```

```sql
UPDATE public.identity_profile AS p
SET display_name = CASE WHEN $2::boolean THEN $3::varchar(120) ELSE p.display_name END,
    avatar_color = CASE WHEN $4::boolean THEN $5::varchar(32) ELSE p.avatar_color END,
    avatar_emoji = CASE WHEN $6::boolean THEN $7::varchar(32) ELSE p.avatar_emoji END,
    language = CASE WHEN $8::boolean THEN $9::varchar(2) ELSE p.language END,
    theme = CASE WHEN $10::boolean THEN $11::varchar(16) ELSE p.theme END,
    profile_complete = (CASE WHEN $2::boolean THEN $3::varchar(120) ELSE p.display_name END IS NOT NULL),
    updated_at = pg_catalog.clock_timestamp()
WHERE p.identity_id = $1::uuid
RETURNING p.display_name, p.avatar_color, p.avatar_emoji, p.language, p.theme,
          p.default_currency, p.profile_complete
```

`$1` is derived `owner.identityId` (`uuid`); `$2,$4,$6,$8,$10` are parsed presence flags (`boolean`); `$3` `varchar(120)`, `$5,$7` `varchar(32)`, `$9` `varchar(2)`, `$11` `varchar(16)` are parsed values. Absent fields bind false/null; explicit nullable avatar clear binds true/null. Nonnullable name/language/theme true/null is rejected. Both callbacks require exactly one returned row, strict `ProfileView` mapping and no client-provided operation name or owner. No dynamic SQL/columns, caller GUC, pre-read client cache or currency assignment. SQL010 already has `identity_profile` FORCE RLS, `subtrack_runtime` own-row policies and runtime SELECT/INSERT plus column-limited UPDATE; ordinary migration must match accepted business schema exactly. The accepted writer currently grants UPDATE on `default_currency` for fixture service compatibility, but HTTP must never expose currency mutation. A deleted owner is denied by the live identity lock even if a profile row remains.
