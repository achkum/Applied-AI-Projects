## Blocking findings

1. **Major — Startup does not qualify the installed writer graph or business policy.** `apps/web/private-https-server.mjs:53-102` verifies named function count, SECURITY DEFINER ownership, table presence, FORCE RLS flags, and one successful epoch fence. It does not compare function signatures/bodies/configuration or profile columns, constraints, policies, and ACLs. A changed `check_current_web` or enrollment function body, or a broadened `identity_profile` policy/grant, can still allow the server to open HTTPS. The separate ordinary/qualified catalog comparison in `apps/api/test/private-profile.integration.ts:36-40` only compares two fresh installations; it cannot reject a subsequently drifted private installation at startup. Qualify an exact reviewed catalog/function definition and writer/role graph before `server.listen` and add actual startup refusal cases for tampered function, policy/grant, and profile shape. Keep operation fences and connection reset checks.

2. **Major — Actual private proof omits same-install restart and refusal evidence.** `tools/database/private-profile-proof.sh:138-173` launches one server, drives one browser enrollment/profile flow, checks persistence and a small owner/RLS matrix, then cleans up. The bundle parser's unit tests do not prove a fresh server process reopened the *same* key file and preserved session/CSRF/burn authority in PG16. The script also does not mutate one key, the Ed25519 pair, declared digest, bundle presence, active epoch row, or schema and assert HTTPS startup refusal; nor does it exercise unknown-commit/lost-response behavior. Add owned disposable tests for those cases, including wrong DB/Origin/epoch pairing and the preserved old qualified fixture at this changed head. Assert no listener is opened on failure, without emitting keys or credential bodies.

3. **Moderate — The proof's supply and source pin is incomplete.** `tools/database/private-profile-proof.sh:16` uses mutable `mirror.gcr.io/library/postgres:16-alpine`; `custody()` compares the configured tag rather than an immutable image digest. The tracked-input SHA/blob loop at lines 80-88 runs only before the server and browser, with no finish comparison; compiled `apps/api/dist` code executed by the launcher is not itself attested. Pin the PG16 image digest, bind build outputs to the checked source in the proof or require a clean exact-head build, and recheck all source inputs at the end before printing `PROOF PASS`. The workflow's preflight is a TLS feasibility proof; its profile matrix does not run the historical ST-233a qualified fixture proof, so record a separate exact-head receipt for that regression.

4. **Moderate — Natural-browser authority negatives are too narrow for the acceptance matrix.** `apps/web/test/private-profile-browser.mjs:96-116` probes wrong CSRF, malformed bodies, successful read, and a reload stop. It does not prove missing/duplicate/cross-session chain and binding, wrong Host/Origin, profile refresh-path denial, cookie invisibility to JS/page routes, expiry/deleted owner, partial terminal cookie write, late abort, or double submission over the actual HTTPS/PG path. Add targeted actual negative requests with closed problem/status assertions and no sensitive output. This is especially relevant because the new `st_v2_chain` comparison cookie is part of current authority, while refresh is outside this feature.

5. **Major — Enrollment adapter collapses unrelated infrastructure and authority failures to replay conflict.** `apps/api/src/auth/enrollment-v2/private-enrollment-http.ts:162-165` maps every non-wire exception to 409, except the login-required code. The published matrix has separate 401, 429, and 500 outcomes. A PG outage or invalid authority is therefore presented as a one-use restart. Preserve generic externally safe responses but classify trusted internal failure states, with tests for each status and the uncertain terminal-result case. This is a platform reliability issue as well as a client guidance issue.
