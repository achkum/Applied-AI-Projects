# ST-237 early TLS feasibility author handoff

Scope: source scaffold only under the Conductor's conditional Type 2a early TLS GO. This does not establish enrollment, profile persistence, qualified database behavior, or browser PASS until the new workflow runs at its exact PR head.

The proof uses one Node `https.Server` on `127.0.0.1:3443`. Its `/v2/tls-preflight` POST passes the original `IncomingMessage` and `ServerResponse` directly to an isolated Nest application on an Express adapter. The controller asserts that Express still sees an encrypted `TLSSocket`, a loopback peer, the browser's exact `Origin`, and single raw Host/Origin headers. Other requests reach the real built Next `/sv/register` page. No API HTTP hop is present. This isolated proof controller does not register enrollment or profile routes.

The script creates a one-day task CA and leaf with DNS SAN `localhost` only in an owned temporary directory. NSS `certutil` imports that CA into only one ephemeral Firefox profile. Playwright 1.63.0 launches Firefox against that profile, loads Next, and issues a browser-created same-origin POST to Nest. It then rejects the same leaf at `https://127.0.0.1:3443`, and rejects the localhost leaf from a separate clean Firefox profile. The trusted profile, clean profile, certificates and keys are removed by the script's exit trap; server/browser process groups are terminated by their recorded owned PIDs. Logs remain in the same private temporary directory and are removed; CI exposes only fixed PASS/FAIL markers. No certificate bypass or persistent system trust is used.

`playwright@1.63.0` was already in the lockfile's virtual store but could not resolve from `apps/web`. The exact direct web dev dependency and three lockfile importer lines are the only dependency changes. Workflow pins Ubuntu 24.04, Node 22, pnpm 12.6.0 and Playwright 1.63.0; `libnss3-tools` comes from the selected Ubuntu apt repository and is therefore a remaining package-version pin question for independent review. The Playwright package selects its own Firefox revision from its installed browser manifest. All processes run on the same ephemeral GitHub runner network namespace; no Docker image or host bridge is involved.

Local checks: `node --check apps/web/test/private-https-preflight.mjs` passed. Web-scoped Playwright 1.63.0 and API Nest/Express resolution passed. The full browser proof has not run locally (no Linux NSS/Firefox environment); require actual workflow PASS at the exact PR head before full-feature source GO.
