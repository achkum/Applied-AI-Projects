## Focused profile locator finding

The register page mounts `Preferences` in its locale layout. `Preferences` renders a `div role="group" aria-label={copy.themeLabel}` while `ProfileEditor` renders `<label htmlFor="profile-theme">{copy.theme}</label>` and its select. In both catalogs, these labels are identical: English `Color theme` and Swedish `Färgtema`. The driver uses unscoped `page.getByLabel(copy.profile.theme, { exact: true }).selectOption(theme)` after `profile.png`. Playwright label lookup can match an element with an accessible `aria-label` as well as an associated form label, making this locator ambiguous and a concrete candidate for a strict locator failure before any PATCH. Scope profile controls to the named profile region (`page.getByRole('region', { name: copy.profile.title, exact: true })`), which is backed by the editor section's `aria-labelledby="profile-title"`; retain all assertions and the separate global preference control. C19's fixed `PROFILE_EDIT` phase and `patch=NONE` would corroborate this candidate. The two English identifier failures are separate and still need their own C19 phase evidence.
