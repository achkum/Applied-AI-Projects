The C25 actual four-variant Firefox matrix passed the bounded reload observation, localized verified-login stop, and mounted editor absence, then failed in the former combined `PARTIAL_TERMINAL` phase. The safe receipt did not identify which partial-terminal action or assertion failed. This is a diagnostic change only; partial-terminal acceptance remains HOLD.

Its failure receipt appends only closed `partialNavigation=(200|304|400|404|500|NONE|OTHER)`, `partialCompletion=(201|400|401|403|409|500|NONE|OTHER)`, `partialRead=(200|400|401|403|409|500|NONE|OTHER)`, `partialCompletionCount=(ZERO|ONE|MANY)`, and `partialRoute=(NONE|OK|FAILED)`. The Conductor owns matching both anchored reporter allowlists before the next actual run.

The route callback records its fixed completion status. If its existing fetch, status, cookie-roster, clear, or fulfill operation fails, it records `FAILED` and attempts to abort that one request without printing the exception. A deferred signal settles in the callback's `finally`, after either `OK` or `FAILED` is recorded and any abort attempted. The main flow waits for that settlement within the existing 45-second completion window before checking `partialRoute=OK`; a browser response arriving before the callback returns cannot cause a false failure. It still requires committed completion, exactly one completion request, the closed 403 profile-read body, localized stop, editor absence, and the exact retained cookie roster. The prearmed profile-read promise has an attached rejection handler so a failed click cannot create an unhandled rejection. No action, retry, timeout increase, server/product/security behavior, or success assertion was removed. No URL, query, body, cookie value, credential, profile value, console message, or raw exception enters the receipt. A fresh exact-head actual run and independent review are required.
