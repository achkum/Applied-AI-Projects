# ST-237 browser-chain cookie — narrow security readiness

Security review, 2026-10-11, for the private ST-237 HTTPS slice only. I read `backend-author.md`, the earlier `security-exact-readiness.md`, the current enrollment completion/current-web authority source and SQL009. This is a conditional **Type 2a GO for the cookie wiring**, not feature acceptance or an executed browser/PG proof. There is no new Type 1 founder hold for the exact change below. No source, Git, test, provider or deployment state was changed by this review.

`DurableDevelopmentEnrollment.complete()` already obtains the browser chain from the SQL-matched enrollment witness and returns it internally as `browserChainId` only after known terminal commit. SQL009 `check_current_web` compares that chain with the stored live session together with the token-derived owner/session, exact Origin, binding digest, current CSRF, epoch and manifest. The accepted `WebSessionResponse` exposes only transport, sessionId and csrfToken; it has no chain field. The backend may pass the internal chain to the private completion adapter and set **one** `st_v2_chain=<canonical 43-character base64url value>; Path=/v2; Secure; HttpOnly; SameSite=Lax` cookie, with no `Domain`. Emit it in the same successful completion response as the existing access and refresh cookies, after known commit and access-token issue. Do not place the chain in JSON, URL, JavaScript state, logs, snapshots or error details. Its role is a nonauthoritative comparison witness; possession alone never authenticates, selects an owner, bypasses CSRF, or supplies a recovery path.

For profile POST read and PATCH, parse the raw Cookie header without coalescing; require exactly one each of `st_v2_access`, `st_v2_binding` and `st_v2_chain`. Reject repeated Cookie headers, duplicate names even with the same value, malformed quoting/whitespace/separators and ambiguous encodings before invoking authority. Reject `st_v2_refresh` on profile routes; its `/v2/auth` path means an ordinary browser will not send it there. Define the private route's accepted cookie roster explicitly and reject unexpected auth/chain aliases or collisions; bootstrap/enrollment routes reject a preexisting chain/access/refresh cookie. Check the chain is canonical 32-byte base64url (43 characters, round-trip encoding), then pass its **unchanged** value to `CurrentWebRequest.browserChainId`. Keep exact TLS/Host/Origin, access, binding and current `X-Session-CSRF` checks, and the unchanged current authority's SQL pre/post checks and owner/GUC/role/pool cleanup. No new lookup function, SQL grant, table read, session bypass, callback authority, token claim or contract response field is approved.

Use a session cookie with no `Max-Age`/`Expires`, or a positive lifetime no longer than the remaining durable session (at most 24 hours); never extend it on profile reads/patches. The database's live session expiry remains decisive even if a browser restores session cookies. The existing access token lasts at most 15 minutes, so this slice cannot use the chain cookie to continue profile access after access/CSRF loss. Do not add refresh or reload recovery here. An unknown/lost terminal response or partial cookie write remains an unknown committed outcome: clear local continuation, stop safely and never replay terminal completion or issue replacement credentials. Error responses carry no `Set-Cookie`; success and problem responses remain `no-store`/`no-cache`.

Before accepting the private listener, pin and check that `st_v2_chain` cannot collide with configured binding/access/refresh or other private cookie names, that the route/cookie roster is exactly the reviewed one, and that no competing writer/recovery module is mounted. Update task-owned source/cookie inventory documentation and exact-head tests to cover successful known-commit cookie flags/path/host-only behavior; missing, malformed, duplicate, wrong and cross-session chain; wrong Origin/binding/current CSRF; rejection of refresh on profile and chain before enrollment; expiry, revoked/deleted owner, lost terminal response and partial cookie write. The browser proof must show the cookie reaches `/v2/me/profile/read` and PATCH automatically while remaining unavailable to JavaScript and the Next page route. Existing ST-233a and private qualified PG proofs and the full ST-237 QA/CI gates still apply.
