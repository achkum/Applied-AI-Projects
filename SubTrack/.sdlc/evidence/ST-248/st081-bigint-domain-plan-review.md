# ST081 bigint detector domain stream: independent platform plan review

**Domain algorithm GO; clean-Node runtime export needs one prerequisite correction before source freeze.** No source, storage, API, or authority implementation was made.

The current detector takes `DetectionTransaction.amountMinor:number`, runs `assertSafeMinorUnits(number)` for every transaction before pending/direction filtering, then calls the existing Money constructor and one shared cadence/amount/reason algorithm. An additive bigint entry can preserve old behavior exactly by factoring that algorithm into one internal function with an amount validator argument. Keep `detectRecurring(TransactionSeries)` and its number-safe validator/signature/export unchanged; add distinct bigint transaction/series types and `detectRecurringBigint` with runtime `typeof amountMinor==='bigint'` and an explicit signed persistable minor-unit bound (including rejection of an outflow magnitude that cannot fit the target BIGINT). Do not normalize through Number, duplicate thresholds, or change Money helpers. Tests need legacy golden results and invalid-number behavior unchanged, safe-value output parity, >MAX_SAFE_INTEGER exact amount bands, boundary/overflow, account/currency mismatch, runtime wrong-type rejection, and clean emitted Node import.

The proposed TSC-only `./detection-runtime` export cannot meet the clean-Node condition yet. `detector.ts` imports `@subtrack/money`; `packages/money/package.json` maps its runtime `.` import to `./src/index.ts` and emits no JS runtime. TSC preserves that package import in emitted detector JS. A clean Node consumer therefore still encounters a TypeScript dependency. Freeze one narrow runtime packaging prerequisite first: either compile/export the **existing** Money implementation as a dedicated runtime subpath with an explicit build dependency and test order, or bundle the exact existing Money source into the detector runtime artifact with an owned, pinned build tool. Preserve the current Money default/legacy source export and algorithms, verify package-root import after a clean install/build, and do not rely on dirty `dist`, TS loaders, API fixture bundling or Metro. The selected option must be listed in the ST249 path roster and independently source-reviewed.

Conditional path roster after that choice: `packages/domain/detection/types.ts`, `detector.ts`, `index.ts`, focused detection tests, `packages/domain/tsconfig.detection-runtime.json`, `packages/domain/package.json` for `./detection-runtime` and `build:detection`, plus only the chosen Money runtime packaging/build dependency paths. No SQL/contract/HTTP/native authority code belongs to this first stream. The local ST081 privacy plan also requires Undo's final trusted clock check after awaited writes with no further await before commit, closed expiry on equality/advance, a same-owner feedback→undo composite FK, and exact migration/SQL/column privilege review before any database execution; those are later storage gates, not a reason to widen this pure domain stream.
