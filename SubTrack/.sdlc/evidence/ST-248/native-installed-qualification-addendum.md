## Installed journey

1. Fresh login from `/personal`, open the existing gated Demo bank link, assert explicit Synthetic-only copy and empty retained list. Tap Connect once. Wait for the installed current read to show Connected, one saved account and zero transactions; compare the owned bank receipt: one connection/generation/account, zero transactions/purged, one mutation receipt. No direct API call from the test harness performs a bank mutation.
2. Tap Sync. Wait for the installed current read to show a positive saved transaction count and non-null last sync; compare the owned receipt with positive transaction count and digest. Tap Sync again with a distinct ordinary user action. Verify transaction count and digest remain equal, with one additional immutable mutation receipt. Refresh the bank screen and assert the saved count/status; stage `accepted-bank-active.png` privately after the UI assertions. Log out and verify owner data is hidden.
3. Restart the actual API and app. Compare the closed bank receipt exactly with the pre-restart receipt. Fresh login, reopen Demo bank, assert the same Connected status, count, and last-sync state. Tap Disconnect and keep data; the installed screen must show Disconnected and the same account/transaction counts, and a new Connect action must be available. The bank receipt must preserve connection/generation/account/transaction counts and transaction digest, with one additional mutation receipt. Stage `accepted-bank-retained.png` privately after the disconnected and retained-count UI assertions, then log out. A fresh login/read after a further app restart must still show that retained generation before purge.
4. On that retained generation, tap the separate Remove action, verify the warning, cancel once, and log out. Compare the closed bank receipt exactly with the prior retained receipt: no mutation or deletion occurred. Fresh login, reopen the retained generation, and explicitly confirm removal. Wait for the installed current read to show an empty retained list and the removal acknowledgement. Compare the owned receipt: connection/generation retained as tombstones, `purged=1`, accounts/transactions zero, one more immutable mutation receipt. Assert the original manual tracking receipt remains exactly equal. Stage `accepted-bank-purged.png` privately after the UI assertions. Refresh, log out, and verify no owner bank data remains visible. After another real API/app restart and fresh login, the bank list must remain empty and the final closed bank receipt unchanged; log out again.

No automatic retry follows an uncertain mutation. A conflict or readback failure fails the installed qualification; the existing client/session behavior can require fresh verification, but the driver must not turn that into a successful mutation claim. The three new screenshots are staged privately by Maestro and copied to accepted output only after all matching UI and database assertions pass. Failed screenshots and raw Maestro/API logs stay private. Preserve the current screenshot whitelist and add only these exact names. The final installed receipt gains closed `bankInstalled*` booleans for the asserted journey and retains every parent field. Never publish OTPs, tokens, IDs, names, transaction descriptions, SQL rows, raw responses, or digest values.
