## Exact user and authority boundary

An enrollment-created owner completes and authoritatively rereads a persisted profile. Only then the same live session sends an explicit Just Me choice, receives known-committed success and separately rereads the choice. The list is a truthful persisted owner list; a displayed row supplies the detail UUID internally. An owner changes an allowed status once and separately rereads detail. Empty list is an empty state. No handwritten UUID, household/peer view, fake account, real bank/provider, reload recovery or default/public/production route activation. Synthetic subscription insertion is proof setup in disposable PG16 only; the identity and session must result from natural enrollment.

All new business work runs through the existing `DurableCurrentWebAuthority.withCurrentWebAuthority(request, callback)` and `OwnerTx.execute(name, values)`. Its existing signed access token, exact private Origin, binding, chain, volatile CSRF, epoch/manifest fence, locked live identity, both transaction-local owner GUCs, `subtrack_runtime` role, post-action recheck, known COMMIT and clean pooled connection remain intact. The trusted launcher installs a finite frozen `businessStatements` object. Never expose SQL, a principal, household/scope selector or a new authority callback in a request. Existing isolated subscription Prisma/browser compositions are projection/policy references only. Keep ST-237's `https://localhost:3443`, exact three private cookies, no-store/no-cache and honest reload/partial-cookie login stop.

The currently published `/v2/subscriptions/{id}/read` contract describes owner **or peer** visibility; either narrow its private deployment documentation while preserving the shared `VisibleSubscription` schema elsewhere, or add a private owner-specific response schema. Do not make the private endpoint return a peer projection or claim peer access. The status target matrix is `ACTIVE→PAUSED/CANCELLED/ARCHIVED`, `PAUSED→ACTIVE/CANCELLED/ARCHIVED`, `CANCELLED→ARCHIVED` only. `DETECTED`, `TRIAL`, `REJECTED`, `ARCHIVED` remain visible as owner rows and have no lifecycle controls in this slice.

Use fixed generic problem codes by endpoint, with normal title/status pairs: malformed wire/body/cursor/UUID 400 (`INVALID_MODE_REQUEST` or `INVALID_SUBSCRIPTION_REQUEST`), authority failure 401 `AUTHENTICATION_REQUIRED`, valid-envelope but rejected Origin/CSRF roster 403 (`MODE_REQUEST_REJECTED` / `SUBSCRIPTION_REQUEST_REJECTED`), invisible detail/status 404 `SUBSCRIPTION_NOT_FOUND`, incomplete/other mode 409 `MODE_CONFLICT`, status conflict 409 `LIFECYCLE_CONFLICT`, outside-authority server fault 500 `INTERNAL_ERROR`. To preserve those 404/409 distinctions, the callback returns a typed `{state:'missing'|'conflict'|'ok', value?}` result instead of throwing; the HTTP adapter maps it **after** `withCurrentWebAuthority` has completed COMMIT and pool reset. Throwing inside the callback is collapsed by current authority to generic 401. Preserve that collapse for every authority failure, including uncertain commit; never infer success or retry a mutation. The client does one authoritative mode or detail read after a lost/409 response; if that read fails, clear private state and disable actions. Validate strict closed responses before rendering.

## Complete bounded owner pagination

Fix page size at 50 and query 51 owner rows under current authority. Order by immutable `(created_at DESC, id DESC)` and continue with `< (cursor.createdAt, cursor.id)`. Return first 50, and mint `nextCursor` from the last displayed row **only when row 51 exists**. The owner list UI must provide an accessible next-page action while `nextCursor` exists; it may append or replace pages, but must never silently strand rows after 50. A cursor is an opaque UI token, not an authority source. Follow the existing `SubscriptionReadService` canonical base64url/keyset precedent with a new endpoint discriminator, exact decoded keys/version, UTC timestamp and UUID validators, bounded 512-character encoding, and canonical re-encoding check. The token contains no owner, household or filter selector; server derives owner anew on every page. If a stronger MAC is chosen, pin its existing private server key source and test restart, without adding a client credential or arbitrary configuration selector. Re-evaluate current visibility each page; concurrent insertions can change later pages, so do not advertise snapshot totals. Test empty, 1, 50, 51 and more than 100 owner rows, tied timestamps, malformed cursor and another owner's cursor/rows. A cursor copied to another owner cannot disclose the first owner's rows because SQL always binds the current owner.
