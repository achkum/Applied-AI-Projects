## Mode and list freeze

Contract first: freeze `POST /v2/me/mode` with exactly `JustMeChoice` and `POST /v2/me/mode/read` with exactly `{}` in OpenAPI/generated/closed decoders. Add nullable `identity_profile.onboarding_mode` with only `NULL` and `just-me`, default `NULL`, in ordinary forward migration `0004`/Prisma mapping **and** separately installed, pinned qualified SQL011. Do not edit executed SQL010. The choice callback uses fixed `modeRead` and conditional `modeChoose` under the existing identity lock; write only when `profile_complete=true` and mode is `NULL`. A repeated same choice returns side-effect-free 200 readback (no timestamp update); absent/incomplete profile, other stored mode or corrupt state returns generic 409 after successful authority. A lost response leads to a separate authoritative mode read, not an automatic write retry. The read returns exact `{mode:null|"just-me"}`. No household, membership or consent record is created. The UI advances only after the persisted choice reread. If the final API contract claims completion/choice as a direct-call precondition for list/detail/status, enforce it server-side; UI sequence alone cannot establish that precondition. Owner isolation itself rests on the current authority and owner SQL predicates.

Freeze `POST /v2/subscriptions/owner/read` as an owner-only current-browser read. Initial request `{}`; continuation may carry **only** an opaque, bounded server-produced cursor, never owner/scope/filter/limit. Cap each page at 50 and query 51 rows. Order by immutable `(created_at DESC,id DESC)`; keyset continuation uses strict `<` on that tuple, and `nextCursor:null` only after exhaustion. Use the reviewed canonical base64url keyset precedent with an endpoint discriminator, version, exact timestamp/UUID validation, canonical re-encoding and maximum 512 characters. The cursor contains no owner selector and grants no authority; every page derives owner from the current session and rechecks RLS. Foreign-owner cursor reuse must never disclose rows; malformed/noncanonical cursor gets generic 400. A cursor must be exercised for >50 rows; a first-page-only implementation cannot claim a usable owner list. Concurrent inserts ahead of a cursor need honest non-snapshot semantics. List and detail should return only the owner projection of the established subscription shape; each SELECT must include `s.identity_id=$1::uuid` before ordering/limit even though existing RLS allows some peer visibility. Check merchant-name join and grants if projected; do not join charges, transactions, bank data or detection evidence.

Detail and status use the displayed persisted row ID, still restricted by `id` **and** owner identity. Missing and foreign ID, including a row peer-visible under the older policy, produce the same 404 body/timing class without owner or share metadata. Lock the owner row `FOR UPDATE`; evaluate the accepted matrix from locked status: `ACTIVE→PAUSED/CANCELLED/ARCHIVED`, `PAUSED→ACTIVE/CANCELLED/ARCHIVED`, `CANCELLED→ARCHIVED`. `DETECTED`, `TRIAL`, `REJECTED`, `ARCHIVED`, same-state and disallowed targets conflict with 409. Compare-and-update by ID, owner and old status, return only committed bounded status, and separately reread detail. After 409 or uncertain PATCH the client performs one read, never retries the mutation; a failed reread clears detail and disables actions.

## Failure and wire matrix

All private v2 responses use closed success/problem shapes, strict media and bounded bodies, `Cache-Control: no-store` and no-cache handling; no credential, owner ID, SQL cause or private datum in error/log/snapshot. Reject malformed/duplicate/framed headers, ambiguous credential cookies, duplicate/trailing JSON, query parameters and forbidden body fields before authority work. Keep the exact three-cookie roster and same-origin TLS Host/Origin behavior. No idempotency-key support on these ordinary writes unless explicitly contracted and implemented.

| Condition | Outward result |
| --- | --- |
| Invalid JSON, duplicate keys, body/ID/cursor syntax or unsupported field | Closed generic 400 for the relevant operation. |
| Exact Origin/CSRF/binding/chain **envelope syntax** rejected before authority | Closed generic 403, if retained by the reviewed browser contract. |
| Missing, stale or mismatched current credential/CSRF/Origin/chain/binding; failed epoch, manifest, owner, pre/post check or authority infrastructure | Collapsed 401 `AUTHENTICATION_REQUIRED` from the current authority. Do not infer an invalid current CSRF's cause from it. |
| Authenticated incomplete/absent profile or incompatible Just me state; stale/same/disallowed subscription status | 409 with a safe operation-specific code, only when the authority commits a classified result. A same-value mode repeat is a side-effect-free 200 readback. |
| Missing or foreign owner subscription ID | Identical 404 `SUBSCRIPTION_NOT_FOUND`, only after successful current authority. |
| Service/storage fault outside authority | Masked 500; unknown commit inside authority reveals no success and remains its generic 401. Client treats uncertain transport/result as unresolved and rereads if the live CSRF survives. |

The current authority catches callback and commit exceptions and collapses them to generic 401. Therefore domain 404/409 cannot be thrown from its callback and then remapped by HTTP. Return a closed discriminated result from the callback, let the authority commit, and map it afterward. A database or parsing fault is never classified as a known domain absence. The profile HTTP handler provides the wire-parsing pattern, but its error catch is not a license to reinterpret authority failures.
