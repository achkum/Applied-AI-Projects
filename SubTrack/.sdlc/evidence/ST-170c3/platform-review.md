# ST170c3 architect-platform review

**Decision: APPROVE — platform scope only.** The internal CSRF core is consistent with ST-170c3 and the accepted ADR-0010/OpenAPI contract at the reviewed source. This approval covers the primitive and its compile-time adapter boundary; it does not establish that any HTTP request, cookie, Origin, TLS connection, or active session is trusted.

## Findings

- **Core binding and rotation — no finding.** `session-csrf.ts:57-69` frames identity and session digest inputs with UTF-8 byte lengths and uses domain-separated SHA-256 digests. `:116-127` mints 32 random bytes and synchronously replaces the binding record before returning the independent base64url token. `:129-145` checks only the current record and does not consume it. The tests cover repeat verification, replacement of the old token, and rejection under changed identity/session (`session-csrf.spec.ts:27-57`).
- **Capacity and atomic store semantics — no finding for the supplied in-memory store.** `session-csrf.ts:85-92` validates copied digest records and the bounded limit before mutation; it permits replacement for an existing binding at capacity and refuses a new binding without evicting an old one. The task’s synchronous `replace` interface documents atomic replace-or-fail (`:20-25`), while the concrete Map implementation performs this synchronously (`:85-92`). The capacity test exercises both behaviors (`session-csrf.spec.ts:75-86`). A future persistent or shared store still needs its own reviewed atomic implementation; the TypeScript interface alone cannot enforce transactionality.
- **Shape, errors, and diagnostic privacy — no finding.** The authority shape is restricted to exactly the two own string properties and each identifier is nonblank and at most 256 characters (`session-csrf.ts:41-55`). Public guard failures collapse to the same generic message, including store exceptions (`:37-39`, `:117-155`). Records, lookups, and snapshots are copied/frozen and expose only validated fixed-length digests (`:71-103`); tests check the snapshot has no raw token or identity/session strings and check the copy/freeze behavior (`session-csrf.spec.ts:27-45`, `:88-104`).
- **Compile-time authority boundary — accepted with explicit adapter caveat.** The unique-symbol brand is module-private and the module exports no authenticating constructor (`session-csrf.ts:3-13`); runtime validation checks shape only and deliberately does not prove authentication (`:5-8`, `:45-50`). TypeScript casts can forge this compile-time type, as the test helper itself demonstrates (`session-csrf.spec.ts:11-20`). This is appropriate for this core, provided future call sites pass authority derived from a currently validated v2 web-cookie session, verify session ownership/current activity, and enforce the accepted transport exclusivity, exact Origin, and TLS requirements. Request selectors must never create this authority. No such adapter or HTTP trust behavior was inspected or approved here.

- `packages/contracts/openapi.yaml`: session and refresh sections describe the distinct web CSRF token; unsafe web routes require `X-Session-CSRF`; session-list/revocation descriptions require server-derived active v2 identity/session and exact Origin where applicable.
