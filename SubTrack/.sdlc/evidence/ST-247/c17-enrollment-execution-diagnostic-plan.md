# C18 proposed enrollment child-execution diagnostic

Status: **plan only**. PR291 Android run 38485301984/job 115597376213 failed in `flow-enroll-add` with `unclassified` and `unknown-tool-diagnostic`; the current run did not establish a save row count. iOS is independent. This note does not alter any flow, timeout, acceptance assertion, or proof result.

The current `run()` in `apps/mobile/scripts/private-runtime-device.mjs` writes the exact child log privately and rejects with the same generic message for every nonzero Maestro exit. Its `exit` handler discards the signal, and its `error` handler discards launch context. `enrollmentToolDiagnostic()` then sees only the private child/Metro text; when its fixed patterns miss, it withholds `unknown-tool-diagnostic`. Thus the public failure cannot distinguish a failed assertion from a child process failure or an empty log.

Proposed narrow change: for the existing `enroll-add` invocation only, retain a RAM record from the child events with a fixed, closed execution result: `launch-error`, `exit-nonzero`, `signal`, or `completed`. Record a bounded exit-code bucket (`zero`, `one`, `other-nonzero`, `unavailable`) and signal bucket (`none`, `TERM`, `KILL`, `other`) from Node's event parameters; do not print the raw error, command, arguments, environment, path, PID, or full numeric code. An explicit `timeout` bucket may be `not-applicable` for this direct `spawn('maestro')` path; do not infer a timeout from a 30-second Maestro wait or add a new deadline. Record the existing fixed `enroll-add.log` as `empty`, `nonempty`, or `unavailable` using a bounded stat/read result, without exposing bytes or a log excerpt. Emit this one fixed record only under `currentPhase==='flow-enroll-add'` and only on failure. Keep all raw output and screenshots in owned private TEMP.

Extend the existing trusted enrollment target roster only for steps already present in `private-runtime-enroll-add.yaml` but absent from its diagnostic labels: `date-field` from `MAESTRO_DATE`, `personal-title` from `MAESTRO_PERSONAL_TITLE`, `saved-row` from the fixed literal `Native restart proof`, and `expected-amount` from `MAESTRO_EXPECTED_AMOUNT`. The last two are emitted solely as fixed enum names, never their literal/value. This permits an actual failed line that names one of those targets to be classified; when no failed line matches, retain `unknown-tool-diagnostic`. Do not guess a failing target from the YAML sequence or classify a successful line. Keep ANSI stripping, input bounds, longest-label matching, and privacy canary checks.

Smallest paths: `apps/mobile/scripts/private-runtime-device.mjs`, `private-runtime-identifier-diagnostic.mjs`, and their existing focused diagnostic tests (plus this evidence note). Tests should cover exit 1/other nonzero, signal, spawn error, empty/unavailable log, no false timeout claim, each newly trusted target on a FAILED line, and rejection of arbitrary private strings. No changes to `private-runtime-enroll-add.yaml`, OTP handling, save probes, bank flow, workflow waits, receipts, or accepted screenshots. Implementation and next CI dispatch require independent privacy source review.
