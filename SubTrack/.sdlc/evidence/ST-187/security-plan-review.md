## Capacity decision

Approve the proposed `maxConsumed` policy for the in-memory development/test reference: when the active target hash cannot be retained because it collides with a retained consumed hash or the unexpired consumed store is at its configured bound, return the exact frozen `{ kind: 'capacity' }` result before changing either the target record or any tombstone. Do not evict, overwrite, or shorten retention of prior tombstones. Prune only entries whose original `expiresAt` has passed according to a validated trusted clock; a hash collision remains a capacity failure even if the count is below the bound. This preserves the existing replay evidence and prevents a revoked credential hash from becoming eligible for a new session during its original lifetime.

This policy deliberately permits revocation to fail under resource pressure. Callers and any future adapter must not represent `capacity` as successful logout/revocation. This approval establishes no HTTP mapping, retry promise, durable-store policy, production readiness, or change to the accepted refresh lifetime or resource limits. Any durable implementation needs a separately reviewed retention/capacity design before it can claim equivalent guarantees.

## Required implementation properties

- Extend the same in-memory repository with current-session-scoped revocation. Validate canonical UUID request and target IDs, exact own-context shape and active owner, and safe bounded `observedAt` against trusted time before any pruning or mutation. Validate stored timestamps before pruning.
- In one synchronous atomic section, confirm the requesting session still exists, is active, belongs to the context owner, and is live at trusted time; require its creation time to be no later than `observedAt`. Recheck this at mutation time. If the request session is absent, expired, revoked, or its owner is deleted, fail closed. Allow self-revocation when target equals request session.
- Require a live target owned by the same active owner. Missing, foreign, expired, and otherwise unavailable targets must have the same result so the method does not create an ownership oracle. No target lookup or mutation may occur for malformed inputs or invalid request sessions.
- Retain the target's current refresh hash as a consumed tombstone carrying the original owner, session, family, creation/expiry, and transport binding fields, then delete only that target session record. Preserve every pre-existing tombstone. Existing consumed-hash reuse behavior must continue to revoke only the matching family after proper transport binding. New session creation must continue rejecting the retained target hash until trusted expiry pruning removes it.
- Keep the interface internal to the development/test reference. Add no route, controller, CSRF/idempotency behavior, database/provider/schema/dependency change, or public success claim. Do not log credentials or hashes.

## Review evidence required before merge

Use real issuer/refresh/resolver/listing flows against the shared repository and verify: current owned target revocation invalidates its access resolution and refresh while removing it from listing; self-revocation; neighboring owned sessions/families remain listable and usable; another owner's state is unchanged; missing and foreign targets are indistinguishable; request-session deletion/reuse/expiry is rechecked; capacity and collision failures preserve the target and every existing tombstone; trusted expiry pruning reclaims only expired tombstones; the revoked hash cannot be re-created before its original expiry; and returned result values are exact, frozen, and contain no metadata. Include malformed/accessor/symbol/extra-field inputs without invoking getters or mutating state. Preserve independent source review, secret scanning, declared QA, and exact-head CI gates.
