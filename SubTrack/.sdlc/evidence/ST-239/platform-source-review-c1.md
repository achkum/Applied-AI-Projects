## Verdict: BLOCK source approval pending two bounded corrections

1. **MAJOR — request digest omits required browser authority fields.** `durable-development-login.ts` `witness()` sets `requestH=this.h('request',operation,parts)` at line 158. The callers supply only `[choice]` for verification and `[loginProof]` for session exchange. The frozen platform-readiness final addendum requires the keyed request digest itself to include operation, strict body, browser chain, nonce and cookie binding. `authorityH` and SQL scope separately carry some of these fields, and the global idempotency burn mitigates direct replay; this is therefore a source-freeze divergence, not a proven bypass. Include the canonical `nonceH`, `bindingH`, and resolved `chain` in `requestH`, and test the digest changes when each changes. No SQL signature change is needed.

2. **MINOR — launcher returns an enrollment problem code for invalid login methods.** `private-https-server.mjs` lines 851–855 uses `privateProblem` from the enrollment HTTP module for a wrong method on `/v2/auth/session` or `/v2/auth/login/simulator/verify`, yielding `400 INVALID_ENROLLMENT_REQUEST`. The frozen private login wire/OpenAPI names `400 INVALID_LOGIN_REQUEST`. Route these login method failures through the login problem mapping and add a launcher-level negative test. This does not affect valid POST routing or commit semantics.

## Boundaries inspected without a new static blocker

SQL012 is additive to SQL001–011 and defines exactly the six frozen function names and caller grants. `issue_login` locks epoch, owned burn and original session nonce before the live identity row; `login_material`/`consume_login` lock the successor nonce and proof and recheck the stored live subject. The Type 2a executor `UPDATE(id)` grant is paired with both owner GUCs in the `FOR UPDATE` policy and `WITH CHECK(false)`; no producer/runtime proof-table grant or login-role executor membership appears. The terminal SQL transaction inserts family, session, credential and current CSRF, deletes proof and nonce, and completes the owned burn. The proof FK uses `ON DELETE CASCADE`; proof expiry is no later than its original nonce, so expired nonce pruning cannot evict a live proof. Actual PG16 must still prove the row-lock/RLS behavior, FK cascade, privilege denials, concurrency and complete catalog projection.

The API uses a closed trusted Alice/Bob simulator result, domain-separated subject digest and provisioner-only candidate lookup, then SQL's independent owner/subject check. Its transaction helper releases credentials only after a reported COMMIT and clean role/GUC reset; an uncertain COMMIT does not replay or compensate and discards its connection. Private HTTP requires exact Origin and fresh binding/nonce, parses closed bodies and headers, treats old session cookies as inert on the three specified pre-auth login steps, and writes cookies/CSRF only after the durable call returns.
