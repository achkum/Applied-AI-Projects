## Classification and authority boundary

**Owner-only private manual add/edit is a Type 2a contract/schema decision**, provided it uses the current verified owner, existing `subtrack_runtime` owner RLS, private loopback HTTPS, and does not expose the route in the default/public graph. F4.5 already authorizes manual entries. A new receipt table and revision column, if chosen, are additive architecture changes for architect/platform review and independent security review. No present evidence requires a Type 1 founder decision. A concrete expansion to another owner's read/write access, sharing, real provider, production/public exposure, or a security-model bypass would be Type 1 and must be classified on that exact delta. The blocked ST-081 does not become DONE: create a dependency-safe private owner child of ST-086, or resolve the specific dependency in the task contract, before source GO.

`private-https-server.mjs` currently pins SQL001–012 and a closed route inventory. Its `PrivateOnboardingHttp` checks exact Origin `https://localhost:3443`, raw wire/cookie shape, access/binding/chain and current CSRF through `DurableCurrentWebAuthority.withCurrentWebAuthority`. That authority verifies the live owner, token/current session and CSRF inside a transaction, checks the authority again before commit, sets both owner GUCs locally, and rejects uncertain COMMIT without releasing a result. Manual writes should join this path with server-owned fixed named statements and the same independently read `profile_complete=true` plus `onboarding_mode='just-me'` gate **inside the mutation transaction**. Do not use the earlier separate Nest lifecycle graph as a substitute for ST-239's current private authority. No browser owner/household/session selector, asserted provider identity, or read-only projection may supply write authority. Preserve exact Origin, TLS, no bearer/refresh fallback, cookie chain/binding, CSRF, deleted/revoked/expired session behavior, pool reset and default-route absence. POST needs one bounded `Idempotency-Key`; reject duplicates/mixed/unknown fields and headers, ambiguous JSON, query strings and transfer encodings under the same strict private wire discipline.

## Storage facts and needed freeze

`subscription` has `source=MANUAL`, `custom_name varchar(120)`, taxonomy category, cadence enum, bigint minor amount, currency char(3), optional date, status, `always_private` and `updated_at`. Migration 0002 grants `subtrack_runtime` full SELECT/INSERT/UPDATE/DELETE on this table, and owner-GUC `subscription_insert`/`subscription_update` policies; SQL011 applies FORCE RLS. Those privileges are broad relative to the proposed manual writer, though not a new grant. The launcher currently pins subscription RLS/ACL and a fixed statement catalog. New code must narrow its **application** write projection to owner `source=MANUAL`, immutable `identity_id`, `source`, `always_private`, linked merchant/account/plan, charge/review fields and approved editable columns. If storage ACL is narrowed, prove existing status/read flows still work and pin the exact resulting grant roster. Do not edit SQL001–012; any table/revision/privilege change goes in one additive qualified migration, with schema, catalog, launcher hash/startup and negative privilege proof. No new executor/producer membership or SECURITY DEFINER write shortcut is justified.

Recommend a durable owner-bound mutation receipt table with a unique keyed digest of the client key, operation, owner ID, canonical request digest, committed result ID and immutable response/revision snapshot. The receipt and subscription insert/update must commit in **one** transaction. A repeated key under a fresh current web authority returns the exact committed result only when owner, operation and request digest match; any mismatch is a stable conflict without disclosure. Concurrent same-key calls serialize at the unique constraint. Retain receipts for the lifetime needed to prevent duplicate create after a lost response; a short expiring burn alone cannot provide this guarantee. Define cleanup on owner deletion without leaking PII or raw keys. Unknown commit returns no success and the client retains the same key/request for recovery; never create with a new key or blind retry. A safe read/reconcile alternative is only acceptable if it can unambiguously identify a possibly committed new row, including same-name entries; the current owner list cannot.

For edits, freeze an explicit revision precondition. A monotonic bigint revision is preferable to `updated_at` alone because timestamp resolution may permit a same-tick write. All manual-field edits and existing legal status updates must advance the revision if it is the stale-edit token; otherwise the two routes can miss each other's changes. Revision mismatch is 409; absent/foreign/non-MANUAL target is the same 404. The receipt snapshot distinguishes replay from a later update. Server ID generated in the transaction. Successful create returns 201, edit 200, only after known commit; exact response/problem codes and replay status need contract review.

## Input and disclosure boundary

Freeze a closed create/edit body: bounded nonblank custom name, approved taxonomy code, fixed cadence (`WEEKLY`, `MONTHLY`, `QUARTERLY`, `SEMIANNUAL`, `ANNUAL`; `CUSTOM` needs its own semantics), positive canonical base-10 integer string within signed bigint range, currency exactly `SEK`, optional true ISO calendar date for expected next charge. Validate with money helpers/BigInt, never floating conversion or locale-formatted price on the wire. Set `source=MANUAL`, `status=ACTIVE`, `always_private=true`; do not set merchant/plan/account, charge or detection evidence. The read model must label the entry as manual and treat `nextChargeDate` as an expectation, not a paid charge. The existing owner projection lacks `source` and `updatedAt`/revision, so contract/read projection changes are part of this slice. A UI-only label inferred from null merchant is insufficient.

Return identical 404 for missing, foreign and nonmanual edit IDs; do not reveal row existence through receipt conflicts, timing-sensitive diagnostics, logs or count differences. Malformed input 400, absent/invalid authority 401 or 403 per current private policy, missing profile/mode 409 with no mutation, stale revision/key mismatch 409, masked storage 500. Confirm 400/401/403 split against the frozen private route contract. No raw name, account, key, token, CSRF, subject or money payload in logs/evidence.
