# Android signing recovery source preparation

The original Linux signer memory floor, all original signing modes, StageApk and the independent Ubuntu signature/manifest/Hermes/16KiB-alignment verifier are unchanged. The last delivered app remains V6. The old retained V7 source is superseded and must not be returned as the corrected product. No original backup, password or private key has been read during this preparation; no remote operation has been reserved, no history has advanced and no app has been signed or published by this new path.

The reviewed recovery source uses the exact original remote mutex, durable exclusive reservations and a capability sent only over private stdin. An immutable single-attempt claim precedes original-key access. Original certificate/backup bindings, source bytes, manifests, configuration/Hermes and prior published/per-run history are rechecked. Distinct signerExecutionHead preserves the original retained tools-reuse proof; executionHead identifies the new recovery source. There is no stale/TTL/process-exit unlock. Interrupted writes retain the mutex. Finalization needs the actual successful independent Ubuntu verifier, exact returned assets and confirmed local cleanup before canonical per-run/global history advances and the owned lock is released.

The desktop GitHub observer explicitly uses a source-bound trusted operator observation, not a GitHub-signed attestation. It authenticates the exact repository, workflow, event/ref/head, run/attempt/job, original dispatch/source/certificate and actual cleanup receipt. The actual REST job shape has labels, not runner_environment; the implementation binds ubuntu-24.04. Every real GitHub API command pins github.com and rejects a foreign GH_HOST. Draft upload checks include unpublished releases and exclusive local return claims before any POST, so a partial upload is retained instead of silently creating a second candidate. Only the original two private draft assets are uploaded; no production/store/public release is authorized.

Windows source verifies the whole public JDK file portfolio and original apksigner JAR, restricts inherited runtime overrides, uses current-user plus SYSTEM private custody, bounded process pipes/deadlines and password-file arguments. Source and original decoder/certificate are checked before original-key access. The public qualification branch uses only a fresh disposable RSA3072 key and synthetic APK fixture, then requires actual signature verification and secret-custody removal before writing its separate qualification. It cannot qualify the original signer or claim Linux alignment. Mutable buffers are cleared on exit; this is not a physical memory-erasure claim.

Independent reviews of the Node protocol/observer and PowerShell source resolved executable selection, local execution-source binding, draft retry behavior and GitHub host authority. The combined portable Node/policy collection passes19 tests; final Windows source/runtime coverage passes7 tests. These tests exercise synthetic objects and disposable subprocesses, not live signer custody. Actual public-tool qualification initially failed at SIGN; the first wrapper suppressed its category. A reviewed closed classifier then identifies KEYSTORE. Android's [PasswordRetriever](https://android.googlesource.com/platform/tools/apksig/+/refs/heads/main/src/apksigner/java/com/android/apksigner/PasswordRetriever.java) caches a canonical file stream and consumes successive lines, while [SignerParams](https://android.googlesource.com/platform/tools/apksig/+/refs/heads/main/src/apksigner/java/com/android/apksigner/SignerParams.java) reuses the store password if a separate key password is omitted. Passing the same one-line file for both options caused EOF. Removing the redundant key-password option matches the untouched original signer. Actual disposable signing, v2/single-certificate verification and temporary-custody removal now PASS. Only the845byte public qualification remains, SHA256 fed43f2175a04a1af3dcb6c8dad9c9a288ea668125079248613095705d90c12a; public portfolio SHA2567395225586e304cb5dd39e77c55c04c9b4039c372effa5226f28f856f09edd32. Original signer access and Linux alignment remain unperformed. No real-key retry is permitted.

Fresh read-only server memory observation after this source work reports MemAvailable1093736KiB, below the unchanged1310720KiB original signer floor. No service was stopped or memory/resource limit weakened. The local recovery path therefore remains useful; public qualification is not permission to sign a superseded APK or skip the independent Ubuntu verifier.

Operational order remains: complete source/test/security review; qualify public tools with a disposable key; obtain the corrected reviewed source's genuine unsigned successor artifact; authenticate original transfer/tool/source bindings; stage only the finite reviewed files; inspect and reserve the original remote mutex; claim one local signing attempt; restore only the original CurrentUser DPAPI backup and sign once; verify and remove owned temporary secrets; return exactly two assets to a new private draft; run the unchanged Ubuntu verifier; observe its authentic successful receipt; advance canonical history and release only the exact owned lock. Any uncertain step retains evidence and blocks the next dependent step. Apple account setup is unrelated and remains deferred until iOS signing is ready.
