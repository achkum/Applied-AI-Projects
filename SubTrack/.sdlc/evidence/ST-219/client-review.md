# ST-219 architect-client pre-review (2026-10-10)
Verdict: **APPROVE exact contract source for architect-client**, pending independent security, QA and CI. Runtime/UI remain unavailable.
1. Browser POST must carry JSON `{}` (`Content-Type: application/json`), exact URL UUID, no query, a single `X-Session-CSRF`, ambient `st_v2_access` and distinct binding cookie; no Bearer/refresh, nonce, caller selector or Idempotency-Key.
2. A same-origin HTTPS POST supplies `Origin` through Fetch. JavaScript cannot set `Origin` or `Cookie`; no client code may synthesize either. Server still requires one exact allowlisted raw Origin and direct TLS.
3. Generated Hey API cookie scheme can call `setAuthParams` to append a `Cookie` header if an `auth` callback is supplied. Browser use must leave that callback unset for this operation and set `credentials: 'include'`; OpenAPI security alone cannot express the distinct binding cookie or ensure credentials mode.
4. A required OpenAPI `Origin` parameter generates a required `headers.Origin` property even though browser code cannot set it. This is a known generated SDK limitation: contract and tests must distinguish server wire requirement from browser call construction; do not make a browser caller set that header or weaken server validation.
5. Existing web registration uses manual same-origin `/api/v2/auth/*` fetch with `credentials: 'include'`; current Next rewrite covers only `/api/v2/auth/:path*`, so it does not establish a route or production origin topology for the proposed subscription read. Do not claim UI client readiness.
6. The existing V1 `getSubscription` generated function is `.get`, `V1AccessBearer`, `body?: never`, `query?: never`, response `VisibleSubscription`. New operation needs distinct ID and `.post`, cookie-only security, body `{}`, query `never`, `VisibleSubscription` 200 and bounded problem errors; preserve V1 unchanged.
7. `VisibleSubscription` is a strict owner/peer union, with canonical string minor units and no raw transaction/bank/evidence data. Read POST should reuse this shape, preserve identical missing/foreign 404 and no-store on success/errors.
8. Candidate OpenAPI requires `additionalProperties: false`, `maxProperties: 0`; generated `z.record(z.string(), z.never())` accepts only `{}` and generated TS has `[key: string]: never`. The focused contract test covers null, arrays and selector fields.
