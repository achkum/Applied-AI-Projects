# ST-222 Type 2a proof plan (readiness only; revision 2)
1. Wrapper creates fresh ST-222-labelled PostgreSQL 16 tmpfs, sole `127.0.0.1::5432`, canonical migrations, `fixture_owner`, and LOGIN `st221_runtime` with only `subtrack_runtime` membership; no inherited `DATABASE_URL`.
2. Before migration/Prisma/listen it records exact CID, nonce label, creation time and full credential-bearing runtime URL in new owner-only 0700 non-symlink directory/0600 record; only that recorded CID/resource can be cleaned.
3. Compiled child first checks record owner/modes/age, live CID/image/label/tmpfs/sole loopback binding and exact full URL with database/role/password/options, rejecting all mismatches before Prisma/listen.
4. Child constructs one ordinary Prisma pool, passes unchanged ST-221 DB/role/RLS preflight and graph, and uses the same pool for scoped read and both transaction-local GUCs; synthetic fixture rows include registered owner/peer identities, household, consent, merchant, subscriptions and shares.
5. Child alone creates accepted simulator producer, proof store, v2 issuer/access verifier, in-memory session repository/current-principal resolver and session-CSRF guard; those same repository/guard instances are injected into the unchanged ST-221 factory.
6. Fixed owner/peer simulator producer instances resolve only their matching pre-registered synthetic fixture identities; child issues bound web sessions and CSRF, never from browser-supplied identity. This trusted bootstrap is neither enrollment nor login/session HTTP proof.
7. Spawn compiled child with inherited private Node IPC and ignored stdout/stderr; child sends one-use, strictly tagged fixture credential envelopes (access token, binding secret, CSRF, case handle) to parent memory only, never argv, logs, files or a public route.
8. Parent installs only access `st_v2_access` and configured binding `st_v2_binding` as host-only `127.0.0.1`, `Path=/v2`, `Secure`, `HttpOnly`, `SameSite=Lax` via Playwright context before navigation; no refresh cookie is needed; secrets are cleared on teardown.
9. Playwright test context handles ephemeral loopback TLS trust, route-fulfils only HTML GET navigation at `https://127.0.0.1:<port>/`, then page `fetch` sends `{}` with `Content-Type`, `X-Session-CSRF`, `credentials:'include'`; browser emits exact Origin/cookies, while POST is never intercepted or given forbidden headers.
10. Child IPC accepts only fixed case-handle controls with strict message ids: call accepted `revokeForCurrentSession` or advance injected monotonic clock past expiry; subsequent browser POST must deny using current child authority with unchanged cookies.
11. Browser/PG evidence covers owner/peer projection, money strings, identical invisible/missing 404, malformed/query/selector/Origin/mixed-credential/binding/CSRF denials, no writes, rollback and GUC/pool reuse; server records Origin and cookie names/counts only, never values, and browser JS cannot read HttpOnly cookies.
12. Direct Node loopback HTTPS is externally probed; SIGINT/SIGTERM/startup failures close listener and owned pool. Wrapper destroys exact recorded container/TLS/IPC secrets and emits sanitized PASS only after verified cleanup.
13. CI needs Linux Docker, Node 22/corepack/frozen install, PostgreSQL image and pinned Playwright 1.63 via existing `createRequire(packages/ui/package.json)` pattern; install Chromium with `pnpm --filter @subtrack/ui exec playwright install chromium --with-deps`, never silently skip proof, keep >=80% changed-runtime coverage and exact-head gates.
14. If private child authority/IPC/browser custody cannot fit L240 and granted <=1600 own lines, split an owned session/credential harness task before source edits; never widen ST-221 graph, auth core, contract or default app.
