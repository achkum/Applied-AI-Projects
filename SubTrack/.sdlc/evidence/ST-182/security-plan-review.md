# ST-182 Security Preimplementation Review

**Decision: APPROVE** the submitted development/test-only issuer boundary, subject to implementing and testing every condition in `.sdlc/tasks/ST-182.md`.

The design keeps identity proof-derived: `ProofStore.consumeLogin` atomically consumes a transport-bound login proof and returns only its canonical registered identity. The issuer then uses that identity to construct a frozen owner context and relies on `createForActiveIdentity` to atomically require an active identity while inserting the session. This closes the deletion race between proof consumption and session creation, provided the repository performs that check and insertion synchronously in memory with no intervening await (and an eventual durable implementation uses a real transaction/conditional operation).

The issuer must treat malformed proof, invalid proof outcome, collaborator exceptions, false/ambiguous insertion, and token issuance/validation failures as one generic failure. It must not return or log any access/refresh credential on any failure path. After any potentially committed insertion, it must attempt rollback using the exact generated identity/session/family/refresh-hash tuple; rollback must not remove a preexisting or unrelated row. A consumed proof stays burned. These requirements bound any uncertain orphan to the reference record's 24-hour expiry; that lifetime is not approved as production refresh policy.

The outlined collision checks and caps are sufficient for the in-memory reference if they cover duplicate session ID, family ID, and refresh hash, active identity registration, owner scope, record shape/metadata, and capacity after pruning expired records. Constructor/config and caller input snapshots must inspect own property descriptors before reading values, rejecting accessors, symbols, hidden properties, unexpected fields, and nonplain objects. Preserve exact HTTPS origin/browser-chain binding for web and mobile-only optional device names. Keep the repository/API unwired, development-gated, and without any persistence or production readiness claim.

The OpenAPI `SessionRequest` has only the `transport` and `loginProof` fields for web, plus optional `deviceName` for mobile. The internal `transportContext` is therefore an internal trusted seam and must not be presented as a wire contract. The task's returned credential tuple is reference-only and does not revise the distinct web/mobile response shapes in the contract. The 15-minute access token lifetime is independent from the fixed 24-hour development session-record retention.

Required implementation checks include actual simulator-to-proof-store-to-issuer-to-token-verifier web/mobile flows; proof replay and concurrent one-winner behavior; identity deletion before atomic create; malformed/extra/accessor/symbol/hidden input rejection before collaborators; malformed/inactive records, scope, capacity, and collision checks; create/token failures with exact rollback and unrelated-row preservation; rollback failure with no credentials; and absence of raw proof/token retention or logging. The remaining ST170b/c, HTTP idempotency/nonce/CSRF, refresh rotation/reuse, durable storage, and real-provider gates remain separate as the task states.
