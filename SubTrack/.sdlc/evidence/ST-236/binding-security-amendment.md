# ST-236 binding and birth attestation — precise Type 2a
1. SQL010 currently copies the bootstrap `sha256('subtrack:browser-nonce:v2:cookie:'+rawCookie)` into `session.binding_h`; ST-235 requires `hashBrowserBindingCookie(rawCookie)` (session domain plus decoded 32 bytes). The live session is unusable until corrected.
2. At trusted OTP issuance only, service validates canonical raw cookie and passes its accepted session-binding digest as one new `issue_enrollment_otp` argument; SQL stores immutable `otp.session_binding_h` while retaining existing `binding_h` for every nonce/scope check. No caller-supplied terminal digest or new public grant.
3. Carry the stored digest only through the locked OTP→restricted proof→pending→verified chain, with exact predecessor key, origin, chain, bootstrap binding, epoch and source-expiry matches; `issue_enrollment_session` reads the verified value internally. Session/CSRF/current-authority checks use this digest; nonce and burn checks retain bootstrap binding.
4. Issue canonical `v2r.` refresh material and hash its full token with ST-235's refresh domain; retain the existing CSRF digest primitive. Prove signed accepted v2 access through current authority and owner callback, plus same-key fresh-process denial on actual PG16.
5. `xmin` needs system-column SELECT privilege beyond `SELECT(id,external_id,deleted_at)`; remove that read. Preserve the three-column executor grant, owner-dual-GUC SELECT policy, and provisioner INSERT-only privilege.
6. Narrow replacement: private FORCE-RLS transaction intent created only by fixed `terminal_enrollment` after owned pending complete burn, verified/session nonce, epoch/manifest, binding, chain, Origin and fresh expiry rematch; key it to current xid and verified handle, with no caller writer or arbitrary owner selector.
7. A fixed `AFTER INSERT` trigger on `public.identity` records only `(NEW.id,current_xid8)` in a private FORCE-RLS birth table when fired by the qualified login's active provisioner role and matching current-transaction intent whose verified stored subject equals `NEW.external_id`; unqualified INSERT creates no birth row and cannot bind. No generalized identity log.
8. `bind_enrollment_identity` requires exact current xid8 birth row and supplied new UUID, stored verified subject = live `identity.external_id`, `deleted_at IS NULL`, both equal server-derived owner GUCs, and the existing locked terminal burn/nonce/binding/epoch; runtime holds the live identity row lock before its executor plain SELECT. Consume birth row and intent in the same terminal commit before disclosure.
9. Rollback removes intent/birth with identity; success leaves neither. Expiry-only cleanup under fixed epoch/capacity locks removes abandoned rows without retaining erased subject/contact identifiers; prove no sidecar row survives success, rollback or cleanup, and old identity UUID cannot bind.
10. This preserves ADR26–28/D12A as Type 2a only under these exact predicates. Any wider role/grant, caller-supplied session digest, persistent identity log, or old-identity acceptance is a new security delta requiring separate classification; actual PG16 and independent source review remain acceptance gates.
