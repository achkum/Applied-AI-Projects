# ST-236 exact security readiness — conditional Type 2a GO for private implementation
1. ADR26–28/D12 A permit the full private OTP→restricted proof→trusted simulator→verified enrollment→atomic new identity/incomplete profile/session chain. SQL010's fixed, bounded executor lookup of the newly bound identity preserves that model; no concrete Type 1 delta is selected.
2. Mandatory SQL010 amendment: `subtrack_auth_executor` currently has neither `USAGE ON SCHEMA public` nor an `identity` RLS SELECT policy in SQL0002. Add only public-schema USAGE, `SELECT(id,external_id,deleted_at)` and an executor-specific `FOR SELECT USING (true)` policy; no executor identity UPDATE/DELETE/INSERT or other business grant.
3. The executor identity read is confined to `bind_enrollment_identity`: require the locked owned terminal burn, verified/session nonce and immutable stored subject; require `identity.external_id = stored subject`, `deleted_at IS NULL`, server-generated inserted UUID and both equal server-derived owner GUCs. The runtime role locks and rechecks the live identity row first; executor performs a plain SELECT under that lock, without `FOR UPDATE` or arbitrary ID lookup.
4. Keep login SET authority exactly producer/runtime/provisioner, with no executor/owner/fixture membership. Executor functions remain fixed SECURITY DEFINER with qualified references and `search_path=pg_catalog`, exact signature EXECUTE grants, no PUBLIC/default EXECUTE, no direct private table rights for app roles; preserve SQL001–009 and provisioner `SELECT(id,external_id),INSERT` unchanged.
5. Add `public.identity_profile` owner-keyed RLS SELECT/INSERT/UPDATE policies using `subtrack_principal_matches(identity_id)` and runtime-only corresponding grants; no PUBLIC or producer/provisioner/executor profile rights. Identity trusted-name/contact writes use existing runtime owner scope after provisioning and both GUCs; profile defaults are ST-234's incomplete values, without household/consent authority.
6. Independently commit each global operation-specific burn; terminal uses one connection and fixed lock order through provisioner dedup/INSERT, runtime owner row/profile/session writes, verified+nonce consumption and settlement. A failed/uncertain commit reveals no credentials and never replays or compensates account state.
7. Scope of concurrency proof is a disposable qualified PG16 fixture with competing deletion, refresh and legacy identity/session writers demonstrably disabled. Test enabled enrollment races and conflict predicates; do not claim global deletion-race safety until the later shared-lock deletion adaptation is reviewed.
8. Before source GO freeze SQL parameter/output predicates, exact new grants/policies and fixture exclusions in ST-236; prove positive full-service path plus direct-table/PUBLIC/cross-owner/role denial, bound secret/purpose/Origin/chain/epoch/time, rollback/restart/clock/capacity and pool dual-GUC reset on actual PG16. This review is readiness, not implementation or test acceptance.
