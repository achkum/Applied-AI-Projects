# ST-236 C3 SQL010 diagnosis

The actual C3 PG16 run [38132773842](https://github.com/achkum/Applied-AI-Projects/actions/runs/38132773842) failed while applying SQL010 with bounded SQLSTATE `42601`; the enrollment driver did not start. The [independent C3 QA receipt](qa-actual-c3.md) verified all 34 input pins at head `cc6613cdfba54a007219cd0d7c7bcf02e1e8ed1c`. The bounded receipt does not identify the first failing SQL statement or line. C1's earlier migration failure and C2's durable-enrollment failure remain separate history.

SQL010 declared `default_currency pg_catalog.char(3)`. In [PostgreSQL 16 `pg_type.dat`](https://github.com/postgres/postgres/blob/REL_16_STABLE/src/include/catalog/pg_type.dat), `pg_catalog.char` is the internal single-character type OID 18 and has no `typmodin`; `pg_catalog.bpchar` is the length-qualified blank-padded string type OID 1042 and has `bpchartypmodin`. [PostgreSQL 16 `parse_type.c`, lines 338–344](https://github.com/postgres/postgres/blob/REL_16_STABLE/src/backend/parser/parse_type.c#L338-L344) raises `ERRCODE_SYNTAX_ERROR` when a supplied type modifier has no `typmodin`. This gives a deterministic PG16 block for `pg_catalog.char(3)` and is consistent with C3's `42601`. It does **not** prove that this was the first error reached in the actual C3 run.

The narrow correction is `pg_catalog.bpchar(3)`, retaining the `NOT NULL`, `DEFAULT 'SEK'`, `CHECK (default_currency='SEK')`, and rights. The integration catalog assertion checks the stored type and `atttypmod=7`; [PostgreSQL 16 `varchar.c`](https://github.com/postgres/postgres/blob/REL_16_STABLE/src/backend/utils/adt/varchar.c) defines the character typmod as `VARHDRSZ + length`, so length 3 is 7. The existing account graph assertion continues to check the `SEK` default. Actual PG16 execution at the next exact head remains required.
