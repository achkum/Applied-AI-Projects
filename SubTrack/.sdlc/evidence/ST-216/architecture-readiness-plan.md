# ST-216 Type 2a architecture readiness (2026-10-10)
1. Gate: ST-215 PR244 must be accepted on `main`, and independent security/privacy must approve this exact authority, audit, retry, fixture, and cleanup boundary before runtime source edits.
2. Register only an explicitly enabled development composition on numeric `127.0.0.1`; leave `main.ts`, `AppModule`, default routes, and accepted read-only launch unchanged.
3. Private composition factory receives trusted Prisma and V1 public-key verifier from a verified fixture harness; it never promotes environment variables or a caller's database name/role assertion into provenance.
4. Any direct launch first verifies a private, owner-only record against Docker's exact CID, fresh unique `ST-216:<nonce>` label, creation time, running PG16 image, sole tmpfs data mount, and sole numeric-loopback ephemeral port; reject stale/mismatched records before constructing Prisma or listening.
5. The wrapper unsets inherited `DATABASE_URL`, creates a fresh labelled PG16 container, records CID before start, applies full canonical migrations as fixture owner, and creates an ordinary LOGIN, non-superuser, non-BYPASSRLS one-membership runtime role.
6. Verify the runtime URL's role/database/port against that inspected container, without logging credentials; then reuse the accepted read storage preflight and add same-pool UPDATE privilege checks before route activation. Names alone never establish ownership.
7. Register `AuthenticatedPrincipalGuard` with `APP_GUARD`, `PrincipalResolver`, real `PrismaSessionOwnerReader`, read controllers/service, and lifecycle controller/service/private writer in one dedicated Nest graph; no alternate issuer, header, cookie, or scope selector.
8. Guard-provided `getVerifiedRequestContext` is the only identity input. The writer locks the owner row in `withRequestTransaction`, binds both identical transaction-local RLS GUCs, and evaluates the locked status.
9. PATCH parses a UUID path and exact JSON object `{status: ACTIVE|PAUSED|CANCELLED|ARCHIVED}`; reject empty, mixed, extra/prototype-key bodies and any raw URL query string, including keys Express might discard.
10. Target maps deterministically to action: ACTIVE→resume, PAUSED→pause, CANCELLED→cancel, ARCHIVED→archive; private writer admits only ACTIVE→PAUSED/CANCELLED/ARCHIVED, PAUSED→ACTIVE/CANCELLED/ARCHIVED, CANCELLED→ARCHIVED.
11. Return `{id,status}` only. Stable RFC9457 problem projection maps malformed 400, absent/invalid/revoked/wrong-subject session 401, missing and owner-invisible identically 404, disallowed/stale/retry 409, masked storage failure 500.
12. An uncertain committed response can make a retry conflict; clients re-read state. No idempotency receipt, audit event, replay state, retention field, new status, edit/review/undo, or money/privacy-field mutation.
13. Proof uses actual HTTP and the same runtime pool on newly owned PG16: all seven pairs; owner, visible peer/share/open-book and hidden private/outsider; spoof/body/query/prototype attempts; missing/invalid/revoked/wrong-subject tokens; stale/racing conflicts; rollback and pooled GUC cleanup.
14. Wrapper reports sanitized PASS only after verifying container removal and private-temp cleanup; failed or unverifiable cleanup is FAIL, with no credential, token, resource ID, or raw driver logs.
15. Gate focused unit/HTTP tests, ≥80% changed-runtime coverage, API lint/typecheck/full regression, frozen build/container Node22 smoke, dedicated PG proof/CI, and independent platform/security/QA review at exact head.
16. If implementation requires editing accepted auth/read/writer, default launch, schema, or migration files, stop and request a minimal task `allowed_paths` extension and renewed security readiness before that edit.
