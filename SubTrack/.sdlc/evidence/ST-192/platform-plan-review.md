# ST192 platform plan review

**Decision: Type 2a architecture alignment, conditional on the stated gates.** ADR-0010 accepts the additive `/v2/auth/session` contract only; it explicitly keeps runtime work separately reviewed. A new explicitly registered development-only module is a reversible runtime architecture choice, provided it has no AppModule/main/config/provider enablement path. This review does not accept the WIP ST191 interfaces: implementation must wait for ST191 acceptance and bind only to its accepted ports. No production/client-ready or BankID integration claim follows.

**Required constraints.** Fail closed after a redemption attempt: reserve idempotency and terminally consume the session-purpose nonce before proof exchange. Once consumed, that nonce and its reservation remain burned on every later failure; never restore or retry them, and require a fresh verified login and chain. Preserve accepted ProofStore mismatch isolation: wrong-purpose, wrong-transport, foreign-bound, or otherwise nonmatching login proofs remain untouched by consumeLogin. The adapter must not force-burn a foreign/nonmatching proof to satisfy nonce-burn policy. This matches ADR-0010 lost-response semantics. Use generic mappings: malformed request/evidence 400; invalid proof 401; CSRF 403 only if applicable; origin/global throttle 429 with generic `AUTH_RESTART_REQUIRED`; duplicate/unavailable reservation or consumed/replay state 409 `AUTH_RESTART_REQUIRED`; post-commit/internal failures generic 500 without credentials. Preserve accepted problem fields and no-store/no-cache on every response. Reuse the existing 60-per-origin/300-global-per-minute throttle as a development reference policy, documenting its in-memory scope; do not imply distributed production protection.

Derive CSRF mint authority only from the branded authority returned after resolving the newly issued access credential to the current owner and confirming its session id and owner-scoped current row/refresh hash. Caller input, proof claims, or an unverified issuer result cannot mint authority. Cleanup may call exact rollback only with the previously verified owner-scoped row and matching session/family/current refresh hash; never target advanced or foreign rows. Invalidate CSRF only for the same verified authority. If commit identity is unknown, do not guess; retain the bounded issuer orphan expiry. Build and validate the full response and both cookie headers before one publication; never set session cookies on errors.

Require raw-header duplicate rejection and direct TLS socket evidence, canonical allowlisted HTTPS Origin, no forwarded-proto/HTTP fallback, exact body/header allowlists, and no credentials in JSON, logs, or idempotency results. Keep registration module-only and opt-in; no AppModule/main/runtime-config/provider changes. Root owns source, independent security review, actual HTTPS QA, and acceptance gates.
