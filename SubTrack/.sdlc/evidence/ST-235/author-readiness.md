## Exact boundary decisions needed before source GO

- The existing token verifier has only `sub/sid/iat/exp`; there is no signed epoch or key ID claim. Thus epoch is a **server-pinned configuration plus stored row** predicate, not a token claim. `V2AccessToken` receives a key pair but has no durable key-manifest loader. Same-key restart proof requires a private pinned key/manifest fixture and explicit mismatch/retirement startup rejection; do not silently mint a new random key or pretend the current token carries an epoch.
- SQL 001–008 establish `subtrack_auth.epoch`, `subtrack_auth.h/ms`, the qualified login and runtime/producer/provisioner memberships, and `fence` with PG-clock watermark. SQL 009 must source its epoch lock/time check consistently with that established contract; the existing bootstrap port's hardcoded `st233a_development_auth_foundation_proof`, `https://st233a.invalid`, pinned manifest and scoped login are proof-only custody, not a deployable connection factory. No widening of `subtrack_auth_producer`, `subtrack_identity_provisioner`, or a new executor SET membership.
- `DevelopmentV2PrincipalResolver`, `InMemoryV2SessionRepository`, `SessionCsrfGuard`, and `withRequestTransaction` cannot implement this boundary merely by composition: reads/CSRF are process-local or separately transacted, and `withRequestTransaction` sets GUCs without role/lock ownership. The new callback must own the connection, row locks, and business write. Existing v2 session issuer consumes a login proof separately; it is **not** a durable fixture issuance capability. ST-235's issuer is confined to the owned PG proof harness: synthetic fixture-owned seeded identity and same-chain private nonce, no public input/route. A real simulator login producer/verified proof transition is a later prerequisite for private web composition outside that harness.
- Existing `public.identity` runtime RLS permits owner-scoped `SELECT/UPDATE`; checking `deleted_at IS NULL` under lock is feasible after verified `sub`. Current legacy erasure does not share the new locks. The PG proof can test deletion under the protocol, but this slice cannot claim global deletion-race closure until a later durable erasure adapter uses identity-first lock ordering.
- Exact CSRF digest domain/algorithm and refresh credential digest must be frozen from accepted primitives in source; never reuse `SessionCsrfGuard`'s in-memory record as a durable authority or persist raw tokens. Current session token can be replaced only by the reviewed current-session exact-Origin/cookie/CSRF contract in line 9; lost-CSRF reload remains fresh verified login.
- Independent security must explicitly classify the new runtime EXECUTE functions, their private executor table/column grants and predicates as Type 2a or isolate any concrete Type 1 delta. Candidate excludes preprincipal owner lookup, arbitrary fixture identity, historical CSRF, retained erased identifiers, provisioner changes and producer expansion. QA should reject mock-only tests as a readiness substitute.
