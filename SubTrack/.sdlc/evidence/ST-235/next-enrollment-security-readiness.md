# ST-236 security readiness (conditional on ST-235 acceptance)
1. D12 A already selects OTP followed by mandatory trusted development BankID simulator; SQL010's private, bounded persistence and one-chain atomic enrollment are Type 2a implementation of ADR26–28 if the predicates below preserve that authority. Neither fixture-only session issuance nor a SQL object alone proves the requested OTP→account service.
2. Amend ST-236 paths before GO to name the existing web OTP/proof producer, challenge/metadata store, idempotency and nonce/transaction ports actually replaced or adapted; a single new service file cannot make process-local OTP contact recoverable or make existing synchronous ports transaction-bound. Pin ST-229/232/234/235 accepted heads and their web contract; mobile anonymous authority remains separate.
3. SQL010 needs immutable private otp(challenge_h, code_h, identifier_h, channel, normalized contact, web binding, attempts, expiry), restricted proof, pending, verified and session nonce records with source-bounded five-minute lifetimes, capacity and expiry-only pruning; code/secret never stored raw, contact never returned on wire. Fifth bad OTP must exhaust atomically; all operations rematch origin/cookie/chain/purpose/epoch/time under locks.
4. Producer-only typed EXECUTE: issue_otp(web,owned,otp_issue,next_nonce_h), verify_otp(web,owned,challenge_h,code_h,proof_h,next_nonce_h), pending_snapshot(web,pending_h), verify_simulator(web,owned,pending_h,simulated,verified_h,terminal_nonce_h); trusted adapter fixes simulator input after awaited verification and rechecks pending, expiry and pinned epoch. Return status/expiry only; no generic insert, arbitrary purpose or identity argument.
5. Runtime-only typed EXECUTE: admit(web,owned,proof_h,pending_h,next_nonce_h), terminal_material(web,owned,verified_h), consume_terminal(web,owned,verified_h), plus exact enrollment-operation reserve/settle/fence/peek/prune; terminal_material returns stored subject/contact/names solely to the pinned server transaction after full secret, nonce and owned-burn rematch. No caller-supplied owner, digest or material selects a public identity.
6. Grant login SET LOCAL ROLE only to producer/runtime/existing provisioner; never executor/owner or fixture issuer. Give producer/runtime no private table rights, PUBLIC no schema/type/table/function rights, executor only enumerated private columns/lifecycle writes behind fixed SECURITY DEFINER functions; preserve provisioner SELECT(id,external_id)/INSERT and runtime owner-RLS profile/session writes with both server-derived GUCs. Prove PG16 role membership, default EXECUTE, direct-table and cross-owner denials.
7. Independently commit globally unique reservation burn; on one connection lock epoch→owned burn→verified/session nonce→subject/contact digests→identity, switch locally provisioner for dedup/INSERT then runtime for active-owner/contact/names/profile/family/session/refresh/CSRF, consume and settle before COMMIT. Unique external_id/contact arbitrate races; disclose credentials only after known commit; rollback leaves burn spent and all new graph/account/session effects absent.
8. Before terminal implementation, reconcile shared subject/contact lock ordering with authorized deletion: the proposal explicitly defers deletion adaptation yet promises concurrent deletion-race proof. Either include exact deletion port/path and its lock/revalidation in ST-236 or scope the runnable service to an environment where that competing writer is disabled and state this limit; do not claim deletion race safety from uniqueness alone.
9. Exact Type 1 delta would be historical/predecessor CSRF acceptance, retention of erased subject/contact digests, re-linking or resurrection, OTP-only login, caller-selected owner, generic fixture issuance, or added provisioner UPDATE/DELETE/contact SELECT or broad executor/business-table access. None is required for this slice. A proposed new predicate/grant with such effect needs its own before→after founder decision; D12 A is not blanket approval.
10. Conditional GO requires revised exact owned paths, changed-line exception and actual PG16 proof of end-to-end producer→terminal service, wrong-purpose/binding/epoch/secret denials, wrong-code attempt race, duplicate/subject/contact/deletion races within chosen scope, role/GUC reset, rollback and uncertain commit, restart/key/clock/capacity failure. No default HTTP, production, real delivery or usable-account claim follows from this private service.
