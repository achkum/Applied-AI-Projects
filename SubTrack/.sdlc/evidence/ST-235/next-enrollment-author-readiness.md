## Typed private TypeScript surface and transitions

`type Web = Readonly<{origin:string;bindingCookie:string;nonce:string;chainId:string;epoch:string}>`; the constructor takes a copied/frozen pinned manifest, key set (all ≥32 bytes), qualified login `Pool`, checked clock, and `DevelopmentEnrollmentPersonVerifier`. Inputs are exact data objects, no `PoolClient`, SQL, callback, operation registry or owner UUID from callers. `startOtp(web,{identifier,channel:'email'|'sms',purpose:'enroll_identifier'},key): Promise<{challengeId,expiresAt,nextBrowserNonce}>`; `verifyOtp(web,{challengeId,code},key): Promise<{proof,nextBrowserNonce}>`; `admit(web,{proof},key): Promise<{pending,nextBrowserNonce}>`; `verifyPerson(web,{pending},key): Promise<{verified,nextBrowserNonce}>`; `complete(web,{verified},key,privateLocaleHint?:string): Promise<{identityId,sessionId,refreshToken,csrfToken,profile:ProfileView}>`. Only `complete` returns the new server-generated identity/session IDs and credentials, after known commit. Add `public.identity.verified_at/given_name/surname` and owner-RLS `public.identity_profile` keyed by identity UUID, with runtime-only `SELECT,INSERT,UPDATE` and no PUBLIC rights. `privateLocaleHint` is never stored/logged; profile defaults come from accepted `projectInitialProfile`: `displayName:null`, avatar token/emoji null, explicit `sv|en` or sv-prefix hint else `en`, `theme:'system'`, `defaultCurrency:'SEK'`, `profileComplete:false`. Trusted given/surname/verified-at live on identity, separate from user-editable profile display name. No Just me/household/consent row.

Every operation reserves an operation-specific global burn, then uses a single checked connection/transaction for its nonce and state transition. OTP challenge is `(challenge_h,code_h,identifier_h,channel,contact,origin,binding_h,chain,epoch,issued_ms,expires_ms,attempts)`; restricted proof binds challenge and purpose; pending binds consumed proof; verified binds pending and trusted simulator fields; terminal session nonce binds verified and original chain. Each state ≤10,000, max 300,000 ms and never extends source expiry. Code/handles/reusable credentials stored as digests only. Contact is copied from original trusted OTP issue, never reconstructed from a client payload at terminal. Terminal checks all current records again after every await/lock wait. Sorted subject/contact advisory keys arbitrate concurrent enrollments; a missing shared deletion writer is explicitly outside the qualified environment.

`AUTH_RESTART_REQUIRED` is the generic external failure for malformed/expired/wrong-binding/subject-contact conflicts, capacity, database, clock and unknown commit; no material or owner inference. `ENROLLMENT_LOGIN_REQUIRED` is permitted only for an already active matching verified subject. Wrong code can return only remaining attempts 4–1; fifth and all exhausted states return generic terminal failure. Duplicate idempotency key returns generic 409 regardless of pending/completed/failed state, never prior credentials. A known rollback may mark only its owned burn failed; an uncertain commit returns no credentials and performs no retry, compensation or result replay.
