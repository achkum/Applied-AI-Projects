# ST-235 C1 adapter correction checkpoint

The frozen security review found that callback-owned SQL text could call a quoted `pg_catalog."set_config"`, change both owner GUCs temporarily, read another owner through ordinary RLS, then restore the signed owner before the final checker. `OwnerTx.query(sql, values)` has been removed. The callback now receives only `execute(operationName, values)` against constructor-copied, immutable, named statements supplied by trusted server composition. It receives no SQL text, registry, client, or registration function. Unknown operation names fail closed; values are passed as PostgreSQL parameters. The statement source must be audited literals at composition, never request data. Constructor token checks are defense in depth, not proof that arbitrary caller-provided SQL is safe. The existing private checker still runs after the callback and before commit, and escaped capabilities reject use after callback return.

The fixture now locks and validates the pinned epoch on its issuance connection and transaction before locking the synthetic identity and nonce. The private issuer still validates epoch, nonce, time, and capacity after any wait. This aligns its epoch-before-identity order with the runtime adapter without changing SQL 009 or grants.
