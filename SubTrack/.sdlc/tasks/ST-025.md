## Goal
Implement Orbit (home-page hero subscription visualization) as an interactive SVG/Canvas component with accessible list fallback, matching Norrsken motion language and full keyboard/screen-reader support.

## Context (read before starting)
- docs/product/DESIGN_DIRECTION.md §4 (Orbit component) + §3 (motion: spring damping 18, stiffness 180, slow rotation 1 rev/4 min)
- docs/governance/QUALITY_GATES.md (accessibility, visual regression, reduced-motion)
- ST-023 component specifications (once DONE)
- `packages/ui-tokens`: category colors (22-step OKLCH wheel), aurora gradient, reduced-motion token

## Acceptance criteria
- AC1: **Orbit visual**: Subscription bodies render as circles in concentric rings (Me / Shared / Member), sized by monthly cost (minor units), positioned by billing cadence orbit radius (monthly close, annual far); aurora gradient bg only on hero (never behind text); grain texture at 2% opacity (off on low-end Android); slow rotation 1 revolution per 4 minutes using CSS/Framer Motion
- AC2: **Interactivity**: Tap/click a body → shared-element transition to detail view; long-press → quick-split modal; selection persists if user navigates away; reduced-motion disables transitions and rotation
- AC3: **Accessible fallback**: "View as list" toggle shows semantic HTML list (role="region", aria-label="Subscriptions as list", each item with category badge, price, owner); screen readers announce list mode default; focus order verified via testing-library/keyboard-nav unit tests. VoiceOver device session deferred to ST-039 — not achievable by an agent, not blocking.
- AC4: **Reduced-motion**: prefers-reduced-motion:reduce freezes rotation, removes all transitions (instant state changes), shows list view by default; CSS var `--motion-disable` set via theme token
- AC5: **Rendering**: SVG or Canvas (performance decision, must benchmark); Storybook story (in `packages/ui`, via ST-022) with interactive controls (light/dark, empty/populated, reduced-motion toggle). Cross-browser (Chrome/Firefox/Safari) matrix deferred to ST-017/ST-039 — not blocking.
- AC6: **Mobile responsive**: Orbit layout adapts to breakpoints per DESIGN_DIRECTION §6; detail transition works on touch devices
- AC7: **Test coverage**: vitest unit for orbit calculations (radii, angles, sizing logic) and interaction logic (tap/long-press/keyboard handlers, tested via testing-library, not real Playwright E2E); `jest-axe`/vitest-axe unit-level a11y audit passes. Playwright E2E and pixel-level visual-regression snapshot deferred to ST-017 — not blocking this task.
- AC8: i18n: subscription labels and list headings use @next-intl keys; parity check passes

## Out of scope
- Dashboard API and actual subscription data (use mock fixtures; real API awaits ST-082)
- Hero screens (ST-028)
- Performance optimization beyond initial implementation (profiling is QA scope)

## Technical notes
- Orbit rendering: prefer Canvas if motion performance is critical; SVG if simplicity matters. Document decision and benchmark in PR.
- Shared-element transition: use Framer Motion's layoutId or Remix/Next shared layout route pattern
- Long-press detection: pointer events with 400ms threshold (standard mobile UX)
- Rotation: CSS animation or Framer Motion spring; must respect reduced-motion
- Do not edit CI workflows; visual regression test wiring is ST-017 scope
- Per ADR-0009 (component placement): Orbit lives in `packages/ui` (`@subtrack/ui`) first, with tests/Storybook, before `apps/web` integration — same principle as ST-024's signature components. `apps/web` consumes it via `"@subtrack/ui": "workspace:*"`.
