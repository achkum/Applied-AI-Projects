## Acceptance
Opaque compile-time branded VerifiedWebSessionAuthority contains server-derived identityId/sessionId only; private brand, no exported factory/assertion that authenticates caller. Validate runtime shape strictly bounded nonblank strings (maximum256 characters); brand is not authentication. Future reviewed adapters must verify current active web-cookie v2 session and owner, exclusive transport, Origin/TLS etc; request selectors cannot establish trust.
Independent random256-bit base64url token, strict43char token syntax; domain-separated hashed binding and token storage only. Length-framed identity/session hashing prevents ambiguous bindings. Atomic mint/reissue replaces previous token for binding; verify current token without consuming it. Wrong identity/session, malformed/unknown/stale token and store failures yield fresh generic secret-free Error. Timing-safe fixed-length digest compare.
Semantic synchronous store boundary, in-memory boundedcapacity default10000 valid1..10000, frozen copied records/snapshots, no raw identity/session/token diagnostic data. Reissue samebinding works atcapacity; newbinding fails without losing existingrecords. Explicit sameauthority invalidation/cleanup allowed for future session lifecycle; no invented expiry, active-session checks and lifecycle revocation remain future adapter responsibilities.
