## Goal and accepted context

Both signature components are locale-agnostic and receive translated user-facing button text from their host. Their outer accessible groups currently use hardcoded labels: ScopeSwitcher uses `aria-label="Scope"`; RollingNumber uses `aria-label="Period"`. Add optional host props so an app/Storybook can supply a locale-appropriate group name without adding catalog imports or framework dependencies to component source.

Read ST-024 AC1–AC5, `docs/design/components/scope-switcher.md`, `docs/design/components/rolling-total.md`, and the Constitution. ST-024 explicitly requires `role="group"` with an accessible name; the ScopeSwitcher spec requires keyboard operation and accessible names. Rolling total spec requires a coherent accessible value and localized period content.

## Explicit semantic boundary

Preserve `role="group"` on each container and the current child roles/interaction. ScopeSwitcher currently uses native buttons with `role="radio"` inside a `role="group"`; it supports native Tab/Enter/Space activation but does not implement arrow-key radio-group navigation. Existing ST-024/spec language says group plus accessible label, so this localization task must not silently change to `radiogroup` or add roving focus/arrow-key semantics. Axe's ARIA role metadata requires `aria-checked` for `radio`; it does not require a `radiogroup` parent, so this exact role combination is not by itself an axe `aria-required-parent` failure. Axe does not test APG arrow-key interaction. Record the remaining choice between a true radio group with roving focus/arrows and a button group with pressed state as a separate architect-client/accessibility follow-up. Do not claim this label task fixes that behavior.
