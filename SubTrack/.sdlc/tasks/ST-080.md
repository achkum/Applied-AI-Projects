## Goal
Implement a pure deterministic TypeScript recurring-detection engine in `@subtrack/domain/detection` and a repeatable evaluation harness against the synthetic ground truth. Given transaction series with stable merchant identity, the engine reports recurring candidates with cadence, amount band, confidence, and human-readable reason identifiers. No API, storage, schema, provider, ML-service, or network integration is part of this task.

## Context (read before starting)
- PRODUCT_SPEC §F5.1–F5.7; specifically F5.3 cadence, amount band, day-of-month stability, occurrence count, category priors, confidence and reasons
- AI_ML_SPEC §0, §2 (rules run first; model is outside this task)
- SYNTHETIC_DATA_SPEC §1–3 and the ST-063 persona fixture contract
- DATA_MODEL.md, “Catalogue & detection”
- ADR-0002 and ADR-0005
- ST-068 exports deterministic exact merchant matching; it does not decide recurrence.
- `PersonaSubscription` fixtures label positive truth only and currently cover MONTHLY and ANNUAL cadence. The evaluation harness must use those labels without changing the fixture contract and add explicit test-only negative examples based on the non-subscription cases already named in SYNTHETIC_DATA_SPEC §3.
- The engine may depend on `@subtrack/money` for amount comparisons. Transaction amount arithmetic must use integer minor units/BigInt through `packages/money`; do not use floating-point money calculations.

## Pre-implementation architecture review (required)
- Before implementation starts, architect-data reviews and records a concise algorithm note in this task under Progress: candidate-series boundary, supported cadence/timing tolerance, amount-band method, category-prior treatment, confidence/reason representation, and evaluation-case construction.
- The review must confirm these choices remain within PRODUCT_SPEC/AI_ML_SPEC and do not require a new package, runtime service, data model, API, or architectural decision.
- If the specifications conflict or the reviewer believes a cross-cutting change is needed, stop and return BLOCKED for Conductor resolution under DECISION_RULES §4. Do not implement against a silent assumption.

## Acceptance criteria
- AC1: `@subtrack/domain/detection` exports typed, pure functions that accept deterministically grouped transaction series with stable merchant identity and return zero or more recurring candidates. The series boundary and handling of unresolved merchant identity are documented in the reviewed algorithm note.
- AC2: The engine supports the PRODUCT_SPEC §F5.3 cadence set: WEEKLY, MONTHLY, QUARTERLY, SEMIANNUAL, and ANNUAL. It uses occurrence count and observed date/day-of-month stability and returns no detection when evidence does not meet the reviewed deterministic rules.
- AC3: Amount-band comparisons respect currency and use only integer minor units/BigInt through `packages/money`; the engine never converts money to floating point and never combines unlike currencies.
- AC4: Each returned detection contains stable merchant identity, cadence, a deterministic amount band/representative amount, confidence in the inclusive range [0, 1], and stable human-readable reason identifiers (with any numeric parameters needed by clients). Results and reason ordering are stable for identical inputs.
- AC5: The rule-based detector applies merchant/category priors only as allowed by the reviewed algorithm note; it makes no ML/LLM calls and does not classify unknown merchants as a known merchant.
- AC6: The domain unit suite covers each supported cadence, insufficient occurrences, month-end/day drift and calendar boundaries, amount changes within/outside the reviewed band, currency separation, pending/credit/refund handling as defined by the reviewed note, unknown merchant input, stable confidence/reasons, and deterministic output.
- AC7: A synthetic-package evaluation test constructs repeatable cases from `ALL_PERSONAS` ground-truth positives and explicit, test-only negative cases drawn from SYNTHETIC_DATA_SPEC §3 (for example salary, monthly groceries, weekday café, and recurring rent/utility). It reports TP/FP/FN and computes precision and recall deterministically at the detection/group level.
- AC8: Evaluation reaches precision ≥ 0.90 and recall ≥ 0.85 on the committed labeled synthetic evaluation set. Cases/labels are not removed or relabeled to meet the thresholds; if the target is not met, report the failure and propose a task for changes to synthetic truth/data rather than weakening the threshold.
- AC9: Domain package test, typecheck, and lint pass; synthetic package test and typecheck pass. Any money dependency is declared in `packages/domain/package.json` and lockfile changes are limited to that dependency.
- AC10: No production behavior, persistence, data schema, API contract, or external integration is added.

## Out of scope

## Technical notes
- Keep the detection engine under `packages/domain/detection/**`; expose a package subpath without adding a runtime dependency on `@subtrack/synthetic`.
- Put the ground-truth evaluation test under `packages/synthetic/test/recurring-detection.spec.ts`, where the existing synthetic package can import the domain detector and its persona labels. Do not import synthetic fixtures into production domain code.
- `PersonaSubscription` currently provides `id`, `merchantId`, `merchantName`, `category`, `amountMinor`, `currency`, `billingCadence`, descriptor variants, and `groundTruth.isRecurring`. It does not provide negative labels or generated transaction timestamps; the evaluation test must construct deterministic time-series cases and explicit negative test-only labels.
- Use stable codes for reason identifiers; client localization is a follow-up consumer concern, not hard-coded user-facing copy in this domain package.
- Keep monetary logic within `packages/money`. If the public APIs do not support a required exact comparison, raise the gap in the algorithm note rather than implementing a second money utility here.
- `BUG-001` and `BUG-003` are explicit dependencies because package-wide domain gates currently have policy/type and dependency-cycle blockers.

## Progress (owner appends; timestamped)

- 2026-10-04 UTC: Architect-data pre-implementation algorithm review — APPROVED within the existing domain/synthetic package boundary; no spec conflict or new service, schema, or architecture decision is needed. Candidate series are scoped by owner identity and account, stable resolved merchant key, and one ISO currency; do not combine currencies or accounts. Unresolved merchant identity yields no candidate. Accept only settled, nonzero DEBIT outflows (signed negative minor units); ignore pending, CREDIT, zero, and positive refund/credit rows. Collapse same-account/same-merchant/same-currency/same-amount retry duplicates no more than 3 calendar days apart to one occurrence, matching the anomaly rule, and do not bridge missing billing slots.
- Cadence uses calendar schedules, never fixed 30-day months, deriving civil dates from UTC fields so process timezone does not affect results. WEEKLY uses 7-day slots; MONTHLY, QUARTERLY, SEMIANNUAL, and ANNUAL use 1, 3, 6, and 12 calendar-month slots, respectively. Search nominal day-of-month anchors 1–31 (clamped to each target month's last day) and valid month phases; this lets a charge nominally due on a month-end date match when a weekend/holiday shifts it into the next month. Accept at most ±3 calendar days from each nominal slot, with unique consecutive slots. Minimum settled occurrences: WEEKLY 4, MONTHLY 3, QUARTERLY 3, SEMIANNUAL 3, ANNUAL 2 (annual is intentionally two charges because the provider history is 24 months and persona truth includes annual subscriptions).
- Amount band: represent outflow samples as `Money`, validate number inputs with `assertSafeMinorUnits`, and compare only same-currency `Money` values. Use the lower observed median as representative; require every counted amount to be within ±10% of it, using `multiply` rational bounds and `lessThan`/`greaterThan`/`equals`; expose observed min/max as the band. Never average into a fractional minor unit, convert to major-unit `number`, or merge currencies. An out-of-band group produces no candidate; larger price changes remain a follow-up/price-event concern.
- Category priors are metadata only: an explicit excluded code from CATEGORIES.md (SALARY, RENT, MORTGAGE, LOAN, INSURANCE, UTILITY_ELECTRICITY, UTILITY_WATER, TAX, CHILD_ALLOWANCE, SAVINGS_TRANSFER, INTERNAL_TRANSFER, SWISH, CSN, UNION_FEE) is a hard reject; a recognized subscription taxonomy category is positive supporting evidence, not a substitute for cadence/amount evidence. Unknown/missing category is neutral, but unresolved merchant identity remains a hard no-detection rule; never derive a known key or category from free-form descriptors. UNION_FEE must be excluded without retaining or emitting that sensitive classification. Stable reason IDs use fixed codes (merchant resolved, cadence matched, minimum occurrences met, date pattern stable, amount within band, subscription-category prior); order is fixed and numeric evidence is carried as parameters. Confidence is a deterministic rule-evidence score, not a calibrated probability: 0.85 at minimum evidence, +0.03 per additional validated interval and +0.02 for a recognized subscription category, capped at 0.95.
- Evaluation keeps every positive `groundTruth.isRecurring` subscription in `ALL_PERSONAS` (currently MONTHLY/ANNUAL) and obtains its dates/descriptors/amount jitter through `SyntheticBankProvider` with a fixed 24-month window and a one-subscription copy of the persona to preserve the provider's actual billing pattern and isolate truth groups. Add fixed test-only negative groups for salary credits, monthly/weekly grocery shopping, weekday café, rent, and utility. Their labels are separate oracle data, never detector input; salary is excluded by direction, rent/utility by the documented negative category codes, and grocery/café remain unresolved merchants (no inferred subscription key). Count TP/FP/FN per labeled series; a wrong cadence is one FP plus one FN; extra detections in one group count as FPs. Keep every committed case in the denominator and preserve the ≥0.90 precision / ≥0.85 recall thresholds.

- 2026-10-04 UTC: Implemented a pure detector for the reviewed scoped series, cadence schedule, retry collapse, amount band, excluded categories, confidence, and ordered reason rules. Added all-cadence domain tests and the full synthetic-provider evaluation with 26 labeled positive groups and 6 fixed negative groups.
- 2026-10-04 UTC: QA-1 requested stable resolved merchant identities for the grocery and café negatives. Updated those three evaluation groups to stable keys (`groceries-market` for weekly/monthly groceries and `weekday-cafe` for weekday café), preserving all truth labels and series. Focused evaluation now reports TP=26, FP=2, FN=0, precision=26/28 (0.92857), recall=1.00; the two grocery patterns produce candidates, while café does not. The ≥0.90 / ≥0.85 thresholds remain met. No category rule was changed; any grocery/restaurant suppression needs independent algorithm review because the accepted note's excluded-code list does not define those codes, while PRODUCT_SPEC §4 requires general spending to be recognized and excluded.
