## Goal
Provide a single `@subtrack/money` formatter so that D1 web and mobile components (ST-024, ST-025, ST-026, ST-027) share one locale-aware currency formatting implementation instead of duplicating `Intl.NumberFormat` logic.

## Context
- D1 Orbit and RollingTotal components need to display minor-unit amounts (e.g. 14900 öre → "149,00 kr")
- packages/i18n establishes the `'sv' | 'en'` locale vocabulary
- ST-100 will extend this package with full arithmetic (minor-unit ops, allocation, validation)

## Acceptance criteria
- AC1: `formatMoney(minorUnits, currencyCode, { locale? })` returns a locale-aware string; SEK/sv default.
- AC2: Fraction digits are derived from the currency code via `Intl.NumberFormat` (2 for SEK/EUR/USD, 0 for JPY) — no hard-coded lookup table.
- AC3: `minorUnitExponent(currencyCode)` returns the exponent so callers can convert without re-creating a formatter.
- AC4: Vitest suite passes; all four currency/locale combinations in tests pass.

## Out of scope
- Arithmetic, allocation, or validation (ST-100).
- Prisma or API layers.

## Technical notes
- Zero runtime dependencies; devDependency on vitest only.
- `type: "module"` with NodeNext resolution; exports field points to `src/index.ts`.

## Verification evidence
- `vitest run` in `packages/money` — all tests pass.

## Progress
- 2026-10-01 UTC: Implemented. `src/formatter.ts` + `src/index.ts` + `test/formatter.spec.ts` + `vitest.config.ts`. Package.json updated with real scripts and vitest devDep. 12 tests cover SEK/EUR/USD/JPY in both locales plus zero/negative/code-display.

## HANDOFF/v1
- **Exported API**: `formatMoney(minorUnits, currencyCode, opts?)`, `minorUnitExponent(currencyCode)`, types `MoneyLocale`, `CurrencyDisplay`, `FormatMoneyOptions`
- **Locale mapping**: `sv → sv-SE`, `en → en-SE`
- **Test file**: `test/formatter.spec.ts` — 12 tests; uses `toContain` to avoid ICU variation between Node versions
- **No runtime deps**: zero dependencies beyond Node.js built-in `Intl`
- **ST-100 note**: arithmetic (`Money` type, add/subtract/allocate) is a separate task branching from this one
