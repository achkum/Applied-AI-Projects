## Goal
Make the existing catalogue loader and package pass TypeScript checking with `exactOptionalPropertyTypes` enabled, while preserving the public types and current YAML loading behavior.

## Context (read before starting)
- ST-064 catalogue contract and AI_ML_SPEC §4
- The repository TypeScript base config enables `exactOptionalPropertyTypes`.
- `CatalogMerchant` and `CatalogPlan` have optional fields; the loader currently assigns explicit `undefined` to optional `website`, `categoryHue`, and `amountMinor` properties, which is incompatible with exact optional property semantics.

## Acceptance criteria
- AC1: `pnpm --filter @subtrack/catalog typecheck` passes with the repository's existing strict compiler settings; do not disable `exactOptionalPropertyTypes` or weaken compiler settings.
- AC2: The loader returns optional fields either absent or valid values according to the existing `CatalogMerchant` and `CatalogPlan` contracts. Existing YAML semantics for omitted/null values are preserved.
- AC3: Add or adjust focused tests to verify omitted/optional field handling while retaining all existing catalog validation tests.
- AC4: `pnpm --filter @subtrack/catalog test` passes, and the catalog build/typecheck command succeeds.
- AC5: No runtime dependency, schema, catalogue data, or public API change is introduced.

## Out of scope
- Changing catalogue contents or validation requirements unrelated to optional-field typing.
- Changing shared compiler settings or disabling strict checks.

## Technical notes
- Keep corrections within allowed catalog source and test paths. Prefer constructing objects without absent optional keys while preserving the declared public types.
- Do not change the meaning of `null` pricing (`undefined` in `CatalogPlan`) or omitted website/hue fields.

## Test plan
- Run `pnpm --filter @subtrack/catalog typecheck`.
- Run `pnpm --filter @subtrack/catalog test`.
- Run `pnpm --filter @subtrack/catalog build` if distinct from typecheck in the current package scripts.
