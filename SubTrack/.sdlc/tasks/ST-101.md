## Goal
Extend the `@subtrack/money` test suite to ≥ 60 example-based cases plus property-based invariants (fast-check), locking down correctness of arithmetic, allocation, predicates, and conversion for the sharing and settlement features.

## Context
- ST-100 added the money arithmetic layer; ST-101 hardens it with a comprehensive golden suite
- ST-102 (share/split API) and ST-103 (settlement compute) depend on this being well-tested
- property-based invariants (commutativity, associativity, sum-invariant) catch edge cases that example tests miss

## Acceptance criteria
- AC1: Total `it()` cases in `packages/money/test/` ≥ 60 (across all spec files).
- AC2: `fast-check` property tests verify: `add` commutativity + associativity + identity, `subtract` round-trip, `multiply` by 1/0, `allocateEvenly` sum invariant, `allocateByWeights` sum invariant.
- AC3: `pnpm --filter @subtrack/money test` passes with zero failures.
- AC4: No changes to production source files (`src/`).

## Out of scope
- Any changes to `packages/money/src/` (this is a test-hardening task only).
- ST-102/ST-103 implementation.
