## Goal
ST-035 restored the root Turborepo scripts, which means CI's `lint`/`test` steps now actually execute for every package for the first time — and `apps/mobile` is the last remaining red gate on the "SubTrack quality gates" CI job. Two independent, pre-existing (not caused by ST-034/ST-035) breakages in `apps/mobile` need fixing so CI can go fully green.

## Context (read before starting)
- Discovered 2026-09-29 while landing ST-035 (PR #83). CI log: run 36627603920, "Lint" step.
- **Lint failure:** `apps/mobile` pins `eslint@8.57.1` directly (see `apps/mobile/package.json`), but the shared flat config it extends (`packages/config/eslint.config.mjs`) uses an ESLint 9-only rule schema for `no-restricted-imports` (an object with a `patterns` array of `{regex, message}` objects — ESLint 8's flat-config schema for that rule only accepts plain strings/simple objects, not this shape). Error: `Key "rules": Key "no-restricted-imports": ... should be string ... should NOT have additional properties`.
- **Test failure:** `pnpm --filter @subtrack/mobile test` fails with a Jest/Babel parse error inside `react-native@0.74.0`'s own `@react-native/js-polyfills/error-guard.js` — `Unexpected identifier 'ErrorHandler'` (looks like a TS-flavored polyfill file Jest's transform isn't configured to handle for `node_modules`, a known class of issue with older RN + Jest preset/transformIgnorePatterns setups).

## Acceptance criteria
- AC1: `pnpm --filter @subtrack/mobile lint` (and CI's bare `pnpm lint` covering the whole workspace) completes without the ESLint schema error. Prefer bumping `apps/mobile`'s `eslint` to match the workspace's ESLint 9 line (verify `eslint-config-expo`/`eslint-plugin-react-native` or whatever mobile-specific plugins are in use actually support ESLint 9 first — if they don't, use a mobile-local override for that one rule instead of a version bump, and say which approach and why in the PR).
- AC2: `pnpm --filter @subtrack/mobile test` (and CI's bare `pnpm test`) completes without the polyfill parse error — likely a Jest `transformIgnorePatterns`/preset fix (e.g. `jest-expo` preset or explicit RN transform allowlist), not a react-native version change.
- AC3: Both `pnpm lint` and `pnpm test` run bare (CI's exact commands) from the repo root exit 0 across the whole workspace once this is fixed, alongside ST-034/ST-035's fixes (already on `main` or about to be — check current state).
- AC4: No change outside `apps/mobile/**`. If the real fix requires a shared `packages/config` change (e.g. the flat-config rule itself needs to be ESLint-8-compatible for wider reasons), stop and report BLOCKED/PARTIAL with the specifics instead of editing outside `allowed_paths`.
