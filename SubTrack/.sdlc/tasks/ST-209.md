## Acceptance
- Separate mobile-enrollment provisioning method accepts only normalized identifier hash/channel. Return immutable issuance (challengeId, literal enrollment/mobile, identifierHash, channel, issuedAt, expiresAt) projected from the same successfully inserted producer record, plus a separate test-only code. Do not assert coherence by duplicating request fields in an adapter.
- A specialized atomic repository operation distinguishes incorrect codes with remaining attempts, terminal failure, and consumed success. Missing specialized repository capability fails closed. First four incorrect attempts permit retry; fifth is terminal; success consumes once. Existing repository consumers remain compatible.
- Separate mobile verification validates the exact expected issuance from internal metadata against every field of the consumed record before proof issue. Recheck safe monotonic time and five-minute expiry after repository and proof-store awaits; mismatches or uncertain faults disclose no proof. Restricted proof remains enrollment/mobile/challenge/identifier-bound, never account/session/deletion authority. Preserve generic failures and bounded orphans.
- Process-owned bounded store reserves a slot before issuance, counting pending plus published entries toward <=10,000. Publication combines immutable metadata and test-only code in one synchronous atomic transition after future adapter settlement. Internal lookup/claim returns metadata without code, never an HTTP retrieval path. Reject partial, malformed, duplicate, late or over-capacity publication.
- Claim makes a challenge unusable across awaits. Only explicit incorrect-code remaining-attempt outcome may restore active state. Success, terminal and ambiguous fault retire it. Cleanup failure leaves an unusable claim until <=five-minute expiry; never revive consumed or uncertain state. Safe monotonic clock and expiry checks fail closed. Code remains a test-only process boundary with no logging.
- Tests prove exact issuance/consumed tuple coherence, unchanged legacy outputs, malformed tuple rejection, five attempts, exact expiry, clock regression/overflow before and after awaits, concurrent correct verification <=one proof, repository/proof faults, capacity-slot races and atomic publication/retirement/no revival. Existing API tests/lint/typecheck pass.
- Independent platform/security review, independent QA/coverage and required exact-head CI precede Conductor merge. No wire/header/core/HTTP/default/production/provider/DB/credential/deployment edit. Native and real delivery remain separate.
