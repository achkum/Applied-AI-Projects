## Goal
Create the API runtime foundation and health/version and request-scoped database security plumbing without implementing product-domain endpoints.
## Context (read before starting)
- BACKLOG_SEED.md ST-007
- ROADMAP.md §M0
- ARCHITECTURE.md §§2–5

## Acceptance criteria
- AC1: Given valid local configuration and the API starts, when `GET /healthz`, `GET /readyz`, and `GET /v1/version` are requested, then they return successful JSON responses matching the reviewed OpenAPI contract; when a required config value is invalid/missing, then startup fails with a safe diagnostic and no secret value.
- AC2: Given an unhandled request error, when the exception filter handles it, then the response uses `application/problem+json` with stable status/title fields and contains no stack trace or secret in production mode.
- AC3: Given a request enters the database transaction helper with an authenticated user context, when the request transaction begins, then the user context is set transaction-locally before queries and the transaction is closed on success and error; tests demonstrate two sequential user contexts do not leak.
- AC4: Given the app logs a request, when structured output is inspected, then pino emits structured records and excludes authorization headers, tokens, and personal data.

## Out of scope
- Product behavior, endpoints, integrations, or visual decisions not named in this contract or its accepted source documents.
