## Goal
Define the BankDataProvider domain interface and implement SyntheticBankProvider using persona fixtures for deterministic test/demo data generation.

## Acceptance criteria
- AC1: `BankDataProvider` interface exported from `@subtrack/domain/bank` with `getAccounts` and `getTransactions` methods.
- AC2: `BankAccount` and `BankTransaction` types exported from `@subtrack/domain/bank`.
- AC3: `SyntheticBankProvider` in `@subtrack/synthetic` implements `BankDataProvider` using ALL_PERSONAS fixture data.
- AC4: Transactions are generated deterministically — identical call parameters always return the same result.
- AC5: Billing cadence (MONTHLY/ANNUAL) is respected; all transactions fall within the requested date range.
- AC6: All ≥24 tests pass.

## Technical notes
- MONTHLY cadence: stable day-of-month derived via FNV-1a32 hash of `householdSeed:subscriptionId`
- ANNUAL cadence: stable month+day derived from secondary hash
- Transaction dates advanced to next Swedish business day via `nextSwedishBusinessDay`
- Descriptor per transaction picked deterministically via `rng.fork(sub.id).pick(sub.descriptorVariants)`
