## Goal and evidence
Keep existing shared UI assertions working after a normal pinned pnpm 12.6.0 lock regeneration. PR143 failed shared UI TypeScript because jest-dom resolved the web Vitest instance rather than UI's own instance. A controlled scratch comparison uses identical UI/web Vitest 5 consumers; adding only a third Vitest 4/coverage-v8 consumer makes native cycle handling flatten the two jest-dom peer keys. Frozen installs reproduce the mismatched canonical realpaths. Accepted main's lock has two nested contexts; the broken regenerated lock has one flattened context.

## Sources and chosen correction
Official pinned source, retrieved 2026-10-05: https://github.com/pnpm/pnpm/blob/v12.6.0/pnpm/crates/resolving-deps-resolver/src/resolve_peers/finalize/final_paths.rs. Its cyclic-name fallback uses name/version pairs even with dedupePeers false, and its graph unions edges across versions. The current v12.9.1 source retains that fallback; no blind manager upgrade is proposed.
Published official registry metadata, retrieved 2026-10-05: https://registry.npmjs.org/vitest/5.0.3. Vitest 5.0.3 is MIT, satisfies the existing UI ^5.0.2 range, and supports the existing Vite 6.4 and Node 24/26 versions. Pin ONLY UI's Vitest to exact 5.0.3; web remains exact 5.0.2. Their different base versions keep matcher peer keys distinct. This is a contained compatibility workaround, not a vendor resolver fix.

## Acceptance criteria
1. Given accepted main manifests, when the correction is applied, only UI's Vitest declaration changes to 5.0.3. Runtime packages, web declarations, pnpm version/config, source assertions and coverage remain unchanged.
2. Given the generated lock, when its entire semantic delta is reviewed, additions are limited to Vitest 5.0.3's necessary graph and peer contexts. No existing package version/integrity changes; API jsdom 20.0.3 and supports-color 7.2.0 remain. Independently reviewed native normalization may add API Vitest 4's declared coverage-v8@4.1.11 peer and contracts' declared magicast@0.5.5 peer, without direct dependencies/source changes.
3. Given a normal pinned frozen install, when canonical package resolution is inspected, each consumer's jest-dom resolves its own Vitest instance: UI 5.0.3 / Vite 6.4.3 / @types/node26.6.3 and web 5.0.2 / Vite 8.3.1 / @types/node24.19.0. UI strict typecheck and all 53 unchanged UI tests pass. Actual repository lint and required full exact-head CI, including API/contracts/integration gates, pass with no required step skipped.
4. Independent source/lock review and QA approve the final head. Record the deliberate UI/web patch split in UI setup documentation; future convergence requires peer-resolution proof. No vendor patch, hand-edited lock, fabricated types, test deletion/skip, global settings or supply-chain relaxation.
