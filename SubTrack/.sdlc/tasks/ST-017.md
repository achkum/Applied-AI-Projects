- AC1: **ST-020 contrast checker**: CI runs the token contrast verification (light/dark theme pairs per WCAG AA); passes if all pairs meet threshold; fails with readable report if violations found; does not block ST-020 implementation (job already exists or is a simple script call)
- AC2: **ST-022 visual regression**: CI runs Storybook build + Playwright screenshot tests (or Percy snapshot job); passes if visual diffs are within threshold or approved; does not block ST-022 implementation (job already exists or uses standard tooling)
- AC3: **Workflow structure**: Both jobs run in existing `subtrack-ci.yml` under path-filter `SubTrack/**`; contrast checker runs after `typecheck` phase (requires tokens to exist); visual regression runs after `test` phase (requires Storybook build)
- AC4: **Job failure handling**: Job failure is a required check (blocks merge); failures are actionable (clear error messages pointing to token file or story path)
- AC5: **Separation of concerns**: Neither ST-020 nor ST-022 task files have permission to edit `.github/workflows/**`; all workflow logic lives in `subtrack-ci.yml` (devops owns it)
- AC6: **Documentation**: README or inline comments in workflow explain contrast checker trigger and visual regression comparison tool (Playwright/Percy/etc.); link to official docs (with URLs and dates per CONSTITUTION Article 3.3)
- AC7: **Testability**: Workflow can be run locally or in dry-run mode for validation; command documented in PR
