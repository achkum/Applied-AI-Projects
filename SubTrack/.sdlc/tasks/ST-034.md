## Goal
`main`'s `pnpm-lock.yaml` is out of date with `apps/web/package.json` (17 dependencies were added by ST-008 without regenerating the lockfile). This makes `pnpm install --frozen-lockfile` fail in CI, so the "SubTrack quality gates" job fails at the install step on every PR, before lint/typecheck/tests even run. This is a hard CI blocker for the whole dispatch loop.

## Context (read before starting)
- Discovered 2026-09-29 during conductor takeover: PR #82 (docs-only `.sdlc/**` change) failed CI purely on `ERR_PNPM_OUTDATED_LOCKFILE`, confirming the break is pre-existing on `main`, not caused by that PR.
- CI log: https://github.com/achkum/Applied-AI-Projects/actions/runs/36549278321/job/109343173946
- Root cause: `apps/web/package.json` (added in ST-008, PR #70) has 17 deps not reflected in `pnpm-lock.yaml`: `@subtrack/contracts`, `@subtrack/i18n`, `@subtrack/ui-tokens`, `@testing-library/jest-dom`, `@testing-library/react`, `@types/jest-axe`, `@types/node`, `@types/react`, `@types/react-dom`, `@vitejs/plugin-react`, `jest-axe`, `jsdom`, `next`, `next-intl`, `react`, `react-dom`, `vitest`.

## Acceptance criteria
- AC1: Given `pnpm install --frozen-lockfile` runs from repo root, when it completes, then it succeeds with exit code 0 and no `ERR_PNPM_OUTDATED_LOCKFILE`.
- AC2: Given the regenerated lockfile, when `pnpm -w typecheck`, `pnpm -w test`, and `pnpm -w lint` run, then none of them fail due to dependency resolution (pre-existing unrelated failures, if any, must be reported separately, not hidden).
- AC3: Only `pnpm-lock.yaml` and, if needed to resolve `ERR_PNPM_IGNORED_BUILDS`, `pnpm-workspace.yaml`'s `allowBuilds` map may change — no `package.json` in any workspace is modified. If a version needs bumping to resolve a conflict, stop and report BLOCKED with the conflict details instead of guessing.

## Out of scope
- Fixing any lint/typecheck/test failures unrelated to lockfile drift.
- Upgrading any dependency beyond what's already declared in package.json files.
