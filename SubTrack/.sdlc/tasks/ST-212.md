## Phase 1 implementation and projection plan (architect draft; readiness pending)
1. Validate only the accepted existing Bearer JWT with AuthenticatedPrincipalGuard, resolver and real current-session owner reader; derive RequestContext from the trusted principal.
2. Keep the controller in a test-only Nest composition; do not register it in default AppModule or create a production issuer/provider.
3. Run each read in accepted withRequestTransaction, binding both principal GUCs to the same user; use the existing nonowner database role and RLS.
4. scope=me means owned records. scope=household requires a route through the caller's active household memberships even for owned rows; peers see active explicit shares despite always_private, while always_private blocks only open_book. De-duplicate across households.
5. Reject member:<memberId> for these paths: it is a client owner selector. Accept only stable CATEGORIES.md codes; unknown scope/status/category/parameters return generic 400 instead of an empty page or broadened read.
6. Accept the seven existing SubscriptionStatus values; no status filter means all statuses. Review inbox is fixed to owner-owned DETECTED rows, with no scope/status/owner selector.
7. List and detail scoped SQL require (subscription.identity_id=trusted principal OR subscription.status<>DETECTED) before keyset/limit+1; inbox scoped SQL requires identity_id=principal AND status=DETECTED. RLS alone does not hide peer DETECTED rows.
8. Order by immutable subscription created_at DESC, id DESC. Apply the strict last-seen tuple keyset predicate after current visibility, scope and status predicates; fetch at most limit+1.
9. Enforce limit 1..50 (default 20). Decode cursor with max 512 base64url characters/384 bytes, exact version/keys/types, endpoint name, valid timestamp/UUID and matching normalized scope/status/category; reject reuse on another path with generic 400.
10. Cursor is only a position, never authority. Recheck current RLS per page and omit total counts. No hidden row contributes to returned items, cursor or page metadata.
11. Owner projection uses model fields only: id, customName, merchantId/canonical merchantName, categoryCode, cadence, status, expectedAmountMinor, currency, nextChargeDate, alwaysPrivate.
12. Peer projection uses only id, categoryCode, cadence, status, expectedAmountMinor and currency. Never emit owner identity, custom name, merchant/account IDs, detection reasons, raw transactions or evidence.
13. Keep DETECTED review cards owner-only. Expose only known reason code names from accepted detection vocabulary, never params/raw JSON; confidence and catalogPlanId remain owner-only.
14. For detail, return the same 404 problem for missing and invisible IDs. Authenticate before querying; invalid query and auth failures use stable generic RFC 9457 codes.
15. Read bigint minor units as bigint and serialize canonical signed decimal strings within PostgreSQL signed BIGINT range; never cast to Number. Validate currency by accepted Money rules.
16. Prove peer share/open_book DETECTED absence in list, detail, cursors and nextCursor; owner DETECTED remains visible. Prove active-household scope and revocation between pages in disposable PG16 HTTP proof.
