## Goal
Implement three web signature components (RollingNumber, ScopeSwitcher, ReceiptCard) with locale-aware rendering, category-aware coloring, and full accessible/reduced-motion support per Norrsken design direction.

## Context (read before starting)
- docs/product/DESIGN_DIRECTION.md §4 (components 3, 4, 2 respectively)
- docs/governance/QUALITY_GATES.md (test pyramid, accessibility, visual regression)
- ST-023 component specifications (once DONE)
- `packages/ui-tokens`: category-hue tokens, reduced-motion vars

## Acceptance criteria
- AC1: **RollingNumber**: Hero total displays with Fraunces optical size 64px (dark: #F2EFE8, light: #15161C), tab-figure numerals, locale-formatted (sv: "1 390 kr", en: "SEK 1,390"), and digits roll when values change; reduced-motion mode freezes transition; Storybook story (ST-022) + vitest unit/behavior test. Playwright visual-regression is deferred to ST-017 once its CI wiring lands — not blocking this task.
- AC2: **ScopeSwitcher**: Segmented pill (radius 28px) with member avatars, tints global accent per scope (Me=violet, Household=green, member=**member-specific accent via `memberAccentForId`**, per ST-030 — not a category hue), accessible keyboard nav/screen readers (role="group" + aria-label), icon/text labels; Storybook story + vitest interaction test
- AC3: **ReceiptCard**: Editorial layout with perforated bottom edge, price in Fraunces (variable optical size), price-history ticker-tape line, category token color per subscription type; WCAG AA contrast verified; Storybook story. Pixel-level visual snapshot deferred to ST-017 — not blocking this task.
- AC4: All three components use `@next-intl` for sv/en parity; i18n key parity check passes in CI
- AC5: Accessibility: focus visible, reduced-motion respected (motion freezes, no transitions); `jest-axe`/vitest-axe unit-level audit passes with no violations. Full `axe-playwright` E2E audit deferred to ST-017 — not blocking this task. VoiceOver session evidence deferred to ST-039 (no device/simulator available to an agent).
- AC6: Components live in `packages/ui` (`@subtrack/ui`) first, with tests/Storybook, before `apps/web` integration; `apps/web` adds `"@subtrack/ui": "workspace:*"` and consumes them. Integration tests verify data flow from dashboard API stubs.
- AC7: No TODOs without task IDs; cite ADR-0009 (component placement) and existing ADRs for Fraunces/motion choices

## Out of scope
- Dashboard API integration (awaits ST-082); use mock data in tests
- Actual subscription data or payment details (use fixtures)
- Store integrations or external API calls

## Technical notes
- RollingNumber motion uses Framer Motion with spring(damping: 18, stiffness: 180); reduced-motion uses instant transition
- ScopeSwitcher scope change tints full page accent via theme context; reversible without state loss
- ReceiptCard price-history line is SVG sparkline; no external charting library
- Do not edit CI workflows; contrast checker and visual regression are wired by ST-017
- Money formatting: `packages/money` is currently an empty scaffold. Do not block on it — write a local formatter in `packages/ui` for now, matching the ST-023 spec's format examples exactly, and flag it as a future `packages/money` consumer (see ST-056).
- See `docs/architecture/adr/ADR-0009.md` for why `packages/ui` (not a new package) is the target and why Playwright/axe-playwright/device evidence is deferred rather than blocking.
