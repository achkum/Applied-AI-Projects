# ST-067 — Ingestion Worker

**Status:** IN_REVIEW
**Branch:** st/ST-067-ingestion-worker
**Depends on:** ST-065 (bank domain types + BankDataProvider interface)

## Summary

Implements the ingestion worker in `packages/domain/ingestion/`:

- **`types.ts`** — `IngestionRecord` (normalized, deduplicated transaction) and `SyncResult`
- **`normalize.ts`** — `normalizeTransaction(tx: BankTransaction): IngestionRecord`; builds a stable `dedupKey` and serialises the raw payload as JSON
- **`dedup.ts`** — `deduplicateRecords(existing, incoming): SyncResult`; detects inserts, updates (pending→settled, amount/description corrections), and unchanged records
- **`worker.ts`** — `IngestionStore` interface, `InMemoryIngestionStore` (Map-backed), and `IngestionWorker` (`syncAccount` + `syncUser`)
- **`index.ts`** — barrel export for all public symbols

## Changes to `packages/domain`

- `package.json` — added `./ingestion` export condition + `@subtrack/synthetic` devDep
- `tsconfig.json` — added `ingestion/**/*.ts` and `test/**/*.ts` to `include`
- `vitest.config.ts` — added `test/**/*.spec.ts` to `include`

## Tests

`test/ingestion.spec.ts` — 25 tests covering:
- `normalizeTransaction`: dedupKey shape, field preservation, rawPayload validity
- `deduplicateRecords`: first sync, idempotent re-sync, change detection (pending, amount, description)
- `InMemoryIngestionStore`: empty initial state, upsert semantics, per-account isolation
- `IngestionWorker`: full sync lifecycle, idempotency, pending-to-settled transition
