## Goal
Deliver household membership and administration in scope of SubTrack PRODUCT_SPEC, with privacy and security invariants enforced.
## Context
- PRODUCT_SPEC §F2.1, F2.4–F2.7; USER_FLOWS.md UF-02; DATA_MODEL.md §Household
## Acceptance criteria
- AC1: Given a verified user, when they create a household, then creator is its sole ACTIVE ADMIN.
- AC2: Given household roles, when admin transfers role/removes/leaves or member leaves, then transaction preserves exactly one ACTIVE ADMIN whenever household remains active; forbidden last-admin removal is rejected.
- AC3: Given an admin adds a dependant, when persisted, then no login identity is created and member has DEPENDANT role.
- AC4: Given member listing/update requests, when caller is unauthorized or outside household, then deny without disclosing records.

- Features beyond this task’s stated Goal and M1 PRODUCT_SPEC scope.
