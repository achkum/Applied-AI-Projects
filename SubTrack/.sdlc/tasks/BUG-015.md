## Goal
Correct the three existing Orbit visual defects that block review of BUG-014's missing Storybook baselines: clipped outer-member bodies, a DarkCanvas story that actually renders the light theme, and an empty story without its specified line-art constellation. Keep the change inside the existing Orbit component/story boundary.

## Context (read before starting)
- `computeOrbitLayout` uses a 480×480 viewBox centered at (240,240), while the outer ring radius is 312 and the largest body radius is 28. The existing sample includes outer-member bodies whose bounds exceed the viewBox.
- Storybook's preview decorator already applies `data-theme` from the `theme` global. The preview disables Storybook backgrounds; `DarkCanvas` currently sets only `parameters.backgrounds`, so the decorator remains light. Its diagnostic image is byte-identical to `Default`.
- The Orbit component spec says the no-subscriptions state is a line-art constellation and that semantic roles resolve in both themes (`docs/design/components/orbit.md`). Use generated token values already available in `packages/ui-tokens`; do not add colors or user-facing copy for the illustration.
- The Orbit source's `--color-cat-*` and `--color-orbit-*` names are not present in generated token CSS. Category bodies currently fall back to gray, and track/centre/active styling falls back to raw colors. The generated role names are `--category-video-streaming`, `--category-music-audio`, `--category-fitness-wellness`, `--category-software-productivity`, `--category-gaming`, `--category-cloud-storage`, `--category-news-magazines`, `--category-other-subscription`, plus `--line-hairline`, `--bg-raised`, `--bg-sunken`, and `--ink-primary`. BUG-015 may correct Orbit-local references to these existing roles only; it must not edit generated tokens or add new tokens. Category aliases already used by stories map to those generated names (`streaming`→video-streaming, `fitness`→fitness-wellness, `productivity`→software-productivity, `gaming`→gaming, `music`→music-audio, `cloud`→cloud-storage, `news`→news-magazines, and unknown/other→other-subscription).
- BUG-014 captures current story baselines. This task changes no snapshots; after this repair, BUG-014 must re-render and independently review any changed Orbit images before copying them.
- The component spec also calls for a 44×44 CSS-pixel hit target and an accessible list fallback. The current visible SVG button circle is its hit target and can be smaller than 44px; enlarging the viewBox can shrink it further at the same rendered width. Measure and disclose the effective hit-target size before and after the geometry change. Do not claim this bounded repair completes the broader accessible fallback/responsive Orbit contract; unresolved dense-layout collision policy, 44px responsive target, and list-fallback work are explicitly deferred to BUG-016.

## Acceptance criteria
- AC1: Given the current Orbit sample, when the layout is rendered, the viewBox/canvas contains every ring track, visible body, selected stroke, label, transparent body target, and focus stroke, including the radius-312 member ring and maximum radius-28 bodies, with a small positive edge margin. The reviewed implementation approach is to keep current ring radii and cost/cadence placement, use a 720×720 canvas centered at (360,360), and align the rotation origin to that center. At maximum body radius, derive the target radius from the layout size relative to one named 480-unit reference: `28 × (720 / 480) = 42`; the outer target bound is `312 + 42 = 354`, leaving 6 SVG units of margin. Include selected/keyboard focus stroke allowance in tests and preserve positive margin. Equivalent dynamic extents are acceptable if they provide at least these bounds. Do not solve clipping by changing cost-to-size mapping, ring assignment, cadence ordering/angles, or dropping bodies.
- AC2: Given an unchanged set of subscriptions and props, when rendered after the geometry fix, the existing public `OrbitProps`, `OrbitSubscription`, aria labels, selected-body styling, keyboard behavior, callbacks, SVG body radii/cost mapping, and cadence semantics remain unchanged. Transparent hit-target radius must scale by `layout.size /` the single named 480-unit reference so its screen-space size stays equal to the prior visible-circle target. Do not repeat unrelated hard-coded viewBox ratios. At the default Storybook viewport, report smallest effective CSS-pixel hit target before and after. Cover click, Enter, Space, selected styling and focus-visible outline in tests. For the existing Default story fixture, verify every pair of transparent hit targets is non-overlapping so a target cannot steal a neighboring body's click.
