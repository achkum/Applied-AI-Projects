## Goal
Provide stable, theme-aware per-member identity accents so the Scope switcher specification can reference real generated tokens, without borrowing subscription-category hues.

## Context (read before starting)
- docs/product/DESIGN_DIRECTION.md §§3–4, 6
- docs/design/components/scope-switcher.md and QUESTIONS.md on PR #54
- packages/ui-tokens/src/tokens.json, generator and existing contrast tests
- ST-023 architect-client REVIEW/v1 on PR #54

## Acceptance criteria
- AC1: Given an opaque member identifier, when an identity accent is selected, then the same identifier receives a stable member accent across renders and themes without using a display name or other personal data as the selector.
- AC2: Given light and dark themes, when generated web CSS and native theme mappings are inspected, then each supported member accent has explicit, documented token names and values for both themes, distinct from subscription-category hue tokens.
- AC3: Given selected and unselected Scope switcher states, when accent and text/background combinations are tested, then contrast meets the accepted accessibility target and the selected state remains distinguishable without colour alone.
- AC4: Given token sources change, when generation and tests run, then generated assets are reproducible and token/contrast checks pass.

## Out of scope
- Scope switcher component implementation or editing ST-023 specs; ST-023 will cite the final token names after this task merges.
