## Goal
Resolve the open Orbit interaction and accessibility requirements as a reviewed, implementable contract before changing component behavior for arbitrary subscription data. This is a planning and specification task; it does not implement UI or change product behavior.

## Context
- `SubTrack/.sdlc/tasks/ST-025.md` AC3 requires a persistent “View as list” toggle, a semantic list with category, price, and owner, and a screen-reader default mode.
- `SubTrack/docs/design/components/orbit.md` requires a 44×44 CSS-pixel target and an accessible list fallback.
- `SubTrack/.sdlc/tasks/BUG-015.md` preserves the current Default-story targets without overlap and explicitly leaves arbitrary dense layouts, responsive 44px targets, and the list fallback unresolved.
- Existing Orbit cost sizing, cadence placement, scope ownership, public props, and selection semantics are accepted behavior and must remain stable unless a separate reviewed product decision changes them.

## Acceptance criteria
- AC1: Inspect the current Orbit implementation and accepted component/product specs. Record the current responsive dimensions, target sizes, collision cases, fallback accessibility tree, and the exact gap against ST-025 AC3 and the component spec.
- AC2: Define an explicit policy for dense or coincident subscription targets and overflow. The policy must state how keyboard/pointer selection remains deterministic and when or how the accessible list is offered. Do not invent new subscription grouping, cost, cadence, or ownership semantics.
- AC3: Specify how the 44×44 CSS-pixel target requirement is met at supported responsive widths, or document a proposed product-spec exception with its rationale and required approval. State any minimum viewport constraints and behavior when targets cannot fit without overlap.
- AC4: Provide concrete acceptance criteria and meaningful unit/component/accessibility tests for a separate implementation task. Include checks for sparse current fixtures, dense fixture cases, focus order, keyboard selection, pointer selection, reduced motion, and list content as required by the accepted spec.
- AC5: Obtain architect-client, design-lead, and QA review of the resulting behavioral contract. Record unresolved decisions and do not mark this task DONE until the next implementation task is sufficiently bounded and created by the Conductor.

## Out of scope
- Editing Orbit source, styles, tests, stories, generated tokens, or visual baselines.
- Reworking cost-to-radius, cadence/ring placement, or subscription ownership mapping.
- Claiming the existing SVG-only interaction satisfies the list-fallback or responsive 44px requirements.

## Review / handoff
This task exists to make the deferred Orbit requirements explicit and implementation-ready. The Conductor owns any board update and dispatch of the subsequent implementation task after the reviewed policy is recorded.
