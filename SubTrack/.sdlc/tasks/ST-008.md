## Goal
Create a Next.js web app skeleton with app router, i18n routing (sv/en), theme provider (system/light/dark), and generated API client wiring. Skeleton must be ready to receive feature implementations starting with hero screens and auth flows.

## Context (read before starting)
- ST-006 (contracts package) is DONE; generated API client is available
- ST-020 (UI tokens) is DONE; CSS vars and theme JSON are ready
- packages/i18n (ST-011) provides the i18n catalog structure
- docs/design/DESIGN_DIRECTION.md describes the theme system (light, dark, system)

## Acceptance criteria
- AC1: Given a developer runs `pnpm install && pnpm run dev`, when the web app starts, then the root page renders a placeholder welcome screen with language switcher (sv/en) and theme selector (light/dark/system) and the page is accessible (no a11y errors)
- AC2: Given a developer navigates to `/sv/...` or `/en/...`, when they inspect the HTML, then the lang attribute matches and next-intl provides locale context to child pages
- AC3: Given a developer imports the API client from @subtrack/contracts, when they instantiate a client, then TypeScript types are available and the client targets the API base URL from environment config
- AC4: Given a designer opens the app in light and dark themes, when they inspect elements, then CSS custom properties reference the tokens from packages/ui-tokens and no hardcoded colors appear
- AC5: Given the app runs in CI, when lint/typecheck/test scripts complete, then all pass with no warnings

## Out of scope
- Actual pages, routes, or components beyond the placeholder welcome screen
- Authentication or protected routes
- API calls or data fetching
- Storybook or visual regression (ST-022)

## Technical notes
- Use Next.js app router (not pages router)
- Middleware must handle i18n routing without breaking the root path
- Theme provider must read system preference and allow manual override via localStorage
- API client wiring: inject baseUrl from `process.env.NEXT_PUBLIC_API_BASE_URL` or config
- ESLint boundaries (from ST-003) must allow web to import from contracts, i18n, ui-tokens, ui, and config only
