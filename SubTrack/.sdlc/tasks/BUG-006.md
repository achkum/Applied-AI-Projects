## Goal
Restore strict typecheck, lint, build, unit/accessibility tests, and real web-consumer integration tests for the existing shared UI components without changing their product design or intended interaction behavior.

## Context (read before starting)
- The shared UI package implements Orbit, RollingNumber, ScopeSwitcher, and ReceiptCard, but its public barrel exports only Button and Orbit. Web integration tests cannot import the three signature components or `ScopeOption`.
- The latest full check reports strict optional/index-access errors in Orbit layout/types/tests and RollingNumber's Framer Motion target/transition typing.
- UI lint reports unused `useReducer` and `meAndHousehold` declarations.
- UI tests fail because Vitest is missing the `@testing-library/jest-dom` and axe matchers in setup; corresponding matchers also lack type declarations.
- Web typecheck does not see a CSS-module declaration for imported shared UI source. Web integration tests also make assumptions about accessible names/roles that do not match the rendered component semantics.
- Current source and tests are authoritative for intended behavior; this bug does not authorize a visual or product redesign.

## Acceptance criteria
- AC1: `@subtrack/ui` publicly exports `RollingNumber`, `ScopeSwitcher`, `ReceiptCard` and their existing public prop/option/history types, including `ScopeOption`, through its package entrypoint.
- AC2: Shared UI and web strict typecheck/build pass with compiler strictness unchanged. Optional values and indexed arrays are handled explicitly, and Framer Motion props use compatible typed values rather than widening/unsafe casts.
- AC3: The UI package test setup registers the DOM and axe matchers used by existing tests, with the needed type declarations available to both package tests and typecheck. Existing accessibility assertions execute and pass; do not delete or skip them.
- AC4: Remove the reported unused declarations and make lint pass without suppressing rules.
- AC5: The web consumer has a CSS-module declaration available to its TypeScript project and can import the shared UI package entrypoint.
- AC6: Update web integration assertions to query the actual accessible names and roles specified by the existing components, and preserve tests for Orbit's accessible list/body interactions and all three signature component render/interaction behavior. Do not weaken tests to implementation-specific class/text selectors.
- AC7: `pnpm --filter @subtrack/ui lint`, `typecheck`, `build`, and `test`, plus `pnpm --filter @subtrack/web typecheck` and `test`, pass.
- AC8: No visual redesign, new user-facing behavior, raw style token bypass, or unreviewed interaction change is introduced. If visible behavior must change to satisfy accessibility, record it and request design-lead review before proceeding with that behavior change.

## Out of scope
- Redesigning signature components, changing design tokens, or changing product copy/flows.
- Removing accessibility checks, weakening assertions, excluding test files from typecheck, or disabling strict optional/index checking.
- App routing, API, mobile components, and packages outside shared UI and the listed web consumer tests/types.

## Technical notes
- `packages/ui/src/css.d.ts` currently declares CSS modules for its own project; if the web consumer still cannot see the declaration, add a consumer-side declaration at the allowed `apps/web/types/css.d.ts` path and include it in the web tsconfig.
- Existing shared UI dev dependencies already include `jest-axe` and `@testing-library/jest-dom`; add only a compatible type package if needed, updating the lockfile only for that dependency.
- Preserve semantic names and roles in component markup; adjust test queries only to reflect the actual public accessibility contract.
- Design-lead approval is required if a proposed fix changes visible behavior; pure typing, exports, and test setup changes do not require a design review.

## Test plan
- Run package UI lint, typecheck, build, and test.
- Run web typecheck and integration tests.
- Confirm axe and DOM matcher assertions are active and report exact command results.
- Request design-lead review before merging any visible interaction/appearance change.
