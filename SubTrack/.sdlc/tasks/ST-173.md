# Proposed task contract: ST-173 web read-only Lindqvist demo

## Goal
Add a bilingual, read-only fictional demo route to `apps/web` using the public synthetic persona and exact minor-unit formatter. Keep the existing localized welcome and home routes stable. This is a bundled illustrative client experience; it does not create a session, authenticate a user, enforce tenant isolation, or implement UF-12's server-side security/rate-limiting acceptance criteria.

## Current evidence and boundaries
- The accepted web welcome route is `apps/web/app/[locale]/page.tsx` → `welcome-screen.tsx`; it renders the brand and tagline only. Add one honest “Explore demo household” link to `/sv/demo` or `/en/demo` from that screen.
- `apps/web/app/[locale]/home/` is accepted as a distinct Orbit showcase: `lib/home-mock.ts` contains five sample subscriptions, static amount labels, and mixed-cadence totals. Do not repurpose it or claim it is the Lindqvist demo.
- The public `@subtrack/synthetic` root exports `PERSONA_LINDQVIST` (Lars & Maria Lindqvist, six subscriptions). The public `@subtrack/money` root exports `formatMinorUnits(bigint, currencyCode, options)`. Their manifests expose only package-root imports. `apps/web/package.json` currently lacks both direct dependencies.
- Existing web route/component tests live in `apps/web/test`, including both locale handling and `jest-axe` checks. `ST-173` does not appear in the current backlog; confirm before assignment.
- UF-12 describes an ephemeral demo-tenant session, isolation from real tenants, and rate limiting. A static web route cannot demonstrate those guarantees; keep copy explicit that the data is fictional and bundled. Do not represent the route as UF-12 completion.

## Proposed behavior
- Add `/[locale]/demo` with valid `sv` and `en` locales and a localized return-to-welcome link. Invalid locales follow the established `notFound()` pattern.
- Add an accessible welcome link directly in `WelcomeScreen`. Do not add or invoke Create account / Log in callbacks or send those actions to the demo; there are no honest destinations established by this task.
- Render all six `PERSONA_LINDQVIST` entries with the fixture's merchant name, original `MONTHLY`/`ANNUAL` cadence, and currency. Prominently label the data as fictional/demo in both locales. Preserve source cadence and amount; do not normalize annual amounts or show household totals/projections.
- Convert each number-shaped fixture minor amount only after `Number.isSafeInteger(amountMinor)`, then call public `formatMinorUnits(BigInt(amountMinor), currency, { locale })`. Fail closed on an unsafe amount or formatter failure; show a localized unavailable state without a numeric amount. Do not use `Number` for money, float arithmetic, `formatMoney`, Orbit/RollingNumber numeric props, private source imports, or numerical fallback.
- Keep the page read-only apart from optional local presentation state. No fetch/API, auth, session, secure storage, persistence, provider, or tenant claims.
- Use catalog strings, existing theme tokens and established web layout/accessibility patterns. Do not change catalog/synthetic/money source APIs or Next config unless an independently evidenced need is added to the proposal and its review scope.

An unsafe fixture value or formatter exception yields a localized no-amount state.
