# Implement the v2 HTTP transport prerequisite

The accepted v2 contract already requires exact configured Origin, HTTPS outside explicit local development, a distinct configured binding cookie and no-store/no-cache responses. Existing cores consume trusted evidence; raw Node/Nest extraction and runtime configuration remain unwired. Read docs/product/API_CONTRACT.md and ADR-0010 before implementation. This task adds the real transport/configuration boundary and wires cache policy into main.ts. It does not register an auth controller, issue cookies or nonces, or mint a trusted principal/browser-chain authority. ST-170c remains incomplete.

## Contract

1. Preserve existing API configuration when v2 is not explicitly enabled. Add documented strict AUTH_V2_ENABLED (default false), AUTH_V2_ALLOWED_ORIGINS (JSON array of canonical exact origins), AUTH_V2_BINDING_COOKIE_NAME, AUTH_V2_BINDING_COOKIE_PATH and AUTH_V2_ALLOW_LOOPBACK_HTTP (default false). Require explicit valid origins/name/path when enabled; no wildcard/null origin, URL credentials/path/query/fragment, implicit insecure origin, malformed boolean or unsafe cookie fields. Loopback HTTP is development-only and explicit; reject it in production/test configurations. Validate __Host- name/path requirements and collisions with v2 access/refresh cookie names. Report invalid field names only, never supplied values. These are configuration interfaces, not confirmed deployment values.
2. Extract browser evidence from actual Node/Nest requests: inspect rawHeaders to preserve duplicate Origin and recognized binding-cookie occurrences; require exactly one canonical allowlisted Origin. Reject malformed or duplicate recognized binding cookie, without silently normalizing a secret. Determine direct TLS from the actual socket, never req.secure, forwarded headers or caller fields. Explicit development HTTP additionally requires a loopback origin and actual loopback socket peer. Preserve cookie absence for first bootstrap; do not invent an anonymous identity, idempotency scope or throttle. Return only internal origin/TLS/development/binding-cookie evidence needed by the accepted guard, not a session or authorization result.
3. Provide namespace response middleware and install it in main.ts. Every application-handled /v2 and /v2/** success/error response carries Cache-Control: no-store and Pragma: no-cache. Exclude lookalike /v20 and v1 routes. Preserve existing logger/filter wiring and logging redaction. Parser failures occurring before the application pipeline are outside this guarantee.
4. Test via a real Nest HTTP pipeline with a test-only probe controller: explicit loopback development succeeds; missing/null/lookalike/duplicate Origin, duplicate/malformed binding-cookie evidence, insecure transport and spoofed forwarded HTTPS fail generically. Add direct HTTPS success through an ephemeral locally generated self-signed certificate (OpenSSL subprocess argv, no committed key or certificate, no secret output, temporary cleanup). Record direct socket TLS; test fixtures never register in AppModule or production. Verify cache headers on success, rejected context and v2 404/errors; v1/lookalike control responses stay unchanged. Tests also prove config validation and cookie absence handling.
5. Focused tests, API lint/typecheck and actual source-bound platform/security approval required. Root owns full API QA, Git/evidence and exact-head CI. No provider, database/schema/migration, dependency, existing auth controller, OpenAPI/generated-client, deployment or client change.

## Remaining nonce issuance gate

The first anonymous bootstrap has no verified principal or existing browser chain. A separate platform/security decision must define idempotency and throttle scope without trusting caller-supplied proxy/IP evidence. Deployment Origin/cookie/proxy values and durable store readiness remain separate. Neither these transport tests nor in-memory reference cores establish provider, production or full authentication readiness.
