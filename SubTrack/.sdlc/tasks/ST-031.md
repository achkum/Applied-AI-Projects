## Goal
Implement the founder's 2026-09-27 option B: each task that passes required review, QA and CI merges directly to `main`, with milestone/release gates retained for public release rather than routine code integration.

## Context (read before starting)
- `SubTrack/docs/governance/CONSTITUTION.md` Article 3.9 and Article 5
- `SubTrack/docs/governance/DECISION_RULES.md` §2 D-01 and D-07
- `SubTrack/docs/governance/OPERATING_MODEL.md` §§1, 3–5
- `SubTrack/docs/governance/QUALITY_GATES.md`
- Founder reply `B` to the 2026-09-27 main-cadence decision.

## Acceptance criteria
- AC1: Given a task passes required reviews, QA and CI, when the Conductor merges it, then the target is `main`, without routine D-01 approval.
- AC2: Given a task has red checks, unresolved blocker/major findings or QA failure, then it remains unmerged regardless of target branch.
- AC3: Given production/public release is proposed, then a distinct founder approval gate still applies; milestone evidence and security sign-off remain required.
- AC4: No governance document instructs agents to target `subtrack/develop` for new task PRs. Transition guidance for open PRs is explicit.

## Out of scope
- Merging existing PRs or `subtrack/develop` into `main`.
- Editing application code or installed skills.
- Deploying or publishing.

## Technical notes (architect)
- Constitution amendments require a PR labelled `governance` and founder approval. Do not merge this PR without that approval.
- Preserve the review chain, CI, QA, security veto and stop rules.

## Test plan (QA fills before READY for M/L tasks)
- Search governance docs for stale branch and D-01 references; `git diff --check`.
