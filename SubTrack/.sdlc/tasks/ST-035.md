## Goal
CI's "SubTrack quality gates" job still fails after ST-034's lockfile fix — but on a different, more fundamental problem: `SubTrack/package.json` (the pnpm workspace **root** package.json, which wraps Turborepo: `"lint": "turbo run lint"`, `"typecheck": "turbo run typecheck"`, `"test": "turbo run test"`, `"build": "turbo run build"`, `"check": "turbo run lint typecheck test"`) does not exist on `main` at all. CI runs bare `pnpm lint` (`.github/workflows/subtrack-ci.yml:113`) which needs this file's `lint` script — without it, the step fails immediately with `Command "lint" not found`, before ever reaching turbo/eslint. Same problem will hit `typecheck` and `test` steps next.

## Context (read before starting)
- Discovered 2026-09-29 while verifying ST-034 (PR #83): install now succeeds (ERR_PNPM_OUTDATED_LOCKFILE and ERR_PNPM_IGNORED_BUILDS both resolved), but `pnpm lint` fails: `Error: ERR_PNPM_RECURSIVE_EXEC_FIRST_FAIL` / `Command "lint" not found`. CI log: run 36625094338, job "Lint" step.
- Root cause traced via `git log --follow -- SubTrack/package.json`: ST-003 (commit `b97c3ad`, PR #37) created the correct root `package.json` — see reference copy left at `/tmp/st003_root_package.json` on this host for convenience (verify content against that commit directly, don't trust the copy blindly). Later, `[ST-032] Audited migration of accepted foundation work` (commit `87630d1`, PR #68) — a "sdlc board migration/reconciliation" merge — deleted `SubTrack/package.json` as part of what its diff describes as removing the **legacy prototype's** stale package.json. But the file state at the point of that deletion was already back to the *legacy* content (`"name": "subtrack-individual-experience"`, `"start": "node server.mjs"`), not the ST-003 Turborepo version — meaning somewhere between ST-003 merging and ST-032 running, the legacy content had already clobbered the correct one (likely a stale-branch merge artifact), and ST-032's cleanup then deleted that clobbered file entirely, leaving **no root package.json at all**. This was not caught at the time — full history of exactly which merge reintroduced the legacy content wasn't chased further; if you want to confirm it, `git log -p --follow -- SubTrack/package.json` on `main` has the full chain.
- Confirmed separately: the current `pnpm-lock.yaml` (post ST-034) has **no devDependencies for the root importer (`.`)** — only `packageManagerDependencies`. This means `turbo`, `eslint`, `@eslint/js`, `eslint-plugin-boundaries`, `prettier`, `typescript`, `typescript-eslint`, and the `@subtrack/config` workspace link are currently **not resolved anywhere** in the lockfile.
