## Acceptance
- Standalone Nest registration requires development mode + explicit enabled=true. Default and production graphs exclude the routes. Do not edit app.module.ts/main.ts/config.ts or combine browser middleware routing. Copy mandatory >=32-byte anonymous HMAC binding key; require and compare decoded bytes against all configured OTP/rate/idempotency/origin/credential keys. No fallback, caller key or new environment/wire secret. Restart replaces all process-local state; no live rotation.
- Exact accepted POST /v2/auth/otp/start body {channel,identifier,purpose:enroll_identifier,transport:mobile}, one Idempotency-Key. Response202 exactly {challengeId,status:accepted,nextBrowserNonce:null}. Verify body {challengeId,code,transport:mobile}; response200 exactly {purpose:enroll_identifier,proof,nextBrowserNonce:null}. Generic problem+json errors and no-store/Pragma headers, including explicitly registered disabled/production module paths. An absent default graph must prove route absence only; this module cannot alter a graph it does not join. Reject stepup, Cookie/Authorization/Origin/browser nonce/CSRF/legacy selectors, duplicates, extra fields, query/framing ambiguity and mixed transport. Direct TLS socket required; reject plaintext and forwarded HTTPS spoofing.
- Start normalizes with contracts identifiers (SMS phone), hashes normalized identifier, applies existing direct-IP/shared aggregate and keyed identifier limits. Domain/version/operation/transport/purpose/channel/identifier hash use unambiguous length-framed HMAC with the separated server key; verify has a different domain and adds challengeId/stored hash/stored channel. These are anonymous request isolation, never verified principal. Full strict operation payload canonical digest includes code on verify. Capture one frozen reservation input and owner handle; reuse unchanged through settlement.
- Start reserves idempotency then bounded store capacity synchronously before producer mutation, provisions exact producer issuance/code, rechecks validity, settles completed then atomically publishes that same pair, then responds. Reservation/slot/provision/settle/publication/response faults disclose no code/challenge/proof; global keyed burn remains. Never reverse a completed settlement. Unreachable producer challenges expire; no rollback/replay is assumed.
- Verify resolves valid immutable metadata internally, reserves idempotency before claim/producer mutation, claims before awaiting the atomic producer. Correct consumption rechecks time, settles completed, retires metadata/code then discloses restricted proof. Wrong-code outcome burns/settles that request and may restore only explicit decreasing producer attempts4..1. Fifth, success and ambiguous failures retire; settlement or cleanup failure suppresses proof and never revives consumed state. Failed cleanup leaves unusable claim until expiry. Clocks are safe/monotonic across awaits; late proof stays undisclosed and bounded.
- Actual HTTPS tests cover both channels/normalization/exact envelopes, plaintext/proxy/header/framing/query/mixedchallenge rejection, disabled/production/default404, no-store errors; pending/completed/failed duplicate409 without replay and globalkeyreuse; all reserve/slot/producer/settle/publish/cleanup/response faults; expiry/regression/overflow/rates/capacity races; four wrong fresh-key retries and terminal fifth; concurrent correct verify at most one proof; restricted mobile enrollment proof cannot redeem as login/deletion. Test-only code access stays process-local, never HTTP/logging. Mandatory BankID remains.
- Focused tests/coverage >=80%, API lint/typecheck, full API and existing web regression pass. Independent platform/security source approvals, independent QA and exact-head CI precede Conductor acceptance. No native/device/provider/DB/delivery/default/public/deployment claim.
