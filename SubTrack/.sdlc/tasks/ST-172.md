# Proposed follow-on: gated, read-only mobile demo household

## Architecture decision

Proceed with mobile UI implementation using the accepted public `@subtrack/money` `formatMinorUnits(bigint, currencyCode, options)` API, guarded by a runtime capability probe. The probe must run on the executing JS runtime before any demo amount is formatted or rendered. A failed, throwing, malformed, or unsupported probe produces a localized unavailable state with no amount; there is no float or legacy-number fallback.

This is a defense-in-depth gate and permits development of the route while Hermes QA is outstanding. It does **not** revise ST-171's explicit requirement that Expo/Hermes support be separately validated before mobile adoption. Native-device/simulator execution of the probe plus rendered screen remains required before merge/adoption of the mobile caller. Node, component tests, Expo Web, and Metro bundle success do not satisfy this requirement. If the native gate fails on a supported target, the amount stays hidden there and the feature is blocked pending a new exact-formatting architecture decision; do not weaken the gate or silently substitute output.

The runtime probe should be a small pure, unit-testable capability function called at demo-screen entry. Verify BigInt exists, the target locale's `Intl.NumberFormat` accepts BigInt in `formatToParts`, and the public `formatMinorUnits` operation handles a SEK value above `Number.MAX_SAFE_INTEGER`, a negative subunit, and the supported demo locale (`sv`/`en`) without throwing or losing/reordering integer/fraction information. Also exercise 0-, 2-, and 3-digit currency exponents (JPY, SEK, KWD) in focused non-device tests. Probe output is internal and never shown as a demo amount; don't log it. Any mismatch returns unsupported. The gate is not a backend authorization or tenant-isolation check.

## User path and behavior

- Add `(tabs)/en/demo.tsx` and `(tabs)/sv/demo.tsx`, yielding `/en/demo` and `/sv/demo`; keep `/en` and `/sv` stable.
- Add a localized, accessible **Explore demo household** launcher directly to the existing localized Welcome screen and navigate with Expo Router. Keep `WelcomeActions` uncomposed in this slice: it requires create-account and log-in callbacks, and there are no honest destinations for those actions yet. Do not supply fake callbacks or send either action to demo.
- Render the public `PERSONA_LINDQVIST` fixture from `@subtrack/synthetic` with a prominent localized fictional/demo label. The fixture is Lars & Maria Lindqvist, `household-lindqvist`, with six deterministic subscriptions. This is bundled illustrative client data; do not describe it as a server-created demo session, tenant boundary, or access-control guarantee.
- Show each subscription's fictional merchant label and its original amount with original `MONTHLY` or `ANNUAL` cadence. Do not normalize annual amounts to monthly or invent a mixed-cadence household total. Keep the source's integer minor amount through a checked conversion: require `Number.isSafeInteger(amountMinor)` and then construct `BigInt(amountMinor)`; fail closed if not safe. Use `formatMinorUnits` from the public package entry. Do not pass prices through mobile Orbit/ListFallback: its accepted `monthlyCostMinor` is number-valued and its fallback divides by 100.
- Keep read-only behavior, except local selection/expansion state if useful. No network, auth, secure storage, bank/provider, or persistence actions. Provide a localized return-to-Welcome action.
- Use `useI18n`/`t()` and add matching English/Swedish keys to `packages/i18n/catalogs/en.json` and `sv.json`; use theme tokens and existing components only where their money and native contracts fit. Make controls at least 44 logical units, accessible, legible at narrow widths and both themes. No animation is required.
- Currency or cadence display uses exact source values and existing labels. No fake loading/progress state and no UI claim of a successful session.

## Acceptance criteria

1. Both Welcome locales navigate to their matching demo route and return to Welcome. Create account and Log in remain without callbacks in this composition and never reach demo.
2. The screen identifies fictional Lindqvist data in English and Swedish and shows all six fixture subscriptions with original amount and cadence; no mixed-frequency total or normalized monthly amount appears.
3. Capability passes before the formatter receives any value. If BigInt, `formatToParts(BigInt)`, package formatting, or semantic probe checks fail, render a localized unsupported message and no numeric amount. There is no Number conversion fallback, legacy helper, thrown screen crash, or amount leakage during initial/loading state.
4. Conversion from the synthetic fixture's existing number minor values is guarded by `Number.isSafeInteger` before `BigInt(...)`; no floating-point math is used for amounts. Format through the accepted public `@subtrack/money` API.
5. Route/component tests cover localized navigation, fixture adaptation, original cadence retention, capability pass/fail/throw behavior, fail-closed amount suppression, no network/auth/storage calls, and English/Swedish key parity. Money exponent/precision probes have focused tests.
6. Automated tests, mobile lint/typecheck, i18n parity, and Expo Web/Metro bundling are reported separately from native validation. Before merge/adoption, run an Expo native development build with Hermes on each supported platform (at least Android and iOS if both are in scope), recording Expo/RN/Hermes, OS/device/simulator, probe results, exact formatted cases, and rendered state. A compiler/parser or Node/V8 result is not an executable Hermes result.
7. Client and design reviews approve route ownership, action boundaries, responsive/theme/accessibility behavior, banner clarity and honest demo claims. Platform/security reviews apply if money-package code changes. Required data review applies only if synthetic source changes.
