## Goal
API real tests report four data-rights export failures: `0o100644 << 16` produces a signed negative JS integer and Buffer.writeUInt32LE rejects it. Preserve the intended ZIP external UNIX regular-file permission field through explicit unsigned conversion.

## Acceptance criteria
1. Fix the specific external-attribute encoding, preserving all ZIP structure, compression, permissions, and export security behavior.
2. Add a meaningful archive regression checking unsigned external mode, CRC/decompression, central/local entry consistency; retain all data-rights tests and their privacy assertions.
3. All API tests pass, lint/typecheck of changed code passes; independent platform/security review and QA approve.
4. No new dependencies or ZIP parser package, no generic integer clamping or changes to unrelated integer serialization.

## Dispatch
Developer Luna; Conductor main. Do not install concurrently with central refresh. Normal API failures `/workspace/.setup/subtrack-api-tests-final.log`.

## Progress

- Converted only the central-directory UNIX external attributes to an unsigned 32-bit value with `>>> 0`; ZIP layout and the mode remain unchanged.
- Added a ZIP archive regression covering the unsigned mode bits, local/central filename and metadata consistency, DEFLATE decompression, and known CRC-32.

## Handoff

- Validation: focused ZIP test passed (1/1); API Vitest suite passed (94/94 across 10 files); scoped ESLint passed; `git diff --check` passed.
- API `tsc --noEmit -p tsconfig.json` remains blocked by existing errors outside the allowed task scope: missing `PrismaService.session`, household/invitation spec typing errors, and invitation response optional-token typing. No changed-file diagnostics were reported.
- Independent platform/security review and QA are pending; implementation agent has not self-reviewed.
