## Goal
Deliver household invitations and response lifecycle in scope of SubTrack PRODUCT_SPEC, with privacy and security invariants enforced.
## Context
- PRODUCT_SPEC §F2.2–F2.3; USER_FLOWS.md UF-02–03; DATA_MODEL.md §Household; ADR-0003
## Acceptance criteria
- AC1: Given admin creates LINK, CODE, EMAIL or SMS invite, when issued, then it expires after exactly seven days, token is stored hashed, and only authorized admin can revoke it.
- AC2: Given an invite preview request, when token is valid, then disclose only household name, admin first name and member count; invalid/expired/revoked/used tokens return distinct safe states.
- AC3: Given eligible BankID-verified invitee joins or declines, when response is repeated, then same outcome is idempotent and admin notification is queued.
- AC4: Given delivery to non-founder email/SMS recipients, when real delivery would occur, then use test/dev adapter until required D-09 approval; never assume external sending.
## Open decision / gate
- Type-1 D-03 (third-party account/credentials) and D-09 (real email/SMS to non-founder recipients) are not grants. Keep test credentials and outbound delivery behind adapters; obtain Conductor/founder decision before any account/credential creation or real non-founder delivery.
