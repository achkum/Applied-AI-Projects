## Goal
Fix the money package typecheck failure where `Intl.NumberFormat.resolvedOptions().maximumFractionDigits` is typed as possibly undefined, while keeping currency formatting correct and making missing fraction-digit metadata fail explicitly.

## Context (read before starting)
- `packages/money/src/formatter.ts` derives the currency exponent from `Intl.NumberFormat` for `minorUnitExponent` and scales minor units in `formatMoney`.
- With the current strict TypeScript configuration, `maximumFractionDigits` is possibly undefined at formatter.ts lines 36 and 50.
- Money formatting behavior is covered by `test/formatter.spec.ts` for SEK, EUR, USD, JPY, locales, signs, and display options.
- Money and policy code require 100% branch coverage under Constitution Article 3.3.6 and QUALITY_GATES.md.

## Acceptance criteria
- AC1: `pnpm --filter @subtrack/money typecheck` passes under the existing strict TypeScript settings. Compiler flags and types are not weakened, and no type assertion is used to silence the issue.
- AC2: A checked fraction-digit helper accepts only a finite, non-negative integer digit count; if `Intl.NumberFormat` cannot provide a valid count, it throws a clear error. No fallback to zero, two, `NaN`, or another default is used for missing/unknown metadata.
- AC3: Existing public formatter behavior remains correct for SEK, EUR, USD, and JPY, in addition to the current locale, negative, zero, and display tests. No public API signature or money arithmetic behavior changes.
- AC4: Add a focused test that exercises the missing/invalid fraction-digit path using an isolated test seam or controlled Intl test double, plus retain all existing formatter tests. Do not rely on a runtime currency that happens to return a missing option unless the test proves that path is exercised.
- AC5: The formatter source achieves 100% branch coverage. If the package lacks a compatible coverage provider, add `@vitest/coverage-v8` matching its resolved Vitest 3.2.7 version and the minimal Vitest configuration/lockfile changes needed to measure formatter.ts branches.
- AC6: `pnpm --filter @subtrack/money test`, `pnpm --filter @subtrack/money typecheck`, and the configured formatter branch-coverage command pass.
- AC7: `pnpm --filter @subtrack/money lint` passes, and the PR documents coverage output and the formatter behavior evidence.

## Out of scope
- Changing currency exponent policy, supported currencies, public money APIs, monetary arithmetic, or other package code.
- Weakening TypeScript strictness, adding unchecked defaults/type assertions, or changing formatting rules to obtain green checks.
- Any architectural or dependency changes beyond the narrowly scoped compatible coverage provider if required by AC5.

## Technical notes
- Validate the actual `resolvedOptions().maximumFractionDigits` value before using it. Preserve the existing Intl-derived currency exponent behavior when valid.
- A test seam may remain module-private; do not add public API solely for testing.
- Current `@subtrack/money` Vitest resolves to 3.2.7. Any coverage provider added to this package must use the compatible 3.2.7 line, not the unrelated Vitest 4 provider used by another workspace package.
- Report any coverage threshold issue as a real finding; do not exclude formatter.ts from coverage.

## Test plan

- Add the invalid/missing exponent test and confirm it fails with the explicit error.
- Run package typecheck, test, lint, and formatter.ts branch coverage; report exact command output in handoff.
