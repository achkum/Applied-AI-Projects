## Goal
Deliver sessions, refresh rotation and device revocation in scope of SubTrack PRODUCT_SPEC, with privacy and security invariants enforced.
## Context
- PRODUCT_SPEC §F1.3, F1.6; DATA_MODEL.md §Identity; ADR-0003
## Acceptance criteria
- AC1: Given successful OTP or BankID auth, when a session is issued, then client receives EdDSA JWT and opaque refresh credential while only refresh-token hash is stored.
- AC2: Given refresh, when rotated, then old token becomes unusable; reuse revokes the token family and requires reauthentication.
- AC3: Given device list/revoke, when user revokes one device, then that device cannot refresh and other devices remain active.
- AC4: Given any user, when requesting sessions, then only own devices are returned.

## Handoff — v1

### What was built
- `apps/api/src/auth/sessions/jwt.service.ts` — `JwtService`: EdDSA (Ed25519) JWT issue and verify using Node.js `crypto.sign/verify`. Dev fallback generates random key pair at startup; production reads `JWT_PRIVATE_KEY_PEM` env var (PKCS#8 PEM).
- `apps/api/src/auth/sessions/sessions.service.ts` — `SessionsService`: createSession (AC1), refresh with rotation and family revocation on reuse (AC2), listDevices (AC4), revokeDevice (AC3).
- `apps/api/src/auth/sessions/sessions.controller.ts` — REST: POST /v1/auth/session, POST /v1/auth/refresh, GET /v1/auth/devices, DELETE /v1/auth/devices/:id. X-Caller-Id header as M1 auth placeholder.
- `apps/api/src/auth/sessions/sessions.module.ts` — wires JwtService + SessionsService + PrismaService.
- `apps/api/src/auth/sessions/sessions.dto.ts` — Zod schemas for CreateSessionBody and RefreshBody.
- `apps/api/src/auth/sessions/jwt.service.spec.ts` — 6 unit tests: issue/verify round-trip, tampered payload rejection, expiry rejection, cross-instance key isolation.
- `apps/api/src/auth/sessions/sessions.service.spec.ts` — 10 unit tests: createSession, refresh rotation, reuse detection (family revocation), listDevices (caller isolation), revokeDevice (owner-only, idempotent, wrong-caller 404).
- `apps/api/prisma/schema.prisma` — Session model: refreshTokenHash (unique SHA-256), familyId, generation, revokedAt.
- `apps/api/prisma/migrations/0003_session/migration.sql` — session table with RLS: identity_id = current_user for SELECT/INSERT/UPDATE; no DELETE.
- `packages/contracts/openapi.yaml` — added 4 session endpoints + 4 schemas (CreateSessionBody, RefreshBody, SessionTokenPair, DeviceInfo).
- `apps/api/vitest.config.ts` — extended include to cover `src/**/*.spec.ts` (existing OTP/BankID specs were not picked up before).

### AC verification
- AC1: createSession creates a session row storing only SHA-256 hash; returns EdDSA JWT + 32-byte hex refresh token.
- AC2: refresh marks old session revokedAt, creates new session with generation+1; presenting a revoked token calls updateMany on the entire family.
- AC3: revokeDevice sets revokedAt on one session; other sessions for the same identity are untouched.
- AC4: listDevices queries WHERE identity_id = callerId AND revokedAt IS NULL.
- Schema: `npx prisma@6.19.2 validate` → valid.
