No caller identity/session/family selectors. Trusted server caller hashes canonical secrets (ST185); repository never accepts or stores raw secrets.
2. This method authenticates a credential hash, analogous to proof redemption; it must never expose an unscoped row. Hash lookup inside synchronous atomic boundary derives identity solely from stored active row or consumed tombstone, then constructs frozen RequestContext {userId:stored.identityId}. Active owner check, owner-bound session/family and full transport binding, lifetime/time check, successor collision/capacity check, tombstone insertion and row replacement all one no-await operation. Normal readSession/create/rollback/deletion remain explicitly owner scoped. Document credential authentication boundary distinctly from scoped data reads. Platform/security must explicitly approve this principal-derivation design before source.
3. Outcomes: {kind:rotated,identityId,sessionId,familyId,expiresAt}; {kind:reused}; {kind:invalid}. Returned rotated IDs server-stored only. Matching active credential replaces ONLY hash on SAME session/family/identity, preserves generation0, metadata, initial createdAt/expiresAt exactly24h. Previously issued access token stays valid until family revocation/deletion/expiry. No new expiry or policy.
4. Matching CONSUMED hash and matching original transport with active/live original owner revokes every row in that owner/family and returns reused. Wrong transport/origin/chain returns invalid WITHOUT consuming/revoking or revealing owner. Keep consumed hashes until original expiry even after revocation/row rollback so old hash cannot be reused for a newly created session. Prune only by trusted repository time. Deletion removes owned rows and tombstones; identity cannot reactivate.
5. Bounded tombstones max10000, optional test max1..10000 fourth constructor argument. Reject new active session hash collisions against active rows AND unexpired consumed hashes. Refuse rotation when successor collides with any active/consumed hash or tombstone cap reached BEFORE consuming current token. Failure invalid, old active token retained. Trusted own clock safe nonnegative integer; observedAt safe <=trustedNow; row.createdAt<=observedAt<=trustedNow<expiry. Validate input/clock before prune; never caller-time prune. Existing constructor signature first3 parameters unchanged.
6. Add owner-scoped revokeRotatedFamily(expected,context):boolean where expected exact {identityId,sessionId,familyId,refreshTokenHash} and context matching userId. Only matching current successor tuple may remove that owner/family; no restore consumed credential. This is ST185 postcommit token-issuance fault cleanup, not public revocation API. Uncertain adapters no credentials; ST184 supports only synchronous memory, not future durable guarantees.
7. Concurrent same old hash calls: synchronous first rotates, second recognizes consumed hash and revokes family. First returned result represents commit point, not continued ownership after competing revocation. Resolver's existing shared read must deny old/current access JWTs after revoke. Test with real issuer/access-token/resolver sharedrepo for web/mobile; unrelated sameowner family and neighboringowner unaffected.
