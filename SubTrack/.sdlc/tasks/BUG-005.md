## Goal
Repair the current backend lint and OpenAPI contract failures while keeping the approved API behavior, privacy/data-rights coverage, and generated client artifacts truthful to the source contract.

## Context (read before starting)
- The current `subtrack-check-all.log` run reports six API lint errors: unused imports/variables and one forbidden `require()` import across the allowed files.
- OpenAPI validation fails on `SubscriptionSummary.customName` using `nullable`, which Redocly rejects under the current OpenAPI dialect.
- `packages/contracts/tests/contracts.test.mjs` asserts only health/readiness/version operations and the four related schemas, but the source contract also includes approved privacy and data-rights operations. The exact-route assertion therefore rejects routes already present in the approved source.
- Contract generation is part of the workspace build and generated TypeScript clients are tracked. Regenerate from the source contract and keep generated output reproducible.
- The API lint errors are code issues. Prisma engine download failures during API typecheck/tests in the onboarding log are an independent environment/network blocker being handled by the Conductor; do not add a workaround or misreport that failure as an API defect.

## Acceptance criteria
- AC1: The six API lint findings in this task's allowed files are corrected without disabling rules, suppressing lint, deleting tests, or weakening assertions.
- AC2: Redocly validates `openapi.yaml` using a schema representation valid for the declared OpenAPI version, while retaining the source contract's intended optional/null semantics.
- AC3: The contract test asserts the approved source routes and response schemas: `GET /healthz`, `GET /readyz`, `GET /v1/version`, `GET /v1/privacy/settings`, `GET /v1/privacy/preview-as/{householdId}`, `PATCH /v1/privacy/open-book`, `POST /v1/data-rights/export`, `GET /v1/data-rights/export/{token}`, and `DELETE /v1/data-rights/account`. It continues to reject malformed OpenAPI and unexpected route/schema changes. Do not skip or remove the test.
- AC4: Run the configured OpenAPI client generator from the unchanged or corrected source contract; tracked generated client files match the generator output and a second generation is stable.
- AC5: `pnpm --filter @subtrack/contracts lint`, `pnpm --filter @subtrack/contracts test`, and contract typecheck pass.
- AC6: `pnpm --filter @subtrack/api lint` passes. API typecheck/tests are rerun after the Conductor's Prisma binary download issue is resolved; report any remaining independent failures accurately.
- AC7: Required architect-platform and security-privacy reviews approve the API/contract changes, and QA records the gate evidence.

## Out of scope
- Changing or removing approved privacy, data-rights, household, identity, or health routes to satisfy stale tests.
- Disabling or skipping tests, weakening exact contract assertions, changing API product behavior, or introducing unapproved routes.
- Changing Prisma schemas/migrations, adding an alternate Prisma engine, or implementing a network workaround for the external binary-download failure.
- Unrelated generated-client edits or dependency upgrades.

## Technical notes
- Keep OpenAPI as the source of truth; generated clients are outputs. Preserve existing operation IDs and response semantics unless a spec-backed correction is required.
- The exact route/schema allowlist in the contract test should be updated to reflect the approved source contract, not broadened to “any route passes”.
- Generated output belongs only under `packages/contracts/generated/**`; fixture generation output is outside this task.

## Test plan
- Run contract validation, contract tests, contract typecheck, and generation twice; verify generated output is stable.
- Run `pnpm --filter @subtrack/api lint`.
- After the Prisma download issue is resolved, rerun API typecheck and API tests without modifying the Prisma binary setup in this task.
- Include required review and QA evidence in the handoff.
