## Goal
Extend the Prisma schema with banking, catalogue, and subscription tables required by ingestion (ST-067), detection (ST-080), and the subscription API. RLS policies mirror the visibility rules in ST-048.

## Context
- ST-040 defines identity/household/audit tables; this migration appends banking+subscription tables
- ST-048 visibility policy (packages/domain/policy) defines the logic that the SQL RLS USING clauses must match
- ST-064 seeds merchant/catalogue data; ST-067 ingests raw_transactions

## Acceptance criteria
- AC1: Migration adds `bank_connection`, `bank_account`, `raw_transaction`, `merchant`, `catalogue_plan`, `subscription`, `subscription_charge` tables with correct constraints.
- AC2: Banking tables (`bank_connection`, `bank_account`, `raw_transaction`) have RLS policies restricting access to the owning identity only.
- AC3: `subscription` and `subscription_charge` RLS USING clauses match the household open-book policy from ST-048 (owner OR household peer with open_book=true AND always_private=false).
- AC4: `merchant` and `catalogue_plan` have no RLS (public read, service-role writes).
- AC5: Schema validates cleanly with `npx prisma@6.19.2 validate`.

## Out of scope
- Ingestion worker logic (ST-067).
- Merchant catalogue seed data (ST-064).
- Banking or subscription API endpoints.

## Technical notes
- `amount_minor` fields use `BigInt` (BIGINT in PostgreSQL) to avoid floating-point errors.
- subscription.always_private mirrors the field checked by canViewSubscription in ST-048.
- ST-102 will add a subscription_share table and ALTER POLICY on subscription/subscription_charge.

## Verification evidence
- `npx prisma@6.19.2 validate` passes.
- Migration SQL reviewed for RLS correctness against ST-048 parity logic.
