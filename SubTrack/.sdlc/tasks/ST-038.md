## Goal
Make `render()`-based component tests actually work in `apps/mobile`, so ST-026/ST-027 (and any future mobile component task) can produce real, passing render/behavior evidence instead of unit-only logic tests.

## Context (read before starting)
- `docs/architecture/adr/ADR-0009.md` — this task was raised by that ADR's investigation
- Branch `st/ST-026-mobile-signature-components` reproduces the failure today: 3 of 8 jest suites fail, 10 of 25 tests fail, all inside a `render()` call (`RollingNumber.test.tsx`, `ScopeSwitcher.test.tsx`, `ReceiptCard.test.tsx`); the 5 passing suites are pure-logic (`formatMoney`, `oklch`, `colors`, `useReducedMotion`, i18n parity) and don't call `render()`.
- Root cause as diagnosed by the architect: `@testing-library/react-native`'s `^12.4.0` range floats to `12.9.0`, which is incompatible with this repo's RN 0.74 — `detectHostComponentNames` fails with `Unsupported param type … $ReadOnlyArray` originating from `DebuggingOverlayNativeComponent.js`.
- `main` currently has **zero** working render-based tests in `apps/mobile` — `@testing-library/react-native` was installed but never actually exercised before ST-026.

## Acceptance criteria
- AC1: Diagnose the exact `@testing-library/react-native` / RN 0.74 version combination that works (pin to a compatible version, e.g. an RNTL 12.x patch predating the break, or apply the documented upstream interop fix) — cite the actual upstream issue/changelog for the chosen fix, don't guess.
- AC2: Add one new, minimal smoke test in `apps/mobile` that renders a trivial RN component (e.g. a bare `<Text>`) via `@testing-library/react-native`'s `render()` and asserts on its output, proving the harness itself works end to end.
- AC3: Re-run the existing (currently failing) render tests on `st/ST-026-mobile-signature-components` — check out that branch's test files (do not modify their assertions) and confirm they now pass with your harness fix. If any still fail for a reason unrelated to the harness, document it precisely rather than forcing a pass.
- AC4: Update `pnpm-lock.yaml` for whatever version pin you land on; confirm `pnpm install --frozen-lockfile` succeeds from repo root.
- AC5: `pnpm --filter @subtrack/mobile test` is green (or has only pre-existing, documented failures unrelated to rendering).
