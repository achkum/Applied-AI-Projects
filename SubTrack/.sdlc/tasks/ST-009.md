## Goal
Create an Expo mobile app skeleton with file-based routing, i18n (sv/en), theme provider (light/dark/system), secure token storage, and EAS (Expo Application Services) project configuration with dev/preview/production profiles. Skeleton must be ready to receive auth flows and feature implementations.

## Context (read before starting)
- ST-006 (contracts package) is DONE; generated API client is available
- ST-020 (UI tokens) is DONE; native theme JSON is ready
- packages/i18n (ST-011) provides the i18n catalog structure
- docs/ops/APP_STORES.md describes EAS profiles and deployment strategy
- docs/design/DESIGN_DIRECTION.md describes the theme system

## Acceptance criteria
- AC1: Given a developer runs `eas build --platform ios --profile preview`, when the build succeeds, then the app installs on an iOS device/simulator and displays a placeholder welcome screen with language switcher (sv/en) and theme selector (light/dark/system)
- AC2: Given a developer navigates to different locale screens via the language switcher, when they inspect the content, then next-i18n provides locale context and content language updates without restart
- AC3: Given a backend service sends an auth token to the app, when the app stores it via secure storage (Expo SecureStore), then the token persists across app restarts and is not readable by other apps
- AC4: Given a developer inspects app.json, when they check eas.json, then dev, preview, and production build profiles are defined with correct bundleIdentifiers and API base URLs
- AC5: Given a designer opens the app in light and dark themes, when they inspect elements, then theme colors reference the native theme JSON from packages/ui-tokens and no hardcoded colors appear
- AC6: Given the app runs in CI typecheck and lint, when those scripts complete, then all pass with no warnings

## Out of scope
- Actual pages, routes, or components beyond the placeholder welcome screen
- Authentication or protected routes
- API calls or data fetching beyond client setup
- Storybook, visual regression, or device matrix (ST-145)
- App Store/Play Store submission (ST-166)

## Technical notes
- Use Expo Router for file-based routing; support sv/ and en/ path prefixes via dynamic routes
- Secure storage: use expo-secure-store for tokens; document its platform behavior (iOS Keychain, Android Keychain System)
- EAS configuration: dev profile uses a managed app ID (expo); preview and production use app store bundle IDs from APP_STORES.md
- Theme provider must read system preference and allow manual override via AsyncStorage
- API client wiring: inject baseUrl from app.json (managed via eas.json profile substitution or config package)
- ESLint boundaries (from ST-003) must allow mobile to import from contracts, i18n, ui-tokens, ui, and config only
