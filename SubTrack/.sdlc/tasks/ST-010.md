## Acceptance criteria
- AC1: Given the service is started using its documented local command, when `GET /healthz` is called, then it returns HTTP 200 and a stable JSON health response without requiring database access.
- AC2: Given `GET /ml/v1/models` is called before any model is registered, when the response is returned, then it is HTTP 200 with a documented empty model list (no fabricated model names or metrics).
- AC3: Given the service dependencies are installed from the committed uv lock/config, when pytest runs, then the endpoint tests pass; the Dockerfile builds and starts the same application entrypoint.
- AC4: Given the service runs in Compose, when network access is inspected, then it is only reachable on the internal service network as specified by ARCHITECTURE.md.
