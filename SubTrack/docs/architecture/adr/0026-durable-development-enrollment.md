# ADR-0026: Durable development enrollment and session transactions
- Status: Proposed; planning only, pending independent platform/client/security review and fresh QA.
- Class: Type 2a for contracts/storage/async ports; the concrete auth-state database boundary below requires security classification before implementation.
- Date: 2026-10-11. Baseline: accepted ST225 main `ee9225ccab444d6a8404ccf41e5cd42b3c31ce95`.

## Context
ADR0010 requires identifier OTP followed by verified BankID; accepted ADR0020/D12 A permits anonymous mobile OTP start/verify only. Neither proof nor reservation is a principal. ST225 proves private HTTPS cookies with a seeded identity and process-local session; ST226/227 mutation fixtures are independent. UF01 profile/Just me and actual signup remain missing.
At this baseline `identity-provider.service.ts:verifyAndRegister` performs separate provider lookup/create; `bankid-simulator-proof-producer.ts` resolves only registered identities and issues login proofs. `proof-store.ts:ProofRepository` supports async atomic consumption but not a shared transaction. `v2-session-issuer.ts` consumes a login proof before separate session creation/rollback and preloads active identities. These references cannot establish durable enrollment by swapping a Map.
`OtpChallengeRepository` is already async-capable but stores only identifier hash/channel, not a recoverable contact; mobile metadata also stores only the hash/channel. Future OTP issuance must transactionally reserve the private normalized contact with coherent immutable metadata before a continuation can bind it, with expiry cleanup and no test-code persistence. Current simulator `IdentityResult` returns full `name` only; UF01 given_name/surname require an explicit reviewed internal simulator-result extension using fixed trusted fixture fields, never splitting arbitrary client/provider text or inventing real BankID fields.
`SessionRepository.readSession/webContextForCurrentSession/webContextForRefresh`, `BrowserNonceStore`, `IdempotencyReservationRepository` and `SessionCsrfStore` remain synchronous; `V2SessionReader` already permits Promise reads. HTTP adapters call these synchronous ports directly. Identity lacks UF01 verified-at/names/preferences; legacy Session lacks v2 expiry/transport/origin/chain/binding and consumed-refresh tombstones. V2 proof/nonce/reservation/CSRF/continuation state has no schema.
`0002_privacy_constraints/migration.sql:163,266-269,390` supplies existing NOLOGIN/NOBYPASSRLS provisioner with only identity SELECT(id,external_id)/INSERT. Ordinary runtime writes are owner-scoped. `withRequestTransaction` sets both owner settings but does not switch roles. Current founder inventory says databases none; accepted canonical schema/RLS remains the baseline, not historical migration receipts.

## Decision
Use additive, explicitly development-only simulator enrollment and PostgreSQL transactions; retain v1/v2 namespace isolation, exclusive transport, mandatory BankID, no real provider/delivery and no caller identity headers. First usable slice is private HTTPS web; native/mobile completion and household are separately reviewed. Existing mobile anonymous authority must never be widened to enrollment completion/session.
Contract design will separate restricted OTP continuation from authoritative BankID enrollment completion. A server-owned pending enrollment binds the normalized contact/channel, identifier hash, originating challenge, transport, web origin/chain and expiry; client receives only an opaque continuation handle. The server consumes the restricted proof once when admitting this continuation, never changes its purpose to login, and never accepts a client-asserted provider result.
Verified simulator completion produces a separate one-use authoritative enrollment record binding that pending enrollment to provider-subject HMAC, verified-at and trusted simulator names. Preserve five-minute restricted proof/challenge bounds and existing limits. Pending and authoritative continuation records are each bounded to10,000, expire within five minutes, and cannot renew consumed OTP/proof state. Provider verification happens outside the account transaction; validate immutable results/time again after awaits. No provider call inside a database lock.
Web completion uses a separately contracted server transition from enrollment chain to a session-purpose nonce on the same chain and binding cookie; the server binds that transition to the authoritative record. Terminal completion consumes that nonce and authoritative record atomically. No public wire design or endpoint is activated here. Mobile cannot reuse this browser transition or the anonymous OTP reservation kind.
Deduplicate under the existing unique external_id: a subject already registered yields the UF01 “Log in instead?” path, with no contact reassignment, profile overwrite or enrollment session. Explicit later verified login resolves the active existing identity server-side. A deleted subject/contact conflict fails generically, never resurrects or relinks an account. Concurrent new registrations yield one committed identity/session; unique-conflict losers restart/login without replay.

## Transaction and role boundaries
Persist idempotency reservation before work, with global key burns and generic pending/completed/failed409, no response replay. Complete account transaction locks the owned pending reservation, authoritative enrollment and terminal nonce; rechecks expiry/bindings; provisioner SELECT/INSERT deduplicates/inserts identity; then ordinary runtime with server-derived RequestContext writes verified identity fields/contact, initial profile defaults and v2 session/CSRF. Complete settlement is in that same transaction. No client owner selector; no provisioner UPDATE/DELETE or user-data grant.
Use a single database connection/transaction with locally selected roles and both owner settings; role membership and transaction-scoped switching must be proved with disposable qualified roles before adapter dispatch. A separately committed provisioning connection would violate all-or-nothing and is rejected. Insert-only identity dedup does not require widening provisioner SELECT. Existing identities require ordinary owner-scoped active/deleted checks after server subject resolution.
Rollback removes all new identity/profile/session/CSRF effects and consumption in the account transaction; the previously committed reservation stays burned and is failed by owner-handle conditional settlement. A crash leaves pending burned reservation until bounded expiry. An uncertain commit discloses nothing and must not be compensated by deleting a possibly committed account. Lost response never replays credentials: fresh nonce/verified login, known old sessions owner-managed, unknown orphans expire.
The durable preprincipal auth-state and refresh-owner lookup need a concrete schema access proposal: private bounded operations on proof/continuation/nonce/reservation/credential-index records, returning only a matched stored owner after complete secret-hash/transport/origin/binding comparison. No arbitrary owner enumeration, identity/content grants or global runtime SELECT. Existing provisioner rights do not supply this boundary. Before schema implementation, independent security must classify the exact proposed SQL grants/functions; if adding credential-lookup authority is a security-model change, record its before/after and obtain founder Type1 approval. This gate concerns new durable lookup permissions, not already adopted D12 A or BankID.

## Durable session, async ports and recovery
Add transaction-bound Promise ports for all listed synchronous reads/transitions, CSRF mint/verify/invalidate and nonce/idempotency reserve/settle. HTTP adapters must await validated frozen snapshots and recheck clocks, current active owner, expiry and binding after awaits. No global mutable transaction handle or cached active-identity list; timeout/error/capacity/clock regression fails closed. Current-owner read joins current session and live identity, at most one row. Unsafe operations recheck session/identity/CSRF under the same locks as their mutation, closing read-to-write revocation races.
Keep separate v2 session/family/refresh-tombstone schema rather than reinterpret legacy Session. Preserve accepted 15-minute access/24-hour session expiry and same-family semantics; do not invent generation changes. Refresh locates by current or consumed secret hash, validates transport and web binding/Origin, locks family plus live owner, verifies session-bound CSRF, consumes old hash, writes successor and tombstone, replaces CSRF and settles reservation in one commit. Reuse revokes that family and CSRF atomically; unrelated families survive. Tombstones remain through family expiry; refresh uncertainty discards local credentials and requires fresh verified login.
Durable schema stores only proof/nonce/token/owner-handle digests, immutable bindings, lifecycle/expiry and keyed reservation/request digests, never raw reusable secrets or OTP codes. Enrollment contact and provider names are private necessary UF01 data, protected by access boundaries and never logs. Separate owner-profile stores display name, token avatar colour/emoji, sv/en language, theme and Just me mode; defaults must be contract reviewed. Just me creates no household/member/consent; profile errors cannot grant household authority.
Restart with identical pinned development key epoch resumes persisted session/CSRF/nonce/one-use burns, subject to DB expiry and current owner. Reload with in-memory CSRF lost requires an explicit reviewed cookie-bound exact-Origin recovery operation: authenticate current session/binding and atomically replace CSRF, return only the new CSRF, rotate under concurrency; never reconstruct old plaintext or return credentials. Missing recovery contract means fresh verified login, never bypass. Invalid/missing/mismatched key epoch fails startup closed; no fresh random-key fallback. Keep credentials outside git; separate immutable >=256-bit keys and isolated v2 signing namespace. Live key rotation is separate; controlled epoch retirement invalidates affected auth state transactionally and requires fresh enrollment/login without deleting identities. Persist clock watermark/epoch and fail closed on regression; preserve10,000-state bounds and <=24-hour reservation retention across restart.

## Alternatives and verification
Reject seeded completion claims, OTP-only login, client proof conversion, privileged bypass, separate account/session commits, and memory-authority cache after restart. Retain accepted reference cores while introducing separate durable implementations through reviewed ports.
Require independent platform/client/security review of the frozen ADR and transaction plan, fresh planning QA and exact-head applicable CI before merge. Later execution proves new-user OTP→mandatory simulator→identity→session→profile→Just me, restart/reload/fresh login, dedup/contact races, rollback/uncertain commit/lost responses, reused refresh family revocation, expired/consumed nonce/proof isolation, role/RLS/CSRF revocation races and real natural-browser cookie/Origin behavior. No implementation, provider, native or product-completion acceptance follows from this planning task.
