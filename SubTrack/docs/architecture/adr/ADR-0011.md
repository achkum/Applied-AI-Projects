# ADR-0011: Shared identifier normalization ownership

- Status: Accepted (shared normalization and callback-only client scope)
- Date: 2026-10-06

## Context

The web onboarding helper owns deterministic email and phone normalization. Mobile needs the same behavior, and both clients already depend on `@subtrack/contracts`. Duplicating the rules risks divergent validation; adding a new domain package would add client dependencies and package maintenance for a small pure function.

## Decision

Move the accepted pure normalizer and its exported types byte-for-byte into `packages/contracts/identifiers.ts`, expose it as `@subtrack/contracts/identifiers`, and make the existing web helper re-export those types and function. Include the module in contracts typechecking. Mobile consumes that subpath through a reusable callback-only entry component.

The mobile entry uses the existing bilingual `onboarding.identifier` copy and theme tokens/context. It returns the normalized `email` or `phone` value through callbacks. A future API adapter may map phone to SMS; this component does not own transport, routes, networking, tokens, or onboarding orchestration.

## Consequences

Both clients share one source of normalization without adding dependencies. Existing web imports remain compatible. Contracts tests cover the pure rules; client tests cover their respective integration. Mobile Jest evidence is limited to component/native-prop behavior, and an isolated RNweb screenshot does not imply device validation.

## Review
Independent client/platform, security and design reviews approved the actual diff and refreshed RNweb evidence. Native font registration and device validation remain parent gates.
