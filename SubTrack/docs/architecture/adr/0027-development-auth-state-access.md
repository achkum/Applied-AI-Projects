# ADR-0027: Proposed development auth-state SQL boundary
- Status: Proposed, documentation only; no SQL, grants, memberships, runtime or account-readiness approval.
- Date: 2026-10-11; ST230 original2026-10-11T00:04:11Z M120attempt1. ADR0026 is accepted planning; ST229 PR257 `2374f5561c491ca65f80d809c49ce27a81ca48a0` is an unmerged contract candidate, usable only as a planning pin.
- Class: Type2a architecture proposal plus exact independent security classification; retaining erased subject/contact digests would be a concrete proposed Type1 delta only if that optional policy is selected.
## Roles and SQL envelope
Propose isolated login `subtrack_dev_auth_login` LOGIN/NOINHERIT/NOSUPERUSER/NOCREATEDB/NOCREATEROLE/NOBYPASSRLS; PG16 memberships in `subtrack_runtime`, existing `subtrack_identity_provisioner`, new `subtrack_auth_producer` with ADMIN FALSE, INHERIT FALSE, SET TRUE only. These memberships are absent/unproved in source; no executor membership, indirect membership or SET authority is allowed.
New `subtrack_auth_owner`, `subtrack_auth_executor`, `subtrack_auth_producer` are NOLOGIN/NOINHERIT/NOSUPERUSER/NOBYPASSRLS; only migration authority can assume owner. Owner owns private schema/types/tables; executor owns functions, never tables, business objects or roles. Application has no CREATE/TEMP authority or ability to replace functions/types. Provisioner remains exactly identity SELECT(id,external_id)/INSERT; no added UPDATE/DELETE/column grant.
All functions below are static SECURITY DEFINER, VOLATILE, PARALLEL UNSAFE, `SET search_path=pg_catalog`; every reference/type/operator dependency is qualified and no dynamic SQL/user-controlled role names. Validate composite fields individually (SQL STRICT alone does not reject null fields), digest format/domain, literal web transport and configured exact HTTPS Origin. Reject invalid inputs generically with null/false/zero rows; no distinguishable private details/errors. No raw secret/code is returned by SQL.
Revoke PUBLIC schema/type/table/function rights and default PUBLIC EXECUTE for owner/executor creators. Grant schema/type USAGE to runtime/producer/executor only; grant EXECUTE only on the exact signatures in the matrix to the indicated role. Login has no direct grants; SET LOCAL ROLE selects runtime or producer as appropriate. Never grant runtime preprincipal table SELECT or executor assumption.
## Exact proposed objects (all in subtrack_auth; no legacy table reinterpretation)
Notation: `h` is domain-labelled SHA256/HMAC lowercase hex text with CHECK length64/hex; `ms` is bigint CHECK 0<=value<=9007199254740991; `b` expands to transport text CHECK='web', origin text, chain text nonempty, binding_h h, epoch text FK epoch.id, issued_ms ms, expires_ms ms. Each b has issued<expires and configured exact HTTPS Origin. Immutable fields never UPDATE; lifecycle-only column grants/triggers prevent owner/secret/binding reassignment.
`epoch(id text PK, manifest_h h NOT NULL, origin text NOT NULL, watermark_ms ms NOT NULL, state text CHECK IN('active','retired'))`; manifest fingerprints the mandatory immutable isolated key set, not key bytes. Origin is deployment-pinned; changing origin/key epoch requires separate controlled retirement review.
`reservation(key_h h PK, operation text NOT NULL, authority_kind text NOT NULL, authority_h h NOT NULL, request_h h NOT NULL, owner_h h UNIQUE NOT NULL, transport text CHECK='web', epoch text FK epoch, issued_ms ms, expires_ms ms, state text CHECK IN('pending','completed','failed'))`; no response/result column; unique key_h spans operations/authorities for this isolated key namespace.
`nonce(nonce_h h PK, b, purpose text CHECK IN('enroll_identifier','otp_step_up','session'), authority_h h NULL)`; terminal enrollment session nonce requires authority_h=verified.handle_h; nonce expires=issued+300000.
`otp(challenge_h h PK, b, identifier_h h NOT NULL, channel text CHECK IN('email','sms'), contact text NOT NULL, code_h h NULL, attempts smallint CHECK 0..5, state text CHECK IN('active','verified','exhausted'))`; code_h is keyed code digest only, erased on terminal state; contact is private normalized recovery data. Fixed enrollment purpose; expires=issued+300000.
`proof(proof_h h PK, b, purpose text CHECK IN('enrollment','login'), action text NOT NULL, challenge_h h NOT NULL, identifier_h h NULL, identity_id uuid NULL)`; CHECK enrollment/enroll-credential has identifier_h and no identity_id, login/authenticate has identity_id and no identifier_h. Enrollment references otp; login challenge is trusted producer challenge, never an OTP principal. Expires<=issued+300000 and enrollment<=otp.expires.
`pending(handle_h h PK, b, challenge_h h NOT NULL FK otp, identifier_h h NOT NULL, channel text NOT NULL, contact text NOT NULL)`; admitted immutable tuple is copied from otp, expiry<=proof/otp; source proof is deleted atomically.
`verified(handle_h h PK, b, source_pending_h h UNIQUE NOT NULL, subject_h h NOT NULL, verified_ms ms NOT NULL, given_name text NOT NULL, surname text NOT NULL, identifier_h h NOT NULL, channel text NOT NULL, contact text NOT NULL, terminal_nonce_h h UNIQUE NOT NULL FK nonce DEFERRABLE INITIALLY DEFERRED)`; source pending digest retained for audit binding, pending deleted atomically; expires<=pending and issued+300000. No client/provider assertions become these fields.
`family(family_id uuid PK, identity_id uuid NOT NULL FK public.identity, epoch text FK epoch, issued_ms ms, expires_ms ms, revoked_ms ms NULL)`; expires=issued+86400000.
`session(session_id uuid PK, family_id uuid UNIQUE NOT NULL FK family, identity_id uuid NOT NULL FK public.identity, b, generation smallint CHECK=0, device_name text CHECK IS NULL, revoked_ms ms NULL)`; session_id<>family_id; owner/epoch/expiry match family. Access credential lifetime remains900000; no persisted raw access token.
`credential(refresh_h h PK, identity_id uuid NOT NULL, session_id uuid NOT NULL FK session, family_id uuid NOT NULL FK family, b, state text CHECK IN('current','consumed'), consumed_ms ms NULL)`; partial UNIQUE(session_id) WHERE state='current'; owner/family/b immutable and match session. Consumed tombstones retain original expiry, no renewal.
`csrf(session_id uuid PK FK session, identity_id uuid NOT NULL, epoch text FK epoch, binding_h h NOT NULL, token_h h NOT NULL, expires_ms ms NOT NULL, invalidated_ms ms NULL)`; verification requires invalidated_ms IS NULL; invalidation marks it without needing DELETE grants. binding_h is the existing domain-framed identity/session CSRF binding digest, not browser cookie digest; expiry equals session. No plaintext reconstruction.
Optional `retired_subject(subject_h h PK, identity_id uuid NOT NULL, identifier_h h NULL UNIQUE, retired_ms ms NOT NULL)` is excluded from the default proposed graph: it is a retention-policy decision candidate only, not a requirement inferred from ADR0026. Exact semantics/retention/epoch compatibility must be reviewed before inclusion; no permanent ban on fresh signup is assumed.
All tables ENABLE+FORCE RLS. Runtime SELECT/INSERT/UPDATE on family/session/credential/csrf only, no DELETE; USING/WITH CHECK `public.subtrack_principal_matches(identity_id)` (existing granted wrapper checks both live-owner GUCs; no parser EXECUTE grant), with immutable-owner/tuple constraints. Updates only family.revoked_ms, session.revoked_ms, credential.state/consumed_ms, csrf.token_h/invalidated_ms; successor credentials are INSERTs. Public identity/profile writes continue existing owner repositories/policies and separately reviewed UF01 columns/defaults; no household/member/consent bootstrap.
Account persistence proposal adds public.identity `verified_at timestamptz NULL,given_name text NULL,surname text NULL` with existing runtime owner-RLS (no executor/provisioner UPDATE). `subtrack_auth.profile(identity_id uuid PK FK public.identity,display_name text NULL,avatar_colour_token text NULL,avatar_emoji text NULL,language text CHECK IN('sv','en'),theme text CHECK IN('light','dark','system'),account_mode text CHECK='just-me')` gets runtime SELECT/INSERT/UPDATE USING/WITH CHECK `public.subtrack_principal_matches(identity_id)` only, immutable identity_id, no executor access. Exact defaults/token allowlists and private verified-name projection remain separate reviewed UF01 contract prerequisites; this proposal grants no choice to client authority.
Executor SELECT/INSERT/DELETE on nonce/proof/pending/verified; SELECT/INSERT/UPDATE(attempts,state,code_h)/DELETE on otp; SELECT/INSERT/UPDATE(state)/DELETE on reservation; SELECT/UPDATE(watermark_ms) on epoch; explicit executor RLS USING/WITH CHECK true for those private operations only. It cannot update immutable authority. Producer has no table rights.
Executor SELECT on credential only for matched lookup; RLS SELECT true, no credential mutation except expired cleanup below. For family/session/csrf executor SELECT(expires_ms,epoch) only with SELECT RLS true limited by column grants. Executor DELETE on expired family/session/credential/csrf with RLS USING(expires_ms<=trusted DB clock); no live-row deletion or business-table rights. Cleanup removes FK children before parents. Only if retirement option is selected: executor SELECT(subject_h,identifier_h) with SELECT RLS true; runtime INSERT WITH CHECK `public.subtrack_principal_matches(identity_id)` after separately reviewed deletion authority; no runtime SELECT/UPDATE/DELETE of retired_subject. No such grants in default graph.
## Typed operations and compare predicates
All signatures are qualified `subtrack_auth.*`. Types: `web=(nonce_h h,binding_h h,origin text,observed_ms ms,epoch text)`; chain is derived from stored nonce. `burn=(key_h h,operation text,authority_kind text,authority_h h,request_h h,owner_h h,retention_ms ms)`; `owned=(key_h h,owner_h h,operation text,authority_h h,request_h h)`. Server generates all digests/handles; neither type contains caller owner identity.
`otp_issue=(challenge_h h,identifier_h h,channel text,contact text,code_h h)`; `simulated=(subject_h h,verified_ms ms,given_name text,surname text)`; `login_issue=(proof_h h,challenge_h h,identity_id uuid)`; all are internal trusted-producer inputs, never wire models. Reviewed producer verifies fixture subject/names outside locks; SQL cannot cryptographically establish simulator truth from an asserted composite.
`enrollment_material=(subject_h h,verified_ms ms,given_name text,surname text,channel text,contact text,identifier_h h)` is private server-only return used for provisioning/owner writes, never an HTTP projection. `refresh_match=(refresh_h h,identity_id uuid,session_id uuid,family_id uuid,transport text,origin text,chain text,binding_h h,epoch text,issued_ms ms,expires_ms ms)` contains the complete immutable stored credential tuple, no lifecycle state; private server-only snapshot, never wire input/output or mutation authority.
`refresh_burn=(matched refresh_match,authority_h h,request_h h)` is an internal trusted-adapter input constructed only from match_refresh output after selected CSRF preflight, not deserialized from HTTP. The adapter freezes that snapshot and computes authority_h=HMAC-SHA256(application authorityHmacKey, `subtrack:v2:web-refresh:authority:v1:` + frame(chain)+frame(origin)+frame(identity_id)+frame(session_id)); request_h=SHA256(`subtrack:v2:web-refresh:request:v1:` + frame(refreshV2Session)+frame(web)+frame(refresh_h)), matching pinned source; frame is UTF8 byte-length + ':' + value.
Trust boundary: application owns the mandatory isolated immutable authorityHmacKey/idempotency-core key already required by source; SQL receives no key and cannot verify the HMAC assertion. Reviewed adapter alone produces refresh_burn, global key_h=HMAC-SHA256(idempotency-core key, `subtrack:v2:idempotency:core:v1:key:` + strict Idempotency-Key), and owner_h=SHA256(`subtrack:v2:idempotency:core:v1:owner:` + fresh random owner handle); supplied digest fields never establish identity. SQL authenticates only by secret-bound stored credential rematch, not supplied identity/family/session/chain selectors.
Required additive ports: complete immutable credential snapshot (existing webContextForRefresh returns only owner/session/web context), server-only validated refresh_burn producer, async independently committed reservation/transactional settlement and pinned key-epoch configuration; none exists as this durable SQL adapter. Capture the same frozen authority/request/owner tuple for settlement; no SQL key store/helper/new dependency is proposed.
Each mutating operation locks epoch, owned reservation, involved nonce(s) in sorted digest order, otp/proof/pending/verified in graph order; terminal operations then lock subject/contact advisory digests, live identity, family/session/credential/csrf. All paths use this order; no external call or await-provider under a lock. Uniqueness is final arbiter, not SELECT-then-insert optimism.

## Account, login and refresh transactions
Enrollment: commit burn first; fence→BEGIN as runtime→terminal_material locks→SET LOCAL ROLE provisioner→SELECT(id,external_id) by stored subject/INSERT identity under existing unique key→SET LOCAL ROLE runtime→set_config('app.user_id',serverId,true) AND set_config('app.current_user_id',serverId,true)→lock active identity→write verified contact/names/profile defaults, family/session/current credential/CSRF→consume_terminal→COMMIT. Secrets generated only in memory and disclosed only after known commit.
Existing active subject is checked under ordinary derived owner before ENROLLMENT_LOGIN_REQUIRED; no enrollment session/contact/profile overwrite. Deleted/contact conflict or concurrent INSERT unique loser yields generic restart, no resurrection/autolink. Error rolls back entire transaction, then fails owned burn separately. Provisioner never commits separately; terminal_material private return is never accepted from the client.
Login: independently burn; BEGIN runtime→consume_login returns stored uuid but uncommitted consumption→set both GUCs→lock active identity→write session/family/credential/CSRF→COMMIT; failure restores proof/nonce and leaves burned request. Producer registered-subject lookup uses existing provisioner then ordinary owner liveness check; no cached active-owner set.
Refresh: complete secret-bound snapshot→selected CSRF preflight→independent reserve_refresh burn→BEGIN runtime→set both GUCs from matched stored uuid→lock live identity then family/session/credential/CSRF (after epoch/reservation locks), recompare old hash/web bindings/epoch/expiry/current-owner and CSRF→mark current credential consumed→INSERT successor same session/family/generation0 and original expiry→replace CSRF→settle completed→COMMIT. Consumed match instead revokes only matched family/session and invalidates CSRF under the same locks, subject to the explicitly chosen policy below; unrelated families survive. Owner writes supply no client principal.
Current session read is ordinary owner-RLS SELECT joined to live identity, one row; signed access-token subject/session is validated first, both settings written server-side. Unsafe profile/revoke operations lock identity/session/CSRF and recheck authority in their mutation transaction. Deletion/revocation race tests require the same identity-first order; durable deletion adaptation is a separate prerequisite, not a claim about legacy v1.
Session-CSRF owner operations are typed async repository reads/replacements/invalidation within this transaction, not new preprincipal functions. Current-session exact-Origin/cookie-bound CSRF replacement remains unavailable without a reviewed recovery contract; reload uses fresh verified login. No old plaintext/refresh credential is reconstructed.
Commit/rollback always restores role/settings by transaction scope; pool checkout/return must prove session_user login, current_user login, both GUCs empty/reset and no residual temp/search_path authority. Connection is discarded if cleanup cannot be confirmed; no global mutable transaction handle.
## Explicit unresolved contracts and security decisions
Consumed-refresh CSRF option A: require current session token; predecessor token fails generically with no revocation. Option B: accept current token OR original consumed credential's session-bound predecessor token for reuse-only revocation; add nullable `credential.predecessor_csrf_h h`, written at rotation, immutable and expired with tombstone. It never authorizes refresh success, successor disclosure or another family. Both require exact Origin/cookie and live owner. Neither option is selected/activated; B is a concrete proposed Type1 historical-CSRF acceptance/retention delta only if selected; contract/security classify A's missed old-pair reuse detection versus B's added historical-CSRF acceptance/retention before storage.
Exact access classification question: before, runtime owner-scoped business data and process-local trusted proof/refresh lookup; proposed after, executor may privately read bounded preprincipal records and credential index, and return only completely secret-bound stored owner/material. Review each grant/predicate/producer membership, including trust that app-owned producer inputs are verified; decide whether this preserves accepted authentication authority (Type2a storage) or adds a concrete security-model change (Type1). No blanket founder gate inferred for already adopted BankID/D12 A.
Precise semantic question: accepted ADR0026:18 says “A deleted subject/contact conflict fails generically, never resurrects or relinks an account”; data-rights.service.ts:223-233 (blob328e34484496529332648c7593a7cbec0374730a) clears externalId/email/phone. Existing erased rows cannot be found by those old values; this does not prove ADR requires permanent re-registration prohibition. Options for independent platform/security/privacy classification: A reject detectable deleted-row/contact conflicts, never revive/relink/overwrite old rows; B explicitly permit a fresh new identity after complete erasure with no link to old owner; C add optional retired-subject/contact guard. A/B require exact semantic/deletion-race contract, C concretely adds digest retention and deletion-time authority beyond existing erasure (proposed Type1 if selected). No option or founder blocker is silently inferred; unresolved semantics must be recorded before implementing their affected deletion/enrollment predicates.
## Bounds, evidence and slices
Every function prunes only expired eligible rows and enforces<=10000 retained nonce/otp/proof/pending/verified/reservation/session/family/credential/CSRF rows per object under epoch lock; capacity exhaustion fails closed (including tombstones, never evict live burns/reuse evidence). Enrollment expires<=300000 and source lifetime; reservation<=86400000; credential tombstones through family expiry. Fixed trusted DB time/checked observed time, post-await fences and startup watermark prevent regression/renewal. Optional retirement retention capacity is part of its undecided policy, never silent eviction.
Same pinned manifest/epoch restart retains DB burns/one-use/session/CSRF authority; missing/mismatched keys, retired epoch, clock regression or capacity refuse dispatch/startup. No random fallback/live rotation. Controlled epoch retirement invalidates affected auth state transactionally under separately approved maintenance authority, never deletes identities; no retirement grant here. Lost/uncertain response never replays credentials, retries refresh or destructively compensates; fresh challenge/nonce/verified login, bounded unknown orphans, owner-manage known sessions.
Later disposable PG16 proof uses real qualified login/runtime/producer/executor/owner/provisioner roles: direct tables/PUBLIC/default EXECUTE/SET executor/indirect-membership denial; no cross-owner business SELECT; null/composite/type/search_path injection, wrong secret/purpose/Origin/cookie/chain/epoch and expired/deleted-owner denial. Prove every altered refresh_match field rejects, adapter rejects wire-supplied refresh_burn/digests, pinned source digest bytes match, and cross-operation/global duplicate burns fail. Verify both GUCs and pool reset after commit/rollback/cancel; preserve existing provisioner grants exactly.
Race/fault proof: every graph transition at-most-one, OTP attempts/metadata coherence, simultaneous global key burns, capacity under concurrency, simulator expiry across await, duplicate subject/contact and deletion races, nonce cross-purpose binding, rollback before/after every role/write/consume/settle boundary, uncertain commit/lost response without credential replay/compensation; same-epoch process restart and durable clock/key failure. Refresh predecessor/current CSRF cases for chosen contract, current/consumed secret races, reuse family-only revocation, unrelated-family survival and CSRF revocation races are required actual-PG evidence, not mock acceptance.
Slices: (1) finalize ST229 merge+CSRF policy+retirement/privacy decision and producer names contract; (2) narrow schema/access migration and qualified-role PG denial tests; (3) transaction-bound async OTP/proof/metadata/nonce/reservation/producer ports; (4) atomic enrollment/login/refresh and deletion retirement adaptation; (5) isolated HTTPS composition/natural-browser cookie+Origin/restart proof; (6) reviewed web profile/Just me UI. Each gets exact owned paths, independent platform/security review and fresh QA/applicable exact-head CI; no bulk implementation authorization or usable-account claim.
