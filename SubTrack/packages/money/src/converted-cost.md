# Converted charge cost swing

`ConvertedChargeCost` pairs caller-supplied billed and settled `Money` values. `isConvertedCostOutsideMedianBand(candidate, history)` returns `true` only when the candidate's effective booked conversion-cost ratio differs strictly by more than 5% from the ordinary median ratio in 4–50 prior pairs. The median for even histories is the exact arithmetic mean of its middle ratios. A difference exactly at 5% is inside. Valid histories of 0–3 pairs return `false` because the reference set is insufficient; this does not express statistical confidence.

Each pair must have nonzero bigint amounts, a canonical three-letter currency code, USD or EUR billed currency, and a distinct settled currency. Every history pair is validated before the insufficient-history result, and both currencies must match the candidate pair. Signed nonzero values are compared by magnitude; the caller owns refund and direction eligibility. Invalid inputs and unexpected property access failures throw the fixed `MoneyError` message `Converted cost detection unavailable`.

The rule measures effective booked conversion cost, including fees, bank markup, and rounding reflected in the settled amount. It cannot isolate market FX movement. Ratios use absolute settled/billed minor units and exact reduced bigint fractions. Since every pair shares the same billed and settled currencies, exponent factors are common and cancel from relative drift. The API returns no absolute exchange rate. The caller is responsible for supplying authoritative values and selecting same-owner, same-service, chronological prior references that exclude the candidate; the primitive does not establish provenance, authorization, posting status, or grouping. This standalone advisory helper has no source integration, default wiring, or automatic financial action.
